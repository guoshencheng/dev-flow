# 仓库文档归类与维护

按文档用途归类，日期只表示来源时间，不单独决定位置。

| 位置 | 内容与读取场景 |
| --- | --- |
| `skills/*/SKILL.md` | 专业能力入口、关键约束与按需路由 |
| `skills/*/references/` | 执行当前任务所需的方法、协议、契约、格式与工具操作指南 |
| `skills/*/assets/` | 复制或参考到项目的模板、示例、组件源码及其用途/许可/运行说明 |
| `docs/` | 插件维护说明、职责建设方法和当前能力现状 |
| `docs/plans/` | 本仓库的建设计划、阶段优先级和待实现方案 |
| `docs/history/`、`docs/integrations/` | 本机配置历史、特定工具版本观察和接入验证快照 |
| `reviews/`、`evals/` | 独立审阅、工具/行为评测、原始任务与证据 |

业务任务读取现行总纲与相关专业指南，不自动读取建设计划。插件接入任务可以读取安装说明；仓库维护任务按需读取建设资料及历史证据。

混合文档先提取可复用执行内容，再将原规划或历史记录归档。现行指南不继承未实现的工具、账本或未来阶段作为必需前置。移动后修正入站与相对引用、README 和 Skill 路由；不在 references 中留下重复规划副本。

组件目录可以记录用途、边界、来源和实际采用状态；详细的建设验证过程保存在评测记录。原型讨论记录模板保留在 assets，因为它会被复制到项目；空白模板不作为已发生的评审证据。

当前业务项目的产品、UI、技术、验收和运行资料保存在该项目，遵守[项目文档协议](../skills/dev-flow/references/design-document-contract.md)。此处是插件仓库的文档组织约定。
