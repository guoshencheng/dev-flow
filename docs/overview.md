# dev-flow 总纲概述

更新日期：2026-10-10。对应[总纲 v0.22](../skills/dev-flow/references/constitution.md)。

dev-flow 是以 Codex 为主的多角色研发协作体系，目标是逐步替代 superpowers，形成稳定、高效的研发 harness，交付符合用户要求的成果。协议覆盖需求、设计、实现、测试、交付、运行、维护与退役；不同研发对象和任务种类通过可扩展路径逐步支持，并分别记录已定义和实际验证的能力。

## 协作结构

主 Agent 维护目标与范围、选择工作路径、协调依赖和冲突、综合证据并推进交付。六类专业职责按当前任务需要参与：

| 职责 | 核心责任 |
| --- | --- |
| 产品与交互 | 用户任务、信息架构、流程与交互状态、业务规则和验收目标 |
| 视觉设计 | 布局、Tokens、组件及其状态、设计系统与实际渲染检查 |
| 架构 | 整洁架构、技术与代码规范基线、业务域和模块契约、代码业务复核、研发复盘与现状维护 |
| 研发 | 架构后页面/功能/链路的技术实现方案与符合性 Review、实施计划/AI 复核、切片实现及修复 |
| 测试验收 | 早期反馈可测性，综合产品/技术方案设计端到端用例并 AI Review 后交人工确认，实际检查/反馈/复验 |
| 运维与交付 | 启动、安装、发布、运行观察、恢复与退役 |

总纲提供共同协议；专业 Skills 承载职责方法；主 Agent 或获准委派的可用子 Agent 承担工作；项目保存自己的有效知识与长期资产。核心协议保持工具无关，Codex 的会话设置、委派能力和工具接入由宿主适配，流程不要求原生角色注册。

## 三个首要交付目标

1. **严肃的 UI 与交互设计。** 明确真实用户任务、相关界面状态与异常恢复，设计与实现相互关联，分别用实际操作和实际渲染验证。
2. **连续实现与整体验收。** 研发持续集成和自测，完整候选再集中实现 Review 与正式验收；具体问题即时反馈，按关联范围批量修复并定向复评、复验，最后核验整体交付。
3. **准确的端到端交付。** 按本次范围交付可启动源码、可安装产物或实际部署，在干净工作副本或目标环境完成核心用户任务。规划或评审任务以对应成果验收结束。

路径按任务种类、风险和阶段裁剪。实施中发现需求变化时，先进入受影响部分的需求变更闸门，更新规则、方案、用例和计划，再恢复受影响实现；共享文件或接口有明确写入责任，独立任务在可控范围内并行，集成成果重新验收。证据对应当前候选版本，未执行、失效与未知结果明确记录。用户需要作出关键决定时提出具体问题，已有授权范围内持续推进。

完整功能依次为：产品/交互/UI 与人工确认 → 架构设计与重要取舍确认 → 研发端到端技术实现方案 → 产品符合性及相关 UI/架构 AI Review → 测试综合原产品与方案设计端到端用例 → 用例 AI Review → 人工确认验收预期与覆盖 → 研发实施计划/AI 复核 → 连续实现、集成与研发自测 → 完整候选集中 Review/正式验收 → 关联问题批量修复与定向复评/复验 → 整体交付核验及架构复盘。技术方案明确页面/入口、功能、完整链路与 OUT，原产品要求持续作权威依据；技术方案与实施计划默认没有额外人工审批。最终通过实际端到端结果及架构约束检查验收，发现需要改变确认基线时只请求受影响部分的决定。已有有效确认直接复用，局部修复和其他工程类型按任务裁剪。具体规则见[执行协议](../skills/dev-flow/references/execution-contract.md)。

内部切片不作为独立交付验收门槛。主会话派发后继续执行、集成或实际等待，不能因阶段结果或等待超时提前结束。验证采用必要记录和已有工具，历史整理与无关工具维护默认后置。本次规则已定义，完整真实任务的执行效果仍待验证。

## 持续建设与项目沉淀

每个职责和体系部分持续维护专业方法、能力现状、验证案例与改进待办。每个项目持续保存产品规则、交互与设计系统、架构契约、工程与回归资产、启动与运行方式：任务开始读取并核验，过程中更新；用户可以手动触发架构与测试联合维护检查，也可以授权定期检查；检查后把最新有效架构和稳定回归用例同步到项目级当前基线，再对迭代和被替代候选做逻辑归档，下一任务实际复用。通用经验经过适用范围和行为验证后再进入 Skills 或工具。

主 Agent 先明确当前业务项目，在[项目文档索引](../skills/dev-flow/references/design-document-contract.md)定位产品、交互原型、设计/UI、技术及相关验收/交付资料的实际位置、状态与版本。设计讨论和确认通过该项目的文档与原型入口提供预览，Skill 保留通用方法和工具，项目成果保存在所属项目；维护 Skill 默认不逐篇预览其参考文件。

架构在相关实施变化和交付后参与，依据实际源码核对业务规则、依赖与数据所有权，更新目录模块地图、职责及业务域/层次，给出有证据的合理性评价与改动建议。局部修复按影响裁剪，必需偏差继续修复，可选演进入待办；现状、目标和未知分别维护。

## 当前阶段与下一步

目前已建立独立仓库、总纲 v0.22 和六职责专业指导，本地 Plugin 0.1.0 当前提供七个 Skills，不再初始化原生职责 Agent，接入与新上下文 Skill 发现见[验证记录](../reviews/2026-10-09-setup-removal-and-task-routing.md)。产品已有历史隔离行为与连续资产复用证据，视觉阶段增加共同文档/归档协议和 Vite 预览检查，见[视觉职责](visual-agent.md)。架构提供整洁架构、技术与代码规范、细化分工、研发复盘及架构/测试联合维护检查，状态见[架构职责](architecture-agent.md)。测试提供前端/真实 API/前后端 E2E 与交付方案、持续反馈复验、需求变更闸门及跨迭代回归资产维护，状态见[测试职责](acceptance-agent.md)。研发提供基线/计划 AI 复核、自主切片实施、前后端实现、诊断修复和集成交付，状态见[研发职责](engineering-agent.md)。运维提供环境/启动、产物/发布、运行故障与恢复、依赖演进/退役及项目运行资产方法，状态见[运维职责](operations-agent.md)。架构后技术方案、符合性/用例 Review 与整体确认/自主实施的本次调整见[检查记录](../reviews/2026-10-08-technical-delivery-stage.md)，整套流程仍需真实任务验证。插件发现、工具、实际委派、专业行为与真实项目复用分别验收。六类职责的四十八项能力继续按实际证据推进，本地 Plugin 分发已接入，运行内核继续按实测建设。

六职责已有专业指导、项目资产协议与各自范围的验证记录。下一步用真实 UI 任务检验完整交付、持续交接和下一任务复用，在支持且获准委派的宿主核验实际派发；维护已接入的 Plugin 分发，再建设实测必要的运行内核。重要架构与运行问题发现时即处理。

各阶段产物按功能迭代集中在 `docs/dev-flow/iterations/<迭代ID>/`，迭代索引关联规格、原型、架构、技术方案、用例、计划、执行报告与交付；项目级目录维护跨迭代有效基线。目录细节见[项目文档协议](../skills/dev-flow/references/design-document-contract.md)。
