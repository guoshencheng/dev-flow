# dev-flow 总纲概述

更新日期：2026-10-08。对应[总纲 v0.11](../skills/dev-flow/references/constitution.md)。

dev-flow 是以 Codex 为主的多角色研发协作体系，目标是逐步替代 superpowers，形成稳定、高效的研发 harness，交付符合用户要求的成果。协议覆盖需求、设计、实现、测试、交付、运行、维护与退役；不同研发对象和任务种类通过可扩展路径逐步支持，并分别记录已定义和实际验证的能力。

## 协作结构

主 Agent 维护目标与范围、选择工作路径、协调依赖和冲突、综合证据并推进交付。六类专业职责按当前任务需要参与：

| 职责 | 核心责任 |
| --- | --- |
| 产品与交互 | 用户任务、信息架构、流程与交互状态、业务规则和验收目标 |
| 视觉设计 | 布局、Tokens、组件及其状态、设计系统与实际渲染检查 |
| 架构 | 整洁架构、技术与代码规范基线、业务域和模块契约、代码业务复核、研发复盘与现状维护 |
| 研发 | 可运行功能切片、工程集成、依据证据定位并修复问题 |
| 测试验收 | 从需求阶段定义场景，实际检查、反馈、复验与最终验收 |
| 运维与交付 | 启动、安装、发布、运行观察、恢复与退役 |

总纲提供共同协议；原生 Agent 配置确定职责与会话设置；Skills 承载按需读取的专业方法；项目保存自己的有效知识与长期资产。核心协议保持工具无关，Codex 的原生配置、会话设置和工具接入作为适配层，优先在 Codex 上验证。角色尚未建成时，由主 Agent 明确承担对应工作。

## 三个首要交付目标

1. **严肃的 UI 与交互设计。** 明确真实用户任务、相关界面状态与异常恢复，设计与实现相互关联，分别用实际操作和实际渲染验证。
2. **研发测试持续对焦。** 尽早形成可运行切片，持续执行“验证 → 带版本和复现证据的反馈 → 定位修复 → 原问题复验与相关回归”，使问题由实际复验关闭。
3. **准确的端到端交付。** 按本次范围交付可启动源码、可安装产物或实际部署，在干净工作副本或目标环境完成核心用户任务。规划或评审任务以对应成果验收结束。

路径按任务种类、风险和阶段裁剪。共享文件或接口有明确写入责任，独立任务在可控范围内并行，集成成果重新验收。证据对应当前候选版本，未执行、失效与未知结果明确记录。用户需要作出关键决定时提出具体问题，已有授权范围内持续推进。

完整功能由用户确认产品/交互/UI、重要架构设计和测试用例；研发仍产出实现计划，AI 复核通过后自主实施与修复，不增加人工计划审批。最终通过实际端到端结果及架构约束检查验收，发现需要改变确认基线时只请求受影响部分的决定。已有有效确认直接复用，局部修复和其他工程类型按任务裁剪。具体规则见[执行协议](../skills/dev-flow/references/execution-contract.md)。

## 持续建设与项目沉淀

每个职责和体系部分持续维护专业方法、能力现状、验证案例与改进待办。每个项目持续保存产品规则、交互与设计系统、架构契约、工程与回归资产、启动与运行方式：任务开始读取并核验，过程中更新，交付时记录变化，下一任务实际复用。通用经验经过适用范围和行为验证后再进入 Skills 或工具。

主 Agent 先明确当前业务项目，在[项目文档索引](../skills/dev-flow/references/design-document-contract.md)定位产品、交互原型、设计/UI、技术及相关验收/交付资料的实际位置、状态与版本。设计讨论和确认通过该项目的文档与原型入口提供预览，Skill 保留通用方法和工具，项目成果保存在所属项目；维护 Skill 默认不逐篇预览其参考文件。

架构在相关实施变化和交付后参与，依据实际源码核对业务规则、依赖与数据所有权，更新目录模块地图、职责及业务域/层次，给出有证据的合理性评价与改动建议。局部修复按影响裁剪，必需偏差继续修复，可选演进入待办；现状、目标和未知分别维护。

## 当前阶段与下一步

目前已建立独立仓库、总纲 v0.11、产品/视觉/架构/测试验收/研发专业指导，六个 Skills 与五个职责 TOML 由安装检查逐个核验。产品已有历史隔离行为与连续资产复用证据，视觉阶段增加共同文档/归档协议和 Vite 预览检查，见[视觉职责](visual-agent.md)。架构提供整洁架构、技术与代码规范、细化分工和研发复盘，状态见[架构职责](architecture-agent.md)。测试提供前端/真实 API/前后端 E2E 与交付方案、持续反馈复验和项目回归资产，状态见[测试职责](acceptance-agent.md)。研发提供基线/计划 AI 复核、自主切片实施、前后端实现、诊断修复和集成交付，状态见[研发职责](engineering-agent.md)。完整确认、AI 计划复核和自主实施仍需真实任务验证。全局链接、工具、原生发现/派发、专业行为与真实项目复用分别验收。六类职责的四十八项能力继续按实际证据推进，运行内核与 Plugin 分发仍待建设。

下一步建设运维交付 Agent，每个职责配套配置、能力指导、项目资产协议和实际案例；补齐已有职责在真实任务中的持续交接和宿主派发验证。重要架构与运行问题发现时即处理。各职责具备基础能力后用真实 UI 任务检验完整交付，再建设实测必要的运行内核并打包 Plugin。
