# dev-flow 总纲概述

更新日期：2026-10-08。对应[总纲 v0.5](../skills/dev-flow/references/constitution.md)。

dev-flow 是以 Codex 为主的多角色研发协作体系，目标是逐步替代 superpowers，形成稳定、高效的研发 harness，交付符合用户要求的成果。协议覆盖需求、设计、实现、测试、交付、运行、维护与退役；不同研发对象和任务种类通过可扩展路径逐步支持，并分别记录已定义和实际验证的能力。

## 协作结构

主 Agent 维护目标与范围、选择工作路径、协调依赖和冲突、综合证据并推进交付。六类专业职责按当前任务需要参与：

| 职责 | 核心责任 |
| --- | --- |
| 产品与交互 | 用户任务、信息架构、流程与交互状态、业务规则和验收目标 |
| 视觉设计 | 布局、Tokens、组件及其状态、设计系统与实际渲染检查 |
| 架构 | 系统边界、接口、数据、兼容契约与重要技术取舍 |
| 研发 | 可运行功能切片、工程集成、依据证据定位并修复问题 |
| 测试验收 | 从需求阶段定义场景，实际检查、反馈、复验与最终验收 |
| 运维与交付 | 启动、安装、发布、运行观察、恢复与退役 |

总纲提供共同协议；原生 Agent 配置确定职责与会话设置；Skills 承载按需读取的专业方法；项目保存自己的有效知识与长期资产。核心协议保持工具无关，Codex 的原生配置、会话设置和工具接入作为适配层，优先在 Codex 上验证。角色尚未建成时，由主 Agent 明确承担对应工作。

## 三个首要交付目标

1. **严肃的 UI 与交互设计。** 明确真实用户任务、相关界面状态与异常恢复，设计与实现相互关联，分别用实际操作和实际渲染验证。
2. **研发测试持续对焦。** 尽早形成可运行切片，持续执行“验证 → 带版本和复现证据的反馈 → 定位修复 → 原问题复验与相关回归”，使问题由实际复验关闭。
3. **准确的端到端交付。** 按本次范围交付可启动源码、可安装产物或实际部署，在干净工作副本或目标环境完成核心用户任务。规划或评审任务以对应成果验收结束。

路径按任务种类、风险和阶段裁剪。共享文件或接口有明确写入责任，独立任务在可控范围内并行，集成成果重新验收。证据对应当前候选版本，未执行、失效与未知结果明确记录。用户需要作出关键决定时提出具体问题，已有授权范围内持续推进。

## 持续建设与项目沉淀

每个职责和体系部分持续维护专业方法、能力现状、验证案例与改进待办。每个项目持续保存产品规则、交互与设计系统、架构契约、工程与回归资产、启动与运行方式：任务开始读取并核验，过程中更新，交付时记录变化，下一任务实际复用。通用经验经过适用范围和行为验证后再进入 Skills 或工具。

## 当前阶段与下一步

目前已建立独立仓库、总纲 v0.5、产品与视觉专业指导及三个全局 Skill 链接；产品与视觉职责 TOML 已接入。产品已有历史隔离行为与连续资产复用证据，本轮增加共同文档/归档协议和实际 Vite 预览检查，见[视觉职责](visual-agent.md)。全局链接、工具、原生发现/派发、专业行为与真实项目复用分别验收。六类职责的四十八项能力清单继续按实际证据推进，运行内核与 Plugin 分发仍待建设。

下一步补齐产品/视觉在真实 UI 任务中的持续交接和宿主派发验证，继续建设测试验收、研发、运维交付、架构 Agent，每个职责配套配置、能力指导、项目资产协议和实际案例。重要架构与运行问题发现时即处理。各职责具备基础能力后用真实 UI 任务检验完整交付，再建设实测必要的运行内核并打包 Plugin。
