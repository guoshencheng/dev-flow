# 通用需求按功能展开 Progress

## 流程方案与用户确认

- 目标：让所有采用 Dev Flow 的项目默认按用户功能与操作过程理解需求；字段、权限、计算、边界和恢复写在对应功能附近，保留必要追溯与可验证性。
- 范围：通用产品规格模板、产品 Skill 与规格协议、受影响职责提示词、示例及必要校验。只读参考 insight-mashroom 的表达，不改写该项目，不带入业务专属规则。
- 路径：文档与方法维护路径；裁剪运行部署、界面原型及业务 E2E。以源码候选、内容审查和仓库相关检查作为本次交付；提交、版本发布、安装及分发不在本次授权内。
- 流程确认：已确认。展示流程 v1 后用户答复“好的，继续吧”，覆盖本次流程及已明确的源码调整范围。
- 业务依据：本会话交接原文；明确要求正文回答功能、使用者、入口、操作与结果，不强制统一小标题或全局 RULE/AC 表。
- 实施授权：用户已要求完成通用调整；流程确认后按上述明确范围推进，不重复请求同范围实施许可。

## 当前状态

- 当前阶段：已完成本次源码候选交付；独立初审与定向复核通过，检查通过。
- 下一步：如需安装或分发，另按仓库版本升级与安装验证规则处理。方案及验证见 [调整与验证](design-and-validation.md)。

## 验证与结束条件

检查模板并非仅改标题、正文无需查编号即可理解、小功能与大功能均可自然表达、正常/边界/拒绝/恢复仍可验证、通用内容不混入参考项目业务规则。检索现行约束与生成入口，执行相关仓库校验；历史材料不机械改写。若修改受管角色维护源，按仓库要求同步生成与检查入口，记录实际结果。

仅当本次范围内修改、审查、检查及遗留说明齐全，才登记整体完成。后续安装或分发另按仓库版本升级规则处理。

## 实际派发

独立产品 Agent `/root/review` 只读复核完整候选；主 Agent 独占源码写入。初审无阻断，示例重复提交歧义及技术检查引用遗漏已修订，独立定向复核通过；不含宿主安装/发布。
