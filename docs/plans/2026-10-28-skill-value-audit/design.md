# 清理候选与实施顺序

## 目标与依据

按[18 项盘点](audit.md)及三组隔离对照，本轮只取消 `defect-diagnosis`、`regression-verification` 两个独立 Skill 入口。两者主任务是研发日常诊断和回归验证，当前方法大部分与职责专业工作及通用实践重叠；在指定样例里不加载 Skill 也能完成目标。单次结果不足以证明所有任务等价，因此保留高价值方法并维持明确的研发职责引用，不删除诊断或回归能力。

## 变化与兼容

- 两份详细方法的唯一正文迁至 `agents/references/engineering/`。保留同一缺陷假设—实验—结果、目标失败与环境错误区分、同一测试旧新候选比较、权限拒绝及无写入、证据范围和修复交接；分别保留原文中相互引用、验收执行关联及必要的标题锚点。
- 原参考路径保留短迁移入口，避免历史文件的参考链接失效；原 `SKILL.md` 入口退出发现。现行研发职责直接链接两个研发参考；其他现行引用及角色路由、全局 Skill 清单、文档入口和宿主生成同步。
- 独立调用 `$defect-diagnosis` 与 `$regression-verification` 将不再发现，其旧 `SKILL.md` 文件路径不再可访问（保留该文件会使宿主生成器将其识别为 Skill）。当研发职责被明确调用且当前源码版职责提示词实际加载时，提示词指向两个研发参考；验收侧直接从验收执行参考访问回归方法。普通自然语言请求不一定触发该职责或读取参考，未加载职责时不保证自动承接；可显式指定研发职责或要求读取两份参考。宿主新会话自动发现、旧名称调用与真实项目迁移尚需验证，不能声称等价。
- 18 项中的其他候选暂不删除；`technical-diagrams` 保留此前用户明确的独立 Skill 决定。其他工作区未提交改动与尚未安装的技术图示候选保留。

## 验证与交付

独立架构职责审阅本方案及迁移风险；实施后核验迁出/迁入语义、Git 差异、必要相对链接与历史引用、能力清单/宿主生成、两种代表性诊断和回归情境，以及隔离打包。记录语法/工具与真实行为的差别；新会话发现、其他复杂任务与实际宿主安装未验证。交付工作区源码候选，安装/分发之前另按仓库规定升级版本和完成交付核验。
