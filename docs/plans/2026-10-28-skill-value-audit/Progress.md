# 操作 Skill 业务价值盘点与清理：Progress

## 流程方案与确认

- 最终目标：盘点插件现有 Skills，区分有实际任务场景和可复用操作价值的能力与仅重复职责常规描述或 LLM 通用能力的内容，清理经核实不需要独立存在的 Skill 或内容，并保持职责、流程和实际工具能力完整。
- 基线：工作区能力清单声明 18 个 Skill，包括尚未安装的 `technical-diagrams`；有图示指导、新 Skill 和插件完整性迭代的未提交改动。以当前工作区为盘点对象，明确区分源码候选与实际已安装版本，不覆盖其他改动。
- 路径：跨技能的能力与文档清理；不涉及产品 UI，裁剪原型及产品功能验收。职责专业判断归职责，Skill 负责有触发、输入输出及复用价值的操作；流程协议独立评估，不因内容像规则就直接删除。
- 决策依据：每项核对真实使用场景、触发对象、输入输出、项目特有约束、脚本/资源与依赖、代表性行为证据以及未使用 Skill 时的能力；区分“没有证据”和“证明无价值”。逐项给出保留、精简、合并/迁移或移除建议与理由，不仅凭文本长短或 LLM 可能知道就裁定。
- 影响与保护：梳理角色路由、跨 Skill 引用、提示词、模板、资源、工具、宿主生成和打包；删除入口前先承接仍有效的规则、工具和用户工作流，历史记录保留历史事实。涉及重大行为、流程授权或兼容改变时先明确方案及迁移影响。
- 流程确认：用户于本对话回复“确认”，确认版本 1；本轮用户已授权盘点并清理常规描述的技能。
- 验证与交付：采用实际可用的职责执行者进行盘点及独立复核，按用户设定选择模型强度；以代表场景、引用/锚点、能力清单、宿主生成及隔离打包等适用检查核对。工作区交付具体清理与证据；安装/分发前另按仓库版本和安装约定处理，不把其他未提交迭代无意打包发布。
