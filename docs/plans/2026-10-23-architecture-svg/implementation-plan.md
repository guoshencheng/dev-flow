# 架构结构图 SVG 修正实施计划

依据用户参考图与明确修正、发送授权，沿用已确认的文档修改/独立复核/渲染路径。总体状态与来源见 [Progress](Progress.md)。本轮是图示方法维护，以本篇的设计摘要承接，无业务实现方案或发布安装。

## 一、设计摘要与完成标准

- **分层结构**：采用可编辑SVG，用有标题的容器和水平层带/嵌套模块呈现整体 → 分区/运行单元 → 逻辑层/模块，保持对齐、留白、有限强调色，参考用户的深色卡片风格。位置/包含不自动表示调用或源码依赖；分层图可少画或不画关系边，图注明其视角。
- **模块依赖**：单独用SVG表达源码依赖，明确内层端口、外层实现、允许依赖和装配根。实线箭头是源码依赖，接口实现/注入用不同线型并写图例。不会把所有边叠到分层总览，不能把逐步流程图当分层图。
- **具体样例**：复用既有虚构OrderService/OrderRepository/Order模型，新增分层与源码依赖两张SVG，名称与已有业务时序/ER保持一致。控制面/公网/内网参考只迁移构图，不宣称同一业务事实；原控制面样例按需要改为SVG结构总览，运行通信另明示方向。
- **文件与引用**：SVG源放 `agents/assets/architecture/examples/diagrams/`，Markdown用相对图片引用，提供文本职责表及箭头说明。共享规范按图型选择表示方式：结构/部署/模块依赖优先SVG，时序/流程/状态/ER可用Mermaid；结构清晰的已有项目资产可复用，但不能用“Mermaid优先”压过本轮用户格式要求。
- **技术与可用性**：viewBox、稳定元素ID、title/desc、显式文本换行、系统字体、背景/边框/箭头可读；不依赖foreignObject/脚本/外部字体/远程资源，不将文本转路径或只交截图。图中指明虚构目标、逻辑层与部署边界、省略项，确保含义与正文/Service契约对应。
- **覆盖入口**：更新总架构、迭代研发设计、现状地图和Review中结构图说明及规范链接，保留总架构与迭代增量分工、具体业务时序和数据关系要求。

## 三、验证、交付与限制

SVG解析/本地资源和文档链接检查、`sync_host_agents.py --check`、`git diff --check`；实际浏览器打开 SVG 图片嵌入并核对源文件直接打开，Markdown 相对引用另做静态核验，保存本机截图并核对中文、边界、标签及阅读宽度；独立评审者检查技术语义及可读性。新增源文件先纳入Git以便资源校验，不创建无关业务测试。

本轮不改安装脚本，不覆盖0.6.1缓存，不自动发行版本；通知目标聊天读取仓库修正版和SVG源，而不是旧插件缓存。目标聊天执行其项目的文档调整，不由本轮直接改money-bird文件。

## 四、独立复核及进展引用

计划与最终候选的实际结论由 [Progress](Progress.md)关联记录；不能把本篇作者自查登记独立通过。发送只限用户指定聊天，不扩大为其他收件人或后台监控。

## 五、0.6.2 发布与收尾追加计划

依据用户后续明确授权，扩大交付至本地Codex宿主及远程main。升级插件patch版本0.6.2，同步manifest、README和安装说明，运行宿主入口生成write/check；维护源与SVG不另改动。静态验证后运行适用安装/原生角色回归，独立复核版本增量及已有SVG证据有效性。执行manage_plugin install/check，逐文件核对源码、构建和实际缓存，检查SVG与模板关键内容、Skills/角色资源引用、启用状态和用户配置前后保留。记录结果后提交完整成果，最终HEAD再次重建安装/检查；fetch并核对远端祖先关系，仅普通快进推送主干。最后核对远端SHA、本地干净状态和安装候选一致，完成状态回到Progress；不把旧会话的能力快照写成已经刷新。
