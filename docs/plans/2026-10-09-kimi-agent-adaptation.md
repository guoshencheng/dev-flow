# Kimi 职责 Agent 适配设计与实施计划

## 基线和范围

用户确认 Kimi 单独维护 Agent 文档，并要求后续双端同步。基线为 `7c5926d` 及开始时工作区已有流程方法修改；在隔离 worktree 复制当前相关源码作为兼容输入，原 checkout 修改保留。交付为六份 Kimi 原生 Agent、Kimi 清单、同步检查与接入说明，不新增原生 Codex 注册流程、不复制专业方法。

## 设计与验收

- 共用 `skills/` 是专业规则权威；从 Skill name/description 和插件身份生成 Kimi Markdown 与历史 Codex TOML 入口。只在宿主边界声明格式、上下文与交接。
- Kimi 清单扫描独立 Agent 目录，按需加载流程，不自动每个会话加载全套方法。
- Kimi Agent 保留基础提示；禁止二次委派，接收自包含任务和实际 Skill 绝对路径，不猜测用户目录或缓存路径。
- 同步检查阻断过期元信息、双端入口或插件版本；构建调用同步检查。构建和宿主安装独立，现有 Codex install/check/remove 语义保留。
- 验收核对七 Skills/六 Agent、包内引用、隔离构建、漂移拒绝、修改内容完整性和已有用户配置保留；宿主原生发现、实际派发与真实业务任务分别取证，未执行不登记通过。

## 实施顺序与复核

1. 生成两端职责入口和 Kimi 清单，增加自包含派发协议。
2. 在构建验证加入同步检查，更新安装说明和仓库入口。
3. 在隔离目录验证同步/漂移拒绝/打包/原安装语义，尝试本机 Kimi 原生发现与派发。
4. 定向复核当前适配差异、记录证据和能力缺口，回传本次文件到原 checkout，保留原修改。

实施前主 Agent AI 自查：用户已确定独立 Kimi 文档与双端同步方案；生成轻量入口避免专业规则重复。绝对路径由运行时派发提供，工具权限和方法约束分别表达；已有流程修改保留。结论：按上述范围实施，不新增人工计划审批。本次未启用独立 Codex subagent，不登记独立复核。
