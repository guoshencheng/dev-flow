# 文档预览直启与共享依赖缓存计划

日期：2026-10-11。基线：`4952f6a`（预览文档导航已改为树形目录）。

## 目标与范围

将项目文档预览从“复制阅读器到项目后启动”调整为“使用已安装 Dev Flow 模板，显式传入项目目录和文档根目录直接启动”。项目不再需要维护 `tools/design-docs` 才能阅读文档；已有复制工程继续保留兼容能力，避免破坏现有项目。

本轮范围包括：

- 预览脚本从插件模板目录直接启动 Vite，并自动在该模板目录准备锁定依赖。
- 运行记录增加预览模板版本与指纹，便于识别实际运行的阅读器来源。
- 更新预览协议、阅读器 README 和插件说明，明确直启命令为默认入口，`init` 为兼容/定制入口。
- 用隔离项目验证不创建项目内阅读器副本、目录读取、URL、健康检查、停止与重启。

不在本轮范围内：发布独立 npm 包、注册全局 Agent、修改业务项目文档内容、删除已有项目的 `tools/design-docs` 或自动覆盖项目定制。

## 技术方案

### 入口与完整链路

调用者从已安装插件中的 `skills/dev-flow/assets/document-workspace/scripts/preview.mjs` 执行：

```sh
node "$DEV_FLOW_SKILL_DIR/assets/document-workspace/scripts/preview.mjs" \
  serve --project /项目绝对路径 --roots docs/dev-flow,design --port 0
```

脚本显式校验项目和根目录，读取项目文档并在本机 `127.0.0.1` 启动 Vite；运行状态仍写入项目 `.dev/previews/documents.json`。`url` 命令继续校验服务身份、项目和文件范围后返回实际地址。

### 模块与依赖边界

- `preview.mjs`：负责参数、运行记录、模板依赖检查、启动/停止和 URL 查询。
- `vite.config.mjs`、`scripts/core.mjs`、`scripts/doc-server.mjs`：继续负责阅读器构建、目录索引和文档读取；它们从同一个已安装模板目录加载。
- 模板依赖：首次直启时在已安装插件模板目录执行锁文件约束的 `npm ci`；后续项目共享同一份 `node_modules`，不写入业务项目。
- 项目目录：只作为文档读取源和运行记录目录；Vite 文件系统白名单继续限制在项目及指定根目录。

### 兼容与恢复

- `init` 保留原有冲突保护和复制行为，供需要项目级定制或旧项目继续使用。
- 已存在且健康的项目服务继续复用；旧的 `.dev-flow` 运行记录仍兼容读取。
- 新运行记录和健康接口带上模板版本/指纹；停止时只清理当前实例的记录。
- 依赖安装失败时不启动服务，保留项目文档与运行记录，不删除项目文件。

## 实施计划

1. 为预览脚本增加模板依赖检查/锁定安装和模板指纹，接入直启服务与 URL 查询；保持复制入口行为不变。
2. 扩展健康响应、运行记录、README、文档预览协议和插件使用说明，明确实际来源和迁移方式。
3. 为隔离项目补充直启回归：服务能读取当前目录、树形阅读器来自模板、项目内不生成 `tools/design-docs`，健康/URL/停止/失效记录行为正确。
4. 执行类型检查、构建、核心测试和 `git diff --check`；重新安装插件并用已安装缓存直接启动 `run-dash`，核验实际地址和树形 UI。

## AI 自查与验收证据

本计划由主 Agent 对照现有 `document-preview.md`、`preview.mjs`、Vite 配置、安装脚本及当前运行事实完成自查。关键假设是插件缓存可写且可使用项目锁定的 Node/npm；实施时以实际 Node 版本、依赖安装结果和隔离服务健康响应核验。不会把“脚本启动成功”替代为树形界面已显示，最终需在真实浏览器中检查目录树与文件导航。

验收重点：

- 直启命令不需要 `init`，且不会创建项目内阅读器源码副本。
- 服务 `/__docs/health` 与运行记录能识别模板版本/指纹，`url` 返回当前服务 PID 和地址。
- 项目文档目录仍按 `--roots` 隔离，树形导航、搜索、文件地址和停止/重启保持可用。
- 已有旧项目复制模式仍可启动，且无项目修改被自动覆盖。
