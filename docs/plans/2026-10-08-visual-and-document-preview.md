# 视觉职责与项目设计文档建设计划

日期：2026-10-08。依据：用户要求继续建设视觉 Agent，明确产品/视觉文档目录与归档，产品文档覆盖原型与详细功能规则，并通过 Vite 统一预览。

## 本轮成果

1. 建立 `dev_visual` 原生配置和 `dev-visual` 专业 Skill。复用共同 UI 规范、现有 React 组件与原型工具，不固定模型；视觉方法覆盖参考、Tokens、布局、状态、响应式、实际渲染检查与资产演进。
2. 建立共同文档协议，产品维护用户流程、限制、可见性、权限、具体逻辑和验收，视觉维护呈现及代码映射。原型源码与证据独立保存，稳定 ID 和相对链接关联。
3. 建立共享 Vite + React 文档预览工程，按指定文档根目录读取文件，支持成熟格式渲染与明确回退。实际服务地址、文件路径、URL 编码由工具处理，运行信息留在项目 `.dev-flow/`，不把临时端口写成长期链接。
4. 用隔离项目验证目录、路径映射、多格式渲染、原型操作、服务恢复及读取边界；验证 Skill/TOML/全局链接。原生角色发现和真实项目成熟度只依据实际执行登记。

## 文档与工具取舍

默认长期文档进入 `docs/dev-flow/product/`、`docs/dev-flow/visual/`；可运行原型进入 `design/prototypes/`。保留已有项目权威目录，用索引适配。日常变更由 Git 追溯；归档用于已替换的完整方案或重要讨论快照，索引指向现行版本。

React 文档工程使用 react-markdown/GFM、MDX 的 Vite 插件、Mermaid，以及 Word/表格等成熟解析工具。HTML 原型保留原入口，Markdown/MDX 可以关联或嵌入。PDF、媒体及常见文本有对应视图；PPTX、旧 Office 与其他专用格式通过有来源的 PDF/HTML 导出或原工具入口补充，不能声明未经验证的完整格式兼容。

本轮不改变现有共享组件的物理位置，不发布 npm 包，不强制迁移实际业务项目。预览工程能复制到项目直接维护；源文档仍由 Git 管理并可被 Agent 直接读取。文档能打开、视觉已检查、交互已验证和生产已交付分别报告。
