# 架构后端到端技术实现方案阶段调整

日期：2026-10-08。范围：按用户要求调整现有研发流程及相关职责/项目资产，不进行业务项目编码或部署。

1. 在重要架构设计确认之后、测试用例定稿之前，增加研发主责的端到端技术实现方案：页面/入口、功能、完整链路、接口/数据/权限/状态、交付产出，关联有效产品/UI/架构。
2. 产品复核需求覆盖与行为，视觉按涉及页面核对设计状态，架构复核契约和约束。实际 AI Review 通过后交测试；方案候选与生产实现分别记录。
3. 测试同时依据原产品/UI/架构和技术方案编写端到端用例，核查方案遗漏，完成用例 AI Review 后交用户确认。通过后研发产出实施计划并 AI 复核，自主编码和持续复验；不新增人工计划审批。
4. 提供技术方案方法与项目模板，更新总纲、执行协议、原生职责、Skills、用例/计划模板与项目索引、当前说明。保留局部任务裁剪、原型职责边界、模型不固定与现有全局链接。
5. 校验相关 Skill、TOML/YAML、本地引用与全局接入；主 Agent 对正常交接、方案遗漏、验收预期偷改、无 UI 及局部复用场景进行规则推演，记录实际方式/限制并提交。

实施前 AI 复核：主 Agent 根据用户当前要求、总纲 v0.12、执行协议及研发/测试/架构现行方法进行单独自查，结论通过。新增阶段以端到端交付范围为对象，先形成可审阅方案，不将用户确认用例之前的工作解释为正式生产编码；原始产品规则持续作权威依据，不能由技术输出缩减需求。两次方案/用例 Review 与实施计划 Review 各有对象，不固定模型或强制委派。现有确认和局部任务可复用，默认没有新增人工技术方案/实现计划审批。此次没有子 Agent 或独立评审声明。
