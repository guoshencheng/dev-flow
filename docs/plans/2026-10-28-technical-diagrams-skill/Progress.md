# technical-diagrams Skill：Progress

## 流程方案与确认

- 目标：创建插件内可独立调用的 `technical-diagrams` 操作 Skill，支持依据项目证据制作、更新和核验 Mermaid 技术图；职责继续负责专业判断和结论。
- 基线：插件能力清单及当前可见 Skill 中无同名 Skill；架构/研发职责已经引用 `agents/references/architecture/technical-diagrams.md`，此前 Mermaid 及 ER 字段指导仍为工作区未安装候选。
- 范围：Skill 入口、触发边界、技术图示操作方法和示例的归属、插件能力声明及必要引用、文档和验证。制图操作方法及技能专用示例归 Skill；架构职责的专业判断仍归职责，调用按需进行；避免双份权威和将 Skill 绑成职责。保留其他迭代的未提交改动。
- 路径：插件兼容能力新增，裁剪业务 UI 原型；按 Dev Flow 和 skill-creator 对能力边界、候选、典型场景、完整变更与交付分别验证。
- 交付：先交付仓库源码候选。宿主安装需遵循版本升级、候选核验和仓库安装流程；已有其他安装迭代未提交改动，未协调前不将其一并安装或发布。
- 流程确认：用户于本对话回复“继续推进吧”，确认修正边界后的流程版本 1。
- 用户决定及实施授权：本对话明确要求命名为 `technical-diagrams` 并做成独立 Skill。
- 边界纠正：用户强调“职责是职责，技能是技能”；依总纲及文档归属协议，职责负责专业判断、成果和交接，Skill 提供可跨职责独立复用的操作方法；不是把技能变成某个职责的一部分。
- UI：不涉及产品 UI。
