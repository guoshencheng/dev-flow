# 独立收尾 Skill 技术设计

本轮原始决定与授权见 [Progress](../Progress.md)。设计 v1 已经[独立 Review](review.md#design-r1)通过；计划 v2 定向复核通过，完整实现 C1 已形成并通过[静态完整候选 Review](review.md#implementation-r1)。关联[实施计划 v2](implementation-plan.md)，隔离行为与本机安装状态以 Progress 实际结果为准。

## 一、本次要完成什么

用户希望收尾指令明确引导 Agent 梳理已有文档，并将有效内容沉淀到项目级通用文档。新增 `iteration-closeout` Skill，既支持直接调用，也由 Dev Flow 的收尾入口调用；实际回写是收尾成果，不能以一段聊天总结或归档状态替代。

范围包含相关资料盘点、专业有效性核对、长期资产同步、代码保存与结束条件核对、遗留和入口更新。不扩展到全项目历史重审、业务代码改造或跨项目插件规则自动推广。

## 二、当前整体思路

当前权威边界见[总纲 0.33](../../../../skills/dev-flow/references/constitution.md)、[文档协议 0.16](../../../../skills/document-management/references/document-contract.md)和[权威归属](../../../document-ownership.md)。源码 0.6.7 的 `dev-flow/references/closeout.md` 编排核对与保存，文档管理参考描述盘点/回写；架构提示词与模板明确总架构同步，但其他资产和实际回写结果未在统一收尾入口形成同等明确的操作要求。

本轮目标关系为：用户收尾请求 → `iteration-closeout` → 读取 Dev Flow 的结束条件；按影响取得专业结论；调用文档管理完成真实回写/索引/归档，调用 Git 工作流保存授权范围成果。箭头表示操作调用关系。纯文本路由，无服务端、运行拓扑或数据库变化，裁剪图示、API 和 ER 图，以上文字完整说明关系。

| 维护源 | 本轮归属与变化 |
| --- | --- |
| `skills/iteration-closeout/SKILL.md` | 新增收尾操作唯一入口：恢复范围、盘点、取得结论、实际回写、保存和汇报 |
| `skills/dev-flow/references/closeout.md` | 保留整体结束条件与授权边界；调用独立 Skill，不复制盘点方法 |
| 文档管理 | 继续拥有目录、状态、版本、引用、归档方法；不裁定专业正确性 |
| 各专业职责 | 裁定受影响资产的有效内容；架构继续独立技术收尾，其他职责按影响参与 |
| 能力声明、生成入口及 README | 纳入 Skill 发现和调用，不新增职责或改安装机制 |

正常研发中的收尾复用有效流程与授权，独立补做收尾恢复已有迭代；明确只整理资料时按范围裁剪。整体阶段及是否需要流程确认仍引用 Dev Flow，不在新 Skill 发明第二套审批规则。

## 三、核心业务流程

### 3.1 发出收尾指令

直接 `$iteration-closeout`、口语“开始收尾/整理本轮并沉淀文档”或正常交付进入收尾时，定位项目、迭代、Progress、最终候选和实际验证/交付。缺少必要完成结果时，允许先整理已证实内容，但整体保持未完成。

### 3.2 盘点和回写

从现行索引、迭代成果和相关源码/配置定位本轮变化，核对既有长期权威位置。按受影响对象覆盖产品规则、视觉规范、总架构/契约、工程方法、回归用例和运行手册；无关对象不创建空文件。

明确每项的来源、目标、实际更新/复用/待核验结果。经过专业判断的有效增量写入既有长期文档；若长期规范尚不存在，建立本轮可核验范围内的最小入口并关联索引。已有规格本身就是合适权威源且无需合并时可直接关联，但不能仅新增链接就声称已将分散增量合并到既有长期基线。

已验证当前事实、历史决定、未实施候选、待核验建议分别处理。遇到矛盾时交所属专业判断，未解决部分不覆盖现行基线。项目内通用文档与跨项目 Skill 方法分开；后者沿既有验证/发布流程提出候选，不默认改其他项目或插件。

### 3.3 保存和完成

回读目标文件并核对有效正文、来源、版本及相对链接，在已有收尾/索引章节记录简表，不强制新增账本。相关源码、测试和文档按 Git 方法及授权保存；长期资产同步和遗留承接完成后才判断逻辑归档。重复执行只处理新增变化，不重复建档或改变历史结论。

## 四、数据结构与状态

使用已有 Markdown、索引及 Progress，不新增状态 schema。最小回写记录字段为“来源与有效范围、长期权威入口、实际变更或复用依据、结果/待办”，可放既有章节或等价文字，不额外创建独立清单文件。工作结束、技术收尾、文档整理/归档和部署状态仍分别表达。

## 五、兼容性/风险/待决事项

- 保留旧 `closeout.md` 路径作为有效流程入口，现有链接继续可达；不批量改写历史证据。
- “只关联、不合并”仅适用于已有资料本身足以作为权威源的情况；既有基线确需同步却未完成，不能报告收尾通过。
- 独立评审与作者分离，真实执行受限时保留缺口；专业判断不由文档操作代理。
- 新 Skill 为兼容能力新增，定稿后版本从 0.6.7 升至 0.7.0；总纲仅澄清操作归属，结束及授权语义不变，协议版本是否调整以实际差异核定。

## 六、验证和交付方式

验证 Skill 结构、调用路由、相对链接、宿主生成一致性及打包资源；独立执行者在隔离样例中按真实请求操作文件，核对实际回写、无变化复用、冲突/候选保留和重复收尾。使用最小场景验证行为，不添加镜像文案的测试。

新增能力后现有安装测试中固定 Skill 数量预期应跟随真实候选清单校验，保留打包和配置保护断言；不修改安装脚本。执行相关隔离安装测试、构建及 Codex install/check，记录实际版本和缓存。Kimi 只同步生成清单，不声明已安装或发现。收尾后同步本仓库 README、安装指南及权威归属等实际受影响长期入口，保留新会话发现限制。
