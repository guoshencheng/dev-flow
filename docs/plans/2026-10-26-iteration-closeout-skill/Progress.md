# 独立收尾 Skill 与长期文档回写 Progress

## 流程方案与用户确认

- 用户原始问题：发出收尾指令时，没有明显引导 Agent 梳理已有文档并写入通用文档。
- 用户本次要求：“做成一个收尾SKILL这样会更佳明确”。
- 目标与范围：在本插件中提供可直接发现和调用的独立收尾 Skill，接通现有收尾入口；收尾应包含本轮资料盘点、有效结论提炼、项目级长期文档更新、来源与遗留承接，以及已有代码保存/验证/交付条件的核对。
- “通用文档”暂按项目内跨迭代复用的权威文档理解，包括产品规则、设计系统、项目总架构、工程规范、回归资产和运行手册；跨项目 Skill/提示词改进需区分为经过验证的通用方法，不把业务事实直接升级为插件规则。
- 当前基线：源码和已安装插件均为 0.6.7，相关收尾入口与文档归档文件字节一致；开始检查时工作树干净。旧入口已有长期资产核对要求，具体盘点与回写方法分散在文档管理参考中。
- 路径：能力与边界设计 → 独立 Review → Skill 与路由实现 → 完整候选 Review 和隔离行为验证 → 版本升级及 Codex 本机安装核验 → 本轮文档同步和完成说明。
- 裁剪：插件指令与方法建设，不增加业务 UI、生产验收或全项目历史重审；不修改安装脚本，不推送、合并远端，不执行 Kimi 原生安装或重载。
- 交付形态：独立 Skill、直接调用入口、必要的协议/职责/模板及能力声明调整、验证记录，以及升级后的 Codex 本机安装。新增兼容能力拟递增 minor，候选定稿时核定版本。
- 流程确认：已确认；用户在本页流程展示后明确回复“好的，开始推进吧”，覆盖本页流程版本 1。
- 展示入口：本页；随本轮回复展示整体路径并请求确认。
- 实施授权：用户“好的，开始推进吧”同时覆盖本页已展示的指令/文档实现与 Codex 本机交付；设计和计划经独立复核后连续实施，不逐文件重复询问。

## 验证与独立性

- 静态检查覆盖 Skill 的发现描述、相对引用、包资源与 Codex/Kimi 生成入口、版本一致性和差异格式。
- 隔离行为验证关注实际文件结果：仅迭代文档含有效增量时是否回写已有长期文档；没有变化时是否有复用依据；候选/冲突或验证缺口是否保留真实状态；重复收尾是否避免重复文档及结论。
- 不把调用成功、模板字段齐全或脚本通过当作实际回写及专业结论正确的证明。
- 独立设计/候选复核和行为验证按专业需要派发，模型使用用户允许的 sol medium；实际派发前读取协调 Skill，未实际执行不登记独立通过。
- 安装脚本不在本轮修改范围；运行本次相关的打包与宿主同步检查，若范围实际扩大再调整验证。
