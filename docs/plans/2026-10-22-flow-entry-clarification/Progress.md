# 启动入口与 Agent 提示词加载澄清 Progress

本文由主 Agent 统一维护本轮进展。用户已确认流程方案 v1，正在按展示范围执行。

## 目标、范围和依据

用户本轮要求：

1. 解释 Agent 配置已有提示词时，为什么仍引用提示词 Markdown/reference。
2. 进度相关文档放到“从目标推进到完成”说明，明确开始进行 Dev Flow 时必须创建流程文档并与用户确认整体流程。

当前源码与安装基线：Plugin 0.5.0，总纲 0.31。工作区位于 `codex/progress-flow-confirmation`，只读核对时无已有未提交修改。本轮是已交付版本后的入口表述维护，拟以 0.5.1 交付，不覆盖 0.5.0 缓存。

已查明的配置事实：生成器组合 `agents/prompts/common.md` 与各职责正文，写入 Codex TOML 的 `developer_instructions` 和 Kimi Agent 正文；专业 `agents/references/` 与模板未被展开内嵌。当前插件声明 Codex TOML 为参考入口、不会自动注册，不能从文件存在推定当前执行者已加载角色。已实际加载相同正文时，无需重复读取源提示词；缺失时才走显式加载的降级路径。保留同源 Markdown 供维护与生成，不删除专业按需参考，也不扩展为个人 Agent 注册任务。

## 拟采用的入口表述

在 `skills/dev-flow/SKILL.md` 的“从目标推进到完成”首项集中说明：

> 开始执行 Dev Flow 时，必须先在本轮迭代创建独立 `Progress.md` 作为整体流程文档，由主 Agent 全局维护。文档列出目标与范围、路径及裁剪依据、全部阶段、职责与依赖、验证、交付和结束条件。主动向用户展示文件链接及整体流程，取得明确确认后再进入后续阶段；不能仅创建文件或说“按 Dev Flow 执行”就继续。已有迭代恢复原 Progress，同范围有效流程确认直接复用。咨询转为设计或研发任务时，先明确告知进入待流程确认阶段，再执行这一启动步骤。

同节关联总体进度规则、Progress 模板和必要的状态核验说明，并保留阶段更新、工作交接与完成说明的责任；从文件尾部移走独立的进度说明，避免启动要求散在角色选择之后。仅查询/解释不强制启动完整迭代，但不能用该例外跳过用户明确要求进入设计/研发时的启动确认。

“按对象选择职责”保留对象到职责的选择关系，明确优先使用宿主实际已加载的职责 Agent，不把维护源链接表写成每次必读的运行步骤。提示词源、生成配置、原生加载、通用执行者降级和专业按需参考的区别，在 subagent 协调文档及相关说明中一致表达。
