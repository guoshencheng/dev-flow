# 研发 Review · 独立文档模板

这是独立 Review 文档的格式预览，尚未执行真实评审。评审意见、修订处理和复核结论在本篇维护，再将有效版本与简短结论更新到[研发设计主文档的引用区](2026-10-21-engineering-document-template.md#八引用与关联文档)。

产品/UI 候选确认前，研发基于实际技术栈和代码反馈功能位置、交互形式与状态设计的成本；产品/UI 据业务价值回应并修订。研发设计由独立架构执行者 Review，产品/UI 分别核对业务目标、行为与呈现承接。计划复核、实现 Review 可以在本篇按阶段分节维护；对象复杂时再拆分，并统一更新主文档引用。每个阶段绑定自己的对象与版本，方案通过不能代表代码或计划通过。多个职责给出意见时指定一个整合写入者，各评审者对自己的发现与复核结论负责。正式验收用例的独立 Review 在验收资料维护，本篇引用其有效结论。

# 〈功能名称〉Review

| 项目 | 内容 |
| --- | --- |
| 关联设计 | 〈主文档链接、版本与范围〉 |
| 当前评审对象 | 〈产品/UI 候选的技术反馈 / 研发设计 / 实施计划 / 完整实现候选〉 |
| 对象版本 | 〈文档版本；实现评审填写开始基线、最终候选及相关未提交内容〉 |
| Review 文档版本 | 〈版本与日期〉 |
| 评审执行者 | 〈执行者与承担职责〉 |
| 执行方式 | 〈独立上下文评审 / 主 Agent 自查，如实记录〉 |

## 一、评审结论

**结论：**〈通过 / 修改后复核 / 阻断〉

〈先用一段话解释结论：方案或实现是否成立，最重要的发现是什么，哪些问题影响继续推进。尚未审阅的范围明确标为未覆盖。〉

## 二、评审依据与范围

〈列出实际读取的原始业务目标、产品规则、设计、UI、架构约束、计划、正式用例（形成后）或代码范围及版本。说明评审者是否参与被审对象编写，独立 Review 须与作者分离。〉

〈方案评审检查业务链路、模块职责、依赖、接口/数据、权限、兼容与恢复；计划复核检查依赖、实施入口、测试保护、集成和交付；实现评审覆盖开始基线至最终候选的完整变更，分别说明需求符合性与实现质量。按对象裁剪。〉

## 三、具体发现与处理

### 〈问题编号与简短标题〉

**位置与事实：**〈定位具体章节、契约或代码，描述实际发现。〉

**影响与依据：**〈解释会导致什么结果，违反哪项有效要求；推测标为待验证。〉

**修改要求：**〈给出可执行的调整方向和关闭条件。〉

**处理结果：**〈研发修订的位置与版本，或不采纳的事实依据；有 tracker 时引用原记录。〉

**定向复核：**〈评审人实际核对的候选、方法、结论及遗留。涉及行为时关联验收复验，不凭“已修改”关闭。〉

〈按需要重复问题章节。没有发现时写明检查范围与成立依据。〉

## 四、跨职责核对与取舍

〈产品说明是否满足原始业务目标、功能入口与恢复是否充分；视觉检查实际页面/交互和状态的必要性；研发基于真实代码比较位置/形式的成本与可复用性；架构检查边界、依赖和契约。说明各方检查了什么、发现什么、如何调整。〉

〈有争议的 UI 状态写清触发条件、用户需要采取的动作、实现代价与建议。调整方案保留必要的等待、错误、权限与恢复反馈；改变已确认预期或重要约束时只确认受影响部分。技术不能单方降需求，产品/UI 也不能忽略有证据的工程约束。〉

〈实现阶段引用产品/UI 对真实候选的检查，以及正式验收用例覆盖 Review 与执行结果；各结论绑定实际对象版本，未执行保留真实状态。〉

## 五、有效结论与引用更新

〈说明最终通过的对象及版本、剩余阻断或限制。对象修订后说明原结论是否仍适用，受影响范围待复核时不得沿用原通过状态。〉

**主文档引用更新：**〈在主文档“引用与关联文档”同步本篇链接、版本、实际状态和一句话结论。〉
