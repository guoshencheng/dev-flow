# 迭代独立进度与流程确认 Progress

本文是本轮唯一总体进度，由主 Agent 维护。用户已确认本文流程，现按该范围执行。

## 目标与范围

用户明确提出：

1. 进展单独在迭代级别全局维护。
2. 流程进行前先与用户确认。

当前基线：插件 0.4.1、总纲 0.30。现行规则允许 Todo/迭代索引作为总体状态权威，且未要求在整体流程开始前确认。

本轮拟修改 Dev Flow 总纲、执行协议、进度规则、任务路由、文档组织与相关模板/职责引用；检查状态核验说明和相关测试是否需要同步。交付包含源码规则、验证结论、版本升级和 Codex 本地安装核验。Kimi 真实安装、其他业务项目文档迁移、跨会话发送通知及远端推送不在本轮范围。

## 拟落实的规则

- 每轮迭代单独维护一个 `Progress.md`，覆盖从目标、流程确认、设计到实现、评审、验收、交付和收尾的全局进展。业务项目默认位于 `docs/dev-flow/iterations/<迭代ID>/Progress.md`；本仓库建设工作沿用 `docs/plans/<迭代ID>/Progress.md`。
- 主 Agent 维护唯一总体阶段状态，写明阶段负责人、依赖、完成条件、成果入口、当前动作、下一步和阻塞；阶段切换、评审回报、验证结果和范围变化后及时更新。
- `index.md`、设计、实施计划和宿主 Todo 只链接或投影 Progress，不再承载另一套独立维护的总体状态。接手既有活动迭代时，将本轮所需有效状态迁入独立 Progress，并保留原始证据来源；不重写历史事实。
- 进入本轮流程前，允许做定位项目、必要的只读了解及拟定流程草案；先建立 Progress，主动向用户提供链接和阶段摘要，明确路径、范围、裁剪、职责、验证、交付及结束条件，取得流程确认后再推进后续阶段。未答复不视为确认。
- 流程确认与业务设计确认、正式实施授权分别记录覆盖范围；可以由用户明确合并授权，不能从单纯认可流程推定其余授权。同一有效流程跨会话复用，不重复询问；范围、关键阶段或交付发生实质变化时，仅重新确认受影响部分。
- 区分两种用途：向用户报告本轮实际成果、验证与安装状态称“完成说明”；执行者之间移交后续工作称“Agent 工作交接”。后者发生在职责切换、阶段衔接、中断或换执行者时，不作为末尾例行汇报的同义词。沿用现有任务包、结果核对和工程接续规则，并在受影响表述中明确交出方、接收方、移交对象、输入/候选版本、授权与写入边界、完成/未完成、证据、阻塞及下一动作；主 Agent 核验后统一更新本轮 Progress。

现有 Agent 工作交接依据：[派发任务包与结果核对](../../../skills/subagent-coordination/references/dispatch-and-lifecycle.md)、[职责公共交接约束](../../../agents/prompts/common.md)、[工程接续模板](../../../agents/assets/engineering/engineering-handoff.md)。本轮术语调整复用这些依据，不将向用户说明完成结果当作已向其他 Agent 完成工作移交。
