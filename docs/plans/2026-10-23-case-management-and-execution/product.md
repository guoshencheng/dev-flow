# 用例管理与执行工具产品设计

> 本文随原工具方案被替代，仅保留历史内容。当前以用户明确要求的[简化方案](design.md)为准，本文的额外字段、工具和证据门槛不再作为本次要求。


本文是待用户审阅的产品设计候选，不表示工具已经实现或业务契约已经确认。总体进度及本轮授权见 [Progress](Progress.md)，统一技术设计见 [design.md](design.md)。

## 用户任务、范围与依据

### 用户与成功结果

- 项目维护者：跨迭代知道当前有效用例是什么、从哪里来、修改影响哪些检查。
- 测试执行 AI：按明确范围执行，换会话和中断后能接续，逐项报告失败和缺口。
- 开发者：使用项目已有测试工具，定位失败并在修复候选上复验。
- 人工验收者：打开清晰的场景与入口，按步骤验证并提交真实结果，不必阅读内部字段或命令日志。
- 交付协调者：分别看清范围是否完整交代、执行是否完成、验收是否通过，以及 Dev Flow 还缺什么。

成功结果：全量有完整清单和逐项去向；增量有变化、选择及未选原因；自动与人工结果汇总到用户场景；历史结果保留原版本，当前结论有明确适用范围。

### 原始要求与范围

来源为本会话用户连续三轮讨论：长期完整维护、全量逐个不漏、方便查看结果、增量用例及人工验证；本轮要求结合现有 Dev Flow 设计串联，先不实现。流程版本 1 已确认，最终设计仍是候选。

本设计面向单项目本地工具与现有 Runner 的接入；跨项目 SaaS、多用户在线协作、自动生成全覆盖承诺、自动修复业务代码及完整可写 Web 平台均不进入首期。本文定义人工交互需求，具体首期入口形式由技术设计比较并提出推荐。

## 流程与原型

### 核心流程

维护业务依据 → 维护并评审用例/检查 → 确定当前候选及环境 → 形成全量或增量执行清单 → 自动执行与人工验证 → 对账及复验 → 生成人可读结果 → 提炼正式验收结果并衔接 Progress。

正式 TC 的维护时点继续遵守当前 Dev Flow：完整候选后维护、独立 Review；实现前可以准备业务完成标准、测试基础设施和可测性反馈。既有稳定回归用例跨轮保留，受影响部分在当前候选后校准。

本轮不制作可运行原型。以下定义信息结构和交互契约，CLI、静态报告或后续页面应满足相同语义；布局、颜色和多端视觉规格不在范围内。

| 页面/状态 | 入口和前置条件 | 用户看到与可以操作的内容 | 动作、下一状态与数据保留 | 规则 |
| --- | --- | --- | --- | --- |
| 当前用例库 | 已选项目与库版本 | 按功能查看业务场景、覆盖缺口、有效/待修订/废弃、自动/人工方式 | 打开场景和变更；修改经校验/评审后成为新版本 | RULE-CM-01～04 |

## 异常与恢复

- 库引用错误/用例编号重复/执行入口不存在：指出对象与修复方向，保留缺口；不能通过缩减清单掩盖。
- 服务、身份或数据不可用：标注受阻原因与负责方，继续独立项。环境已知不同的结果不能并入原批次通过结论。
- 执行进程中断：已落盘结果保留；未开始项保持待执行；已开始无结束项为结果未知，需核对副作用后恢复。
- 候选在执行过程中变化：暂停受影响项；原批次保留，下一候选新建批次并关联仍可复用的证据。
- 重复导入/重复人工提交：同一请求重复发送应幂等；不同结果冲突须显式更正或复验，不能按最后写入静默覆盖。
- 报告生成失败：原始清单和记录仍可恢复；生成人可读报告不能修改测试结论。
- 原始证据在另一机器缺失：明确不可取得，恢复必要材料或复跑；持久结果须保存复跑方法和版本，不依赖私有路径作为唯一交接入口。
- 人工任务页面关闭/取消等待：任务仍待验；不代表业务动作取消或验证完成。候选/前置变化后的旧提交应拒绝用于当前结论并保留来源。

## 决定、关联与变化影响

### 推荐取舍，待设计评审和用户审阅

- 优先文件式资产与 CLI，兼容现有测试工程；人可读报告共享同源数据。
- 测试用例、技术执行检查和执行结果分离；正式业务规则继续引用产品来源。
- 全量指声明范围内的完整执行，不承诺穷尽未知需求；覆盖 Review 与执行对账分别完成。
- 首期包含人工队列及可追溯提交能力；可写 Web 工作台是否首期提供由技术设计比较成本，静态报告不能伪装成已提交。
- 自动影响分析为辅助；未知影响保留并扩大回归，不自动批准业务预期变化或豁免必需项。

### 与 Dev Flow 的关系

产品先固定业务完成标准；研发维护真实入口与 Runner；测试在完整候选后维护/评审正式用例及执行；架构核对边界与契约；运维提供实际环境与交付版本；主 Agent 核验专业结果并维护唯一 Progress。

后续实施若采纳本设计，需要定向更新用例与执行 Skill、模板、结果映射和接入说明，另行确定兼容迁移与插件版本；本轮不修改这些现行规范。用户对流程的“好的”不登记为本产品设计已确认，也不形成实现授权。
