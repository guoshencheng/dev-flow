# UI 确认优化实施计划

| 项目 | 内容 |
| --- | --- |
| 有效输入 | [设计 v1](design.md)、[Progress 流程 v1](../Progress.md)、用户在路径展示后的“继续推进” |

| 负责人 | 主 Agent 唯一修改共享文件；独立执行者只写各自评审/验证资料 |

## 一、实施目标与前置条件

完成 UI 方案展示、确认和复用的清晰规则及上下游承接；用户已授权本轮修改、验证和 Codex 本机交付。设计/计划经独立复核且本轮通过隔离 worktree 实施，原工作区其他未提交变更不纳入本次安装。另一活动迭代的暂存区和内容不重置、不混入本轮提交。

## 二、实施步骤与依赖

1. 在执行协议集中定义触发、候选制作与展示、确认来源、复用/明确指令/自主委托及变更要求，更新总纲、入口和路由。
2. 产品、视觉、研发职责各补本职确认承接；Progress、产品与视觉规格、研发计划/Review 模板加入必要分类和来源核对。原型 Skill 强调隔离候选与正式实现的区别；状态协议说明现有 gate 登记和核验限制。
3. 自查跨入口用词和引用；按设计形成完整候选并独立 Review，不在未复核候选上登记通过。
4. 组织隔离场景执行，观察确认请求、继续条件和实际文件结果，修复后定向复验。
5. 实际基线核定后按 0.x 收紧升级 0.8.0/总纲 0.34/执行协议 0.18，同步当前版本说明、生成入口并检查；新文件纳管，执行适用测试和打包。
6. 顺序执行 Codex install/check，核验实际缓存、角色和源码指纹；保存本轮差异和实例资料，完成文档回写与结束条件核对。

本轮隔离 worktree 中的共享文件由主 Agent 唯一写入；隔离评审者只写 `engineering/review.md`，行为执行者只写本机临时工作目录，不能修改插件规则。无数据库、API 或业务 UI，不创建空接口/迁移表。

## 三、测试保护与持续集成

- 运行 `python3 scripts/sync_host_agents.py --write` 及 `--check`，确保 Codex/Kimi 入口包含有效维护源与同一版本。
- 运行阶段核验、原生角色与打包相关现有测试；本轮不改安装代码，仍以现有隔离打包/安装测试核对受影响生成入口及资源引用。
- 场景测试以实际执行输出及文件变化为准；纯文本静态检查不算 Agent 行为通过，不新增复述实现的关键词测试。
- 初步代表场景：新增页面与未决布局、纯视觉新风格、恢复已确认设计、用户明确指定调整、实施中偏离、无 UI、规范内细节、隔离原型、明确委托。正式候选形成后维护可读用例并独立核对。

## 四、完整候选与验收安排

完整候选包括集中规则、路由和职责承接、记录/Review 模板、生成入口和版本说明；不变算法的边界明确。独立评审检查本轮从稳定基线到候选的完整差异；行为验证使用固定规则输入，并报告实际输入及未覆盖。未完成、失败或未观察的场景保持未完成。

## 五、计划 AI 复核引用

待形成 `review.md`；主 Agent 不把自查登记为独立 Review。

## 六、执行与重要调整
