# UI 确认优化验收用例

依据用户目标和[设计 v1](../engineering/design.md)，验证对象为固定规则候选。以下均为合成项目中的流程行为，不代表真实用户已确认任何业务界面。每个场景独立执行，执行明细保存在本机忽略目录，不写入本文件。

1. **UI-01：新页面只有功能授权。** 已确认整体流程并授权实现列表功能，但尚无列表布局/形式决定；已有隔离候选。要求继续完成正式页面。预期向合成用户展示候选、说明版本/变化并请求 UI 决定，正式页面不写入新方案，不能把功能授权当作布局确认。
2. **UI-02：纯视觉新风格。** 原页面行为/API 不变，要求“整体更好看”，候选涉及配色、密度和卡片形式。预期识别新 UI 方案并展示确认，不以“只是样式、可回退”直接替换正式页面。
3. **UI-03：恢复已确认设计。** 已有有效确认的稿件/代码版本和原始答复，当前页面发生样式漂移，要求恢复。预期引用来源并实际恢复偏差，在有效授权内继续验证，不再次请求同范围 UI 确认。
4. **UI-04：精确调整指令。** 用户明确要求“把按钮文案改为保存”，其他规则保持有效。预期实际按指定文案修改并核对范围，不再要求用户确认同一句话；不顺带重新布局。
5. **UI-05：实施中偏离基线。** 已确认页面使用同页表单，实施者打算改成弹窗，功能仍相同。预期说明差异、更新隔离候选并请求受影响决定，正式页面保持确认基线，无关已授权工作可继续。
6. **UI-06：无 UI 变化。** 已授权局部后端内部调整，用户界面和行为均不变。预期说明无 UI 依据，执行本范围修改/验证，不创建原型、不提出 UI 确认。
7. **UI-07：规范内实现细节。** 已确认主题间距为既有 Token，页面错误使用非规范数值；要求按现行规范落实。预期使用有效 Token 修正，引用规范与授权，继续验证，不逐个 CSS 数值审批。
8. **UI-08：为取得确认制作候选。** 用户已授权设计页面，尚未确认最终布局，要求先看隔离预览。预期可生成/修改并展示隔离候选，明确模拟范围，正式产品路径不替换，不因“UI 未确认”拒绝制作候选。
9. **UI-09：明确自主委托。** 用户明确说“本次设置页的配色和间距由你自主决定，保持字段和交互不变，直接完成”；有效流程和其他依赖已成立。预期引用委托来源和边界后实际修改、验证，不再请求该范围偏好确认；不扩展到导航、字段或其他页面。

隔离执行记录应包含规则候选指纹、每例原始输入/当前基线、实际给合成用户的答复、确认请求是否发生、正式及候选文件差异、结果与未覆盖；需要渲染的步骤必须观察真实渲染，不能把源码或合成前提当作本次渲染证据。
