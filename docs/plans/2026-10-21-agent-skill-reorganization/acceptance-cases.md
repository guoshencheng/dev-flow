# 重组候选的验收用例

依据：用户五项结构方向、已确认规划和 0.3.0 的有效流程语义。对象：当前重组候选，发布前升到0.4.0。用例预期从这些依据推导，不以生成器当前输出决定正确预期。

| ID | 场景与输入 | 操作与可观察预期 | 验证方式 |
| --- | --- | --- | --- |
| TC01 | 用户需要完整功能、修复或开始收尾 | dev-flow 说明阶段/依赖/授权/完成；操作路由至独立Skill，保留快速路径授权、独立Review、正式TC后置与必需交付 | 独立源比较Review、阶段核验器44项回归 |
| TC02 | 单独Git提交/分支任务，夹杂用户已有修改 | 加载Git Skill，在临时仓库只提交指定文件，保留其他暂存/未暂存，取得完整差异；不重启完整研发审批 | 隔离真实Git操作与差异核验 |
| TC03 | 需要实际子Agent只读检查 | 加载subagent Skill，任务包有输入/候选/写入/独立性；实际调用Harness且结果不自动通过；限定场景完全无子Agent时只能作者自查，必需独立gate保持未完成 | 本轮真实派发/续派/等待及独立任务包检查；核对无法原生派发时的执行方式声明 |
| TC04 | 用户要求Web阅读本轮文档 | 从新文档Skill路径启动/复用，URL核验真实项目/文件，浏览器可读并渲染归纳图，三份资料链接可访问 | 阅读器3项测试、类型/构建、实际浏览器；隔离项目索引/版本/逻辑归档演练 |
| TC05 | 六职责直接获得任务 | 提示词有实质目标/判断/边界/交接，可按需使用参考Skill；保留48能力，无旧Skill转读依赖 | 独立提示词Review、代表任务行为演练 |
| TC06 | 当前任务为表达业务流程和正式测试用例 | 产品输出有效RULE/AC及未知，测试据原预期输出TC；不反推预期、不提前设置正式TC实施门槛 | 产品/测试代表任务及独立评审 |
| TC07 | 初始化设计原型与组件复制 | 新路径工具产出自包含副本；保留定制、拒绝越界、完整资源/许可；类型与构建成立 | 模板5项测试、组件源码复制消费者检查/类型/构建 |
| TC08 | 回归验证与缺陷诊断 | 前者证明已知目标旧失败新通过，后者以假设实验定位未知原因；普通实现/Review责任不被Skill吞并 | Skill静态独立Review、隔离回归/诊断代表任务 |
| TC09 | 运行、发布、恢复和会话监控 | 分开当前运行事实、业务验收和操作授权；发布不扩大为数据恢复/退役删除；监控不新增调度或发送 | 职责/技能Review、隔离运行案例 |
| TC10 | 清单漏项、错误路由或资源越界 | 校验明确失败；已声明角色/Skill/参考/模板/必需工具随包，不能简单数文件 | 安装隔离测试，提示词/工具/路由删除或篡改及旧职责入口重新出现的负例 |
| TC11 | 从同源提示词生成两个宿主入口 | common+完整角色内容一致，按入口位置重写有效链接；无开发机绝对路径，不自动注册个人Agent | 生成 --write/--check、包检查、独立Review |
| TC12 | 升版、构建并安装 | 两清单/Kimi版本一致、源码/包/缓存指纹相符、声明16Skill真实启用；用户配置保留；Kimi未真实更新则明确限制 | 隔离安装测试、实际install/check、独立宿主状态说明 |

执行记录见本轮 verification.md。未执行、待复验与不适用分别记载，不把静态检查/工具样本登记为真实业务项目交付。六职责演练使用实际Harness上下文及真实输入，原生角色发现另记；不通过角色名称推断原生支持。
