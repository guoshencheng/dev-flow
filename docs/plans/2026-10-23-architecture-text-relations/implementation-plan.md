# 架构关系文字表达实施计划

范围、授权和阶段由[Progress](Progress.md)统一维护。本篇中文设计摘要与实施步骤适用于此次局部方法维护。

## 内容契约

规范明确：即使不看图，也能从正文或表格读出关键架构关系；不依赖图片、颜色、坐标、SVG路径或箭头图例猜测事实。图与文字属于同一版本的互补表达，使用相同真实名称、范围、状态与代码依据。

1. **分层/包含**：写出模块属于哪一逻辑层/业务域、谁包含谁、职责、源码路径/关键符号；逻辑归属与进程/部署边界分开。
2. **源码依赖**：明确依赖方→被依赖模块/类型/函数端口、关系类型、作用与依据；声明关键禁止反向依赖/边界限制，允许依赖与实际依赖区分，不能从运行调用反推源码导入。
3. **端口实现**：明确外层实现者实现哪个由哪一层拥有的端口，关联实际符号；可按结构化对象、函数集合或回调端口表达，不强造interface/class。
4. **装配注入**：明确装配位置、实际实现/工厂、消费方、注入参数/字段或调用边界，注明适用环境/选择条件及源码；源码引用、创建、传入和运行时调用分别说明。未查明保持未知/待核验，无独立端口/DI时写事实与裁剪依据。

采用层次职责表加关系清单：关系清单至少有“类型｜主体｜关系对象｜含义/注入目标及条件｜源码依据与状态”。精确参数名只在已核验时填；例子明确虚构。正文可以等价完整表达，不强制重复相同大表；已有权威文字在相同可访问文档链路中可引用其章节与版本，不能只引用图。项目总架构维护唯一事实，迭代只列增量并在收尾同步图和文字。

## 文件与步骤

1. 修改 agents/references/architecture/technical-diagrams.md：新增无图阅读规则、四类文字字段与检查方法；SVG要求关联此规则，不改变绘图选择。
2. 修改总架构/现状地图/研发设计模板，加入明确编写要求及可直接填写的关系表；现状地图引用权威清单并补核验，不平行维护。相关架构与研发Review、架构收尾入口增加无图检查/同步要求。
3. 在既有Order示例补足分层包含、全部重要源码边、端口实现与bootstrap注入的文本/表格；运行拓扑例子补部署归属及关键通信的文字清单，避免关系只存在于SVG。不改SVG、时序或ER语义。
4. 独立审阅完整候选，暂时不看图，先从Markdown复原四类关系，再对照SVG及源码示例说明；检查文字未把虚构示例当真实项目，未知/不适用不造事实。正文路径/锚点、表格解析、既有SVG哈希及sync_host_agents检查，运行适用现有回归。
5. 版本0.6.2→0.6.3：同步两份plugin.json，生成Kimi清单及职责入口并check，更新README/docs/plugin.md和长期能力说明。新文件纳管后install/check，逐文件读回缓存与source_commit、关键文字/资源、角色/Skills及用户配置保留，由独立执行者核验。
6. 记录结果、保存完整提交并以clean HEAD重建安装核验；普通推送远程main并比对SHA。收尾记录提交后若包内内容变化，再按最终HEAD重装，最后工作区保持干净。不重写已完成历史记录。

## 已知风险与覆盖

重复维护导致图文漂移：同名/同版本并检查双向对应，权威来源只保留一份；规范要求与例子共同落地。文字信息过重：只记录关键边界关系，不枚举所有import，不为简单图引入额外工具。AI未打开引用：关键结论及关系在正文可见，引用附明确章节/版本，不能仅指图片。安装/推送未知：查询实际状态不盲目重复；保护用户配置，不强推或覆盖其他工作。
