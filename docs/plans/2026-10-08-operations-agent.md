# 运维与交付 Agent 首版建设计划

日期：2026-10-08。范围：在现有 Git 维护的职责体系建设 `dev_operations` 和 `dev-operations`，接入全局链接；本轮没有业务项目或部署目标，不发布业务服务。

1. 依据总纲 v0.11 与 O01–O08 形成职责入口、原生配置和按需专业方法：环境与启动、产物与发布、运行观察与故障、恢复、环境演进与项目资产。
2. 区分研发候选、验收结论、交付运行和外部发布；延续用户确认设计/重要架构/用例、AI 复核计划后自主实施。运行原型仅提供设计服务，不升级为实现验收。
3. 复用项目现行命令和 README/runbook；没有规范时采用项目 `docs/dev-flow/operations/`。提供运行入口、交付记录和故障/恢复记录模板，版本与当前环境实际核验结果关联。
4. 复用已定义的 React/Vite、Next.js 与 Astro 基线，核对官方交付说明，不添加云平台或其他通用技术栈选型。
5. 在隔离工作副本重建既有真实 HTTP/文件数据样本，生成有指纹的可分发源码包，在另一目录解包启动；实际验证核心写入/读回、进程重启、健康正常但业务失败的候选、回退保留数据及停止后备份恢复。仅登记主 Agent 的工具/方法执行，不声称模型独立评测、框架构建或生产部署。
6. 更新共同协议和各职责交接链接，检查 Skill/TOML/YAML、引用和全局接入，记录证据与缺口，提交已知变更。安装脚本及文档阅读器不改动。

实施前 AI 复核：主 Agent 对照已读取总纲、能力目录、研发/测试交付方法、安装脚本与样本源码完成单独自查，结论通过。职责与阶段边界明确，模型配置保持宿主选择；样本已有真实文件读写和健康接口，可以固定业务判据并验证恢复，产物/数据/运行记录隔离且只停止自管进程。外部发布仅按实际授权执行，未知结果先查询；用户已授权本轮职责建设和全局接入，没有需要新增人工审批的实现计划事项。此次未委派，没有独立评审或原生派发声明。
