## 一、本次要完成什么

### 背景与目标

当前安装插件只加载操作 Skills，六份 Codex TOML 留在包内，用户若要直接按 `dev_product` 等名称派发还需手动配置。此次使既有 `python3 scripts/manage_plugin.py install` 同时注册六职责，升级同步正文和资源路径，`check` 核验注册完整性，`remove` 清理本插件拥有的注册。

### 本次范围

- 新增：六个个人原生角色的受管副本、持久归属记录、安装生命周期保护及隔离测试。
- 调整：安装命令将写入 Codex 用户目录；同步仓库约定、生成入口注释及现行说明，发布 0.6.0。专业提示词及 Kimi 原生机制保持现有来源。
- 范围外：不改全局 AGENTS.md、config.toml、模型/推理默认，不覆盖用户角色，不增加 Hooks 或 MCP。插件页面入口核实并说明边界，不冒称支持自动注册。

### 完成标准

| 编号 | 可观察结果 |
| --- | --- |
| AC1 | 一次 install 后六份有效角色 TOML 位于实际 Codex 用户目录的 agents/，正文内资源引用指向经过核验的安装缓存，用户不需逐个配置 |
| AC2 | 同一命令可重复安装与升级；角色正文及资源根路径随当前已核验缓存更新 |
| AC3 | check 同时验证插件启用、来源/源码/缓存、六角色正文与归属；缺失、用户修改、错误缓存均不能假通过 |
| AC4 | 安装前发现非受管同名文件、链接或目录时明确报冲突，在插件安装副作用前停止；不覆盖用户内容 |
| AC5 | 普通写入异常撤销本次角色和归属记录字节改动；不保证外部 CLI 操作后的旧缓存仍存在，失败不返回成功，修复环境后重新 install 恢复 |
| AC6 | remove 只删除归属明确且内容未变化的角色及归属记录；受管角色被用户修改时整体拒绝卸载，保留插件及资源供处理冲突后重试 |
| AC7 | 自定义 CODEX_HOME 生效，无关角色和用户配置逐字节保留；真实注册、原生发现和实际派发分别记录 |

## 二、当前实现与整体思路

### 当前如何工作

`scripts/sync_host_agents.py` 从 common 与六职责正文生成 `agents/dev_*.toml`，Markdown 相对链接以包内 agents 目录为基准。`scripts/manage_plugin.py` 安装后核验缓存及实际启用并保存仓库本机记录；check 对照受管理源码；remove 移除本仓库插件来源。当前系统 Python 为 3.9，无 tomllib。

### 本次准备如何调整

新增 `scripts/native_agents.py` 专管六角色副本和归属，安装编排仍由 manage_plugin 负责。以安装缓存的 TOML 为输入，将正文内包内相对链接变为已核验缓存的绝对链接：路径逐字节使用 URL 百分号编码（保留 / 与冒号），目标包在 Markdown 尖括号中，原片段后缀单独保留；不将路径中的 # 当片段，也不将括号当 Markdown 定界符，再将副本写入 Codex 用户目录。角色不引用开发仓库；不复制整包到用户角色目录。

以下是目标模块与数据边界，箭头表示调用或生成数据；各目录不是独立进程。省略既有打包细节；安装缓存与角色副本都是实际本机文件。

```text
manage_plugin install/check/remove
  ├─既有打包/CLI/缓存核验 → 已安装插件缓存（唯一专业资源）
  └─native_agents → CODEX_HOME/agents/dev_*.toml（六个可发现入口）
                   CODEX_HOME/dev-flow/native-agents.json（归属和指纹）
```

采用文本结构图而非额外绘图依赖：图中是单进程局部文件边界，Review 可直接核对图文及调用关系，无 UI 渲染成果。

### 技术反馈与方案比较

包内 TOML 软链接最简单，但其相对 Markdown 路径可能按个人目录解释，且链接指向旧版本缓存时升级与卸载容易留下悬空配置。受管普通文件副本可用独立指纹检测用户改动，所有资源引用显式绑定缓存。配置只含现有三字段，使用标准库 JSON 编码读写生成器的字符串字段，避免新增 TOML 依赖。

插件页面没有经核实的安装脚本回调；SessionStart Hooks 需额外信任且不等同安装回调，不采用。独立宿主调查完成后补充证据，不阻断已授权的脚本优先目标。

## 三、核心业务链路

### 链路一：首次安装、重复安装和升级

前置为受管源码及 Codex CLI 可运行。解析 CODEX_HOME（未设置则 ~/.codex），获得本插件专用操作锁，检查归属记录和六目标文件。未经归属记录证明的同名目标一律拒绝；受管角色被改动或链接替换也拒绝。缺失受管文件允许 install 修复。

预检通过后沿用既有 build、marketplace add、plugin add 和全包缓存核验。只使用实际返回且验证通过的缓存构造角色正文和指纹，原子替换六个角色和归属记录，保存仓库安装记录，返回角色数及实际目录。重复运行同样完成核验；升级将六个副本与缓存根路径一起刷新。

失败与恢复：预检冲突不执行插件 CLI 变更；CLI 或缓存核验失败不写角色。角色写入的普通异常回滚本次已写入文件及归属记录；不能假定 CLI 升级保留旧插件缓存；文件回滚不等于原角色资源仍可运行。插件 CLI 已产生的安装状态不做未经证明的自动回退，报错明确要求重新 install 恢复，check 不会将旧状态判为新安装通过。无法保证断电或 SIGKILL 的跨文件原子性，check 会暴露异常，保留现场，不宣称安装成功。仓库记录也纳入同次文件事务，避免注册成功但本机检查入口失效。

示例：0.5.2 尚未注册的用户运行 0.6.0 install，得到六份角色；下一版本 install 将其正文路径切换到新版本缓存。

### 链路二：检查与卸载

check 先保留原启用、来源和源码/缓存核验，再要求归属源与当前仓库一致、缓存根路径一致、六目标为普通文件且与指纹和预期正文完全一致。旧版安装没有注册记录时返回明确“运行 install”提示。

remove 在插件 CLI 移除之前验证归属源及所有仍存在的受管文件。没有归属记录不删除角色；受管文件已缺失允许清理记录；发现修改或链接时拒绝整个操作，保留内容、插件和缓存供恢复。成功移除本仓库插件与来源后删除受管文件和记录，异常回滚文件操作并明确失败；CLI 已移除的状态可通过重新 install 恢复，不声称跨外部 CLI 的事务。

## 四、架构与模块设计

### 模块分工

| 模块 | 负责什么 | 协作与边界 |
| --- | --- | --- |
| sync_host_agents | 声明、源正文与包内生成入口一致 | 更新注释和主机标识，不写个人目录 |
| native_agents | 用户目录解析、锁、归属、路径转换、文件事务、注册/检查/清理 | 接收已验证缓存与插件身份；只管理固定六文件和自己的状态 |
| manage_plugin | 插件构建、来源、CLI 状态、安装记录与注册编排 | 保留现有 install/check/remove 命令；共享文件写入串行化 |

### 接口与数据契约

角色目标为 `agents/dev_{role}.toml`，role 为现有六职责固定集合。状态固定在 `dev-flow/native-agents.json`，字段为 schema=1、owner=dev-flow、plugin_id、source_root、plugin_root、files（固定文件名到 SHA-256）。拒绝未知字段结构/角色集合/无效指纹；不从状态任意文件路径执行删除。source_root 区分同名插件的其他源码来源。

Codex 用户目录优先读取 CODEX_HOME，不改该环境变量本身。agents 目录、插件状态目录、状态和目标文件若为符号链接或类型不符则拒绝操作；显式 CODEX_HOME 根可解析为实际目录。状态中的缓存根绑定实际核验结果。文件操作使用同目录临时文件和 os.replace，回滚保留此前字节内容。

### 必须保持的约束

安装、检查和卸载持有本插件同一操作锁；锁只协调本安装工具，不阻止用户或宿主编辑。提交文件前再次校验预检状态，避免本工具长时间 CLI 操作后覆盖用户期间的修改。修改的受管文件不自动接管。目录中其他 TOML 若声明相同原生 name 也应作为冲突处理，避免不同文件名的名称碰撞；使用 Python 3.9 标准库实现仅提取顶层 name 的有界 TOML 词法扫描，词法层可靠跳过注释、单行/多行字符串内容及数组/inline table 的嵌套内容，在真正的顶层表头开始后不再采集根字段；支持裸键/引号键、基础/字面量/多行字符串和 Unicode 转义；拒绝重复根 name、无效转义、未闭合结构及不能可靠识别的赋值。多行字符串可跳过以避免把 instructions 内容误当字段；无法确定唯一合法 name 的外来配置保守报错，给出文件位置，绝不猜测后覆盖。不尝试校验其余 TOML 业务字段，不依赖外部解析库。

## 五、具体实现设计

### 注册与来源核验

新增 native_agents 模块；manage_plugin install 在首次预检后安装，注册事务包含六副本、归属和仓库记录。check 对比精确预期内容而非只统计数量。remove 使用本仓库 source_root 与记录指纹校验所有权。生成入口为可安装源，不在生成时写绝对开发路径。

边界：空用户目录、CODEX_HOME 含空格、缺失受管文件、同名外来文件、用户修改、目标链接、来源改变、并发安装、写入失败、缓存损坏、同名不同文件均纳入相关检查。使用 Unix flock，对本仓库实际 macOS/Linux CLI 环境生效；Windows 不作为本轮已验证交付。

### 配置、依赖与数据变更

增加个人归属 JSON 及锁文件；无服务、Hooks 或网络依赖新增。版本 0.6.0 属于安装能力新增，协议总纲 0.32 不变。Kimi 清单随版本重新生成，不更改其安装机制。

## 六、兼容、风险与待决事项

旧安装可直接再次运行 install 获得注册。历史 setup 残留未证明归属时作为冲突保留；错误说明精确文件及人工处理方式。GUI 禁用或直接卸载不会触发本工具清理，说明应使用 manage_plugin remove 管理受管注册，页面操作后 check 能报告未启用；不注入非支持回调。

页面安装调查已完成：官方未说明 agents 自动注册或安装回调；Hooks 需单独信任且没有 Install/PostInstall，onboardingSkill 需用户运行 setup。因此本轮不宣称页面安装能自动注册。PATH CLI 为 0.156.1，桌面捆绑 CLI 为 0.163.0-alpha.11.1，分别记录。本机原生角色发现接口继续核实；实现前独立 Review 确认解析方案、事务边界与可测试性。
