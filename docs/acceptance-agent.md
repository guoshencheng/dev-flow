# 测试与验收 Agent v0.3

更新日期：2026-10-08。原生职责 `dev_acceptance`，配置见[dev_acceptance.toml](../agents/dev_acceptance.toml)，专业入口为[dev-acceptance](../skills/dev-acceptance/SKILL.md)。配置不固定模型/强度，实际执行方式与成熟度分别登记。

## 职责与执行关系

测试综合有效产品/交互/UI、架构与经符合性 Review 的端到端技术方案，依据拟交付页面/入口/功能/OUT/链路设计可读端到端用例；从原产品反查遗漏，不能以技术方案缺项缩减需求。用例实际 AI Review 通过后提供拟交付范围/可读场景，由用户确认预期；研发再计划/AI 复核并自主编码。

测试持续实际执行、反馈和复验，以当前版本端到端及适用架构证据验收。方案 Review、用例 Review、人工确认和实际验收分开保存版本/来源，不能改写用例来迁就实现。

测试主责用例、测试策略与自动化、执行/证据、缺陷复验和验收结论。研发主责生产修复；产品/视觉/架构分别维护语义、呈现和契约；运维维护启动与实际环境。测试脚本可以维护，重要验收含义变更仅确认受影响部分，不增加人工计划审批。

## 不同测试验收方案

v0.2 明确阶段与对象：设计文档/原型的流程、规则、交互及恢复走查由产品主责，呈现由视觉主责；测试可读取设计，早期检查用例/覆盖/可测性，实际验收默认面向可运行实现与交付候选。原型可点或使用 Mock/浏览器工具不改变路由。用户明确指定测试检查原型时限定范围、单列证据，不登记实现验收。修订依据与范围见[边界回溯](../reviews/2026-10-08-prototype-review-routing.md)。

| 方案 | 首版要求 |
| --- | --- |
| 局部规则/组件 | 沿用现有工具，React 可用 Vitest/Testing Library；断言用户行为与业务规则，标明模拟边界 |
| 前端界面 | 实际浏览器操作导航、表单、列表、状态、透出/键盘及目标设备；Mock 场景单独记录，视觉检查与行为分别验收 |
| 后端接口/数据 | 真实调用检查输入输出、权限/拒绝、业务状态和读写结果；必要重复、并发、兼容/恢复按契约补充 |
| 前后端 E2E | 实际界面动作 → 对应请求/响应 → 服务端结果/读回 → 刷新或重新进入，以及相关异常恢复 |
| 交付启动 | 在声明版本/环境实际构建、准备、启动/安装/访问并完成核心任务；本机与目标部署分别记录 |
| 回归与专项 | 依据变化、共享契约/组件和历史缺陷选择；性能/可靠性等已有目标采用对应场景与测量 |

成熟工具优先复用，新 Web 浏览器/API 自动化默认 Playwright。React Web、Next 全栈、Astro 静态的既定技术选择继续有效；纯 API 或纯静态按对象裁剪。不能只以截图、2xx 或 Mock 全绿登记完整验收。

## 八项能力如何落实

| 能力 | 首版专业内容与项目产物 |
| --- | --- |
| T01 场景与可测性 | 可读 TC ↔ OUT/链路 ↔ RULE/AC/UI/ARC，前置/操作/预期、用例 AI Review/人工确认基线与真实覆盖 |
| T02 功能与边界 | 正常/边界/拒绝/异常、接口与业务数据不变量，当前候选真实执行 |
| T03 界面交互 | 实际导航、输入、状态和恢复；B/C 任务、目标窗口/键盘与呈现检查 |
| T04 端到端交付 | 从真实入口关联 UI/请求/响应/服务端结果与持久性，核验约定启动/交付 |
| T05 回归 | 变化影响到场景/消费者，原缺陷保护与本轮必要回归 |
| T06 专项 | 适用的架构/权限、性能/可靠性/兼容等目标与对应证据；不默认全专项成熟 |
| T07 缺陷对焦 | 最小复现、版本/证据、研发反馈、修复版本、原问题复验与关闭 |
| T08 自动化与复用 | 项目工具/数据隔离、稳定检查、失效管理与新任务可恢复资产 |

对应方法分为[策略与用例](../skills/dev-acceptance/references/strategy-and-cases.md)、[前端与界面](../skills/dev-acceptance/references/frontend-and-ui.md)、[后端接口](../skills/dev-acceptance/references/backend-and-api.md)、[完整链路与交付](../skills/dev-acceptance/references/end-to-end-and-delivery.md)、[执行与反馈](../skills/dev-acceptance/references/execution-and-feedback.md)、[项目资产](../skills/dev-acceptance/references/project-assets.md)。主入口按需加载，工具兼容与实际命令在项目采用时核验。

## 项目目录、预览与持续建设

已有测试规范优先；没有时使用 `docs/dev-flow/acceptance/index.md`、`strategy.md`、`features/<功能ID>/cases.md`、`runs/<日期>/<runID>/report.md`，缺陷优先用现有 tracker，自动化继续保存在项目实际测试目录。策略、用例、报告与缺陷各有随包模板，普通历史用 Git，完整替代方案按共同归档规则保留。

项目主索引关联测试与产品、UI、技术、运行入口。用户讨论/确认通过业务项目的文档服务预览该项目的用例/方案，执行时操作实际应用；Skill 文件是方法来源。每轮维护测试/数据/缺陷与证据版本，下一任务读取有效资产及待复验范围。
