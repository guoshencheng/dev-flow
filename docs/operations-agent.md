# 运维与交付 Agent v0.1

日期：2026-10-08。原生职责 `dev_operations`，源配置[dev_operations.toml](../agents/dev_operations.toml)，专业入口[dev-operations](../skills/dev-operations/SKILL.md)。配置不固定模型/推理强度；当前执行者按 Skill 承担工作与原生发现/派发分别记录。

## 从工程候选到可用交付

运维读取当前项目有效架构、工程、用例与交付约定，恢复环境/配置/依赖和实际版本。无目标默认可启动交付；源码、安装包、预览部署、生产部署按各自实际入口验证。应用回退、配置回退、数据恢复与迁移兼容分别判断，业务结果和进程健康分别取证。

复用用户确认的产品/UI、重要架构与测试预期；研发计划经实际 AI 复核后自主实施，不增加人工计划审批。运维提供可审阅候选、环境/发布和恢复安排，已有授权持续推进，缺少目标或外部动作决定时仅确认缺失部分。未知发布/迁移先查询实际状态，不能盲目重试。

运行原型/项目文档服务仅提供设计阅读入口，产品/视觉仍主责设计走查；可运行原型不升级为实现或生产交付。研发修复实现，架构维护契约/运行边界，测试验收当前候选，运维核验实际环境并维护运行知识；兼任时登记方式，不声称独立验收。

## 八项能力

| 能力 | 判断与项目产物 | 验证方式 |
| --- | --- | --- |
| O01 环境与启动 | runtime/依赖、配置样例、生效时机、数据、命令/cwd/实际地址与停止 | 新工作副本或要求环境按说明启动，核心任务及停止/再启动成立 |
| O02 构建与分发 | 源版本/未提交指纹、构建输入、产物位置/摘要、平台与入口 | 操作实际产物，来源对应且不依赖未声明源码/配置 |
| O03 发布与配置 | 目标身份、权限、操作 ID/状态、配置与目标版本 | 核对实际环境/入口及业务，未知先对账，不能用本机代替 |
| O04 运行信号 | 存活/就绪/业务探针、日志/指标/请求标识与约束 | 可以识别健康正常但核心任务失败，信号按当前候选核验 |
| O05 故障与恢复 | 用户影响、诊断事实、授权恢复方式、原因/修复及复验 | 受影响任务实际恢复，永久修复与临时恢复分别登记 |
| O06 回退与数据 | 上一有效产物、配置、备份时间点/一致性、迁移兼容与损失 | 实际恢复后核验数据/核心行为，不以代码回退替代数据恢复 |
| O07 环境演进 | 服务/资源/依赖归属与约束、实际问题和消费者、变更待办 | 变化后重新核验目标、健康及相关业务/性能，不虚构容量结论 |
| O08 退役与交接 | 下游/调度/路由/数据保留、替代入口、自有资源清理与运行交接 | 下游可用、数据安排与旧入口/资源状态分别核验 |

方法按[环境与启动](../skills/dev-operations/references/environment-and-startup.md)、[产物与发布](../skills/dev-operations/references/artifacts-and-release.md)、[观测与故障](../skills/dev-operations/references/observation-and-incidents.md)、[恢复与迁移](../skills/dev-operations/references/recovery-and-migrations.md)、[运行资产与演进](../skills/dev-operations/references/project-assets-and-evolution.md)读取。技术沿用 React/Vite、Next.js、Astro 与既有项目基线，不新增厂商或其他通用技术选型。

## 项目沉淀与当前验证

已有 README/runbook、工程与 CI 优先，无规范时采用 `docs/dev-flow/operations/` 运行索引、交付/发布、故障/恢复与必要 runbook；三个随包模板支持按事实维护。长期资料在项目 Git，真实配置密钥通过项目管理入口，本地进程/缓存位于忽略目录。旧部署记录带核验时间，新任务查询相关实际状态；依赖、配置或产物变化使受影响证据待复验。

首版定义 O01–O08，实际证据见[验证记录](../evals/dev-operations/report.md)：主 Agent 使用隔离 HTTP/文件数据样本验证源码包解包启动、版本、核心 API、跨进程数据、故障识别与应用回退/备份恢复。方法执行不代表独立角色行为、原生发现/派发、真实项目、新机器、React/Next/Astro 构建或生产发布，未执行项分别登记。

六职责首版方法现已具备。接下来选择一个真实任务验证设计确认、AI 计划复核、研发测试循环、实际交付及下一任务资产复用；运行内核、平台适配和 Plugin 打包依据实测需要建设。
