## 跨项目可采用的首版规则

1. **React Web 统一设计起点。** 新独立原型/客户端采用 Vite + React + TS，B 端 Ant Design/antd、C 端 Web shadcn/ui；专用视口与普通 UI 分工。已有 JS/JSX、纯 Astro 和原生工程保留有效项目约束。
2. **按实际需要选择服务形态。** 同仓全栈/SSR 可考虑 Next，独立 TS API 可考虑 Hono；CLI/MCP/Worker 与核心用例分开。数据库、队列和拆服务有具体需求才选择。
3. **模型/引擎/平台按项目决定。** rem 的自有运行核心、News 的 AI SDK，Three.js 编辑器、Godot 玩家端，以及 Flutter 和 iOS AR 分别保留约束；共享的是契约和分层方法。
4. **运行单元有自己的工具链。** runtime、管理器/锁文件、平台 SDK、CI/构建和交付入口落入项目技术基线。新 Node 工程评估受支持 LTS，首版候选为 24 系列，不能因维护工具使用 Node 26 就要求所有项目换用它。[Node 发布状态](https://nodejs.org/en/about/previous-releases)
5. **形成可用交付证据。** Web 页面、可安装原生包、扩展/小游戏宿主包、媒体产物、CLI/MCP 命令与部署配置分别定义检查；只读清单不会将这些状态登记为通过。

原多平台约束已移出 Skill，保存为[历史草案](archive/2026-10-08-stack-profiles-v0.1.md)。当前执行遵循三类技术约定与[代码规范](../../skills/dev-architecture/references/code-standards.md)，项目可使用[技术基线模板](../../skills/dev-architecture/assets/templates/technology-baseline.md)维护自己的有效选择。共享组件继续采用源码复制/参考与 Git 来源管理。
