# 本次测试执行记录

单独保存为 `.dev/runs/<迭代ID>/acceptance/<runID>/report.md`，执行表及附件均不提交 Git。已有本地运行目录可沿用，先核对忽略规则。不将本表复制到用例文档、Progress 或可提交的 `acceptance/result.md`。

- 执行日期：〈实际日期〉。
- 用例文档：〈项目内用例文档位置；需要时补其版本〉。
- 本次测试执行范围：〈全量，或增量及选中的用例编号〉。
- 被测对象：〈实际版本/入口；有必要时简述环境和真实/模拟边界〉。

一个迭代可以有多次测试执行，每次单独保存执行表；`<迭代ID>` 标识所属迭代，`<runID>` 标识该迭代内的某次测试执行。同一次测试执行中断后继续填写原表；重新发起测试执行时使用新的 `<runID>`，不覆盖此前的执行表。

- 状态填写“通过 / 不通过 / 未执行 / 待人工验证”。无法执行在备注写原因，不能与已执行失败混淆。
- 简述实际观察；失败写清与预期的差异。复杂场景按需补步骤或命令，不要求每条展开技术拆解。
- 截图、录屏、日志、接口返回、生成文件等有就附链接；没有可写“无”。证明附件可选，按实际操作与观察判断结果；未实际执行不能标通过。
- 人工项在实际验证后填表，可在备注注明人工或反馈来源；AI不能以自己的推测代替人工结果。
- 修复后复验原路径，在备注保留原问题和本次复验结果；重试及不稳定情况如实说明。
