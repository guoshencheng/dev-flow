# 后端接口、业务链与数据验证

先读取项目权威 API/schema、有效 RULE/ARC、鉴权与数据归属、实际环境和已有测试入口。API 测试默认可复用 Playwright `APIRequestContext`，非 Web 项目沿用其合适的请求/集成工具；不为统一工具更换服务框架。[Playwright API 方法](https://playwright.dev/docs/api-testing)

## 多层检查与边界

领域/用例单元检查有利于边界和不变量，handler/适配集成检查验证协议、映射与存储，真实启动服务的 HTTP/业务链验证贯穿授权与读写。纯 handler 调用不能声称真实 HTTP、Cookie、代理、CORS 或部署链已通过；schema 通过也不能证明业务结果正确。

| 维度 | 按项目契约验证 |
| --- | --- |
| 输入与输出 | 正常值、实际边界、缺失/无效字段、类型/格式、分页/排序/过滤、状态码和业务错误语义 |
| 身份与访问 | 未登录、无权限、对象/租户归属，服务端拒绝及拒绝后无业务副作用；预期沿用有效契约 |
| 状态与不变量 | 合法转换、非法前置状态、金额/计数/配额等业务约束、数据所有权和事务语义 |
| 写入与读回 | 响应内容与业务对象、从真实查询路径读回、必要存储观察，适用时重启/新进程或迁移验证 |
| 重复与并发 | 重复请求、幂等键、并发冲突/版本、重试与部分失败；依据项目语义而非强加统一策略 |
| 兼容与依赖 | 有效消费方/版本、外部错误/超时/结果未知、必要事件/异步完成和恢复 |

用例断言具体字段、业务状态、拥有者与副作用。HTTP 2xx、`response.ok()` 或返回 `success:true` 不能独自作为完成判据；错误用例也检查对象未被创建/改变。期望错误碼来自原契约，不为了匹配实现把 403 改为成功。

最终 API 业务链使用本次需要证明的真实存储/迁移与适配；临时内存/假数据库可以用于局部测试，报告不能升级为数据库持久化/约束验证。通过读取源码/日志推断出的结果与实际查询观察分别登记。

## 身份、数据与故障

测试身份来源于明确测试环境或项目 fixture，按实际授权准备隔离用户/租户/对象。每个用例或 worker 使用独立数据标识，创建/恢复与清理有对应 fixture；失败后仍保留证据并执行适用清理，不依赖上一测试顺序。并发用例须实际构造并发，重试不得隐式重复非幂等业务动作。

`page.request` / `context.request` 与该浏览器共享 Cookie；单独 `request.newContext()` 使用独立 Cookie，需要显式登录/认证状态。令牌和浏览器本地状态不是自然互通，按项目实际认证方式接入。拒绝用例显式使用无身份/错误身份上下文，防止继承管理员登录。[API 上下文](https://playwright.dev/docs/api-testing#context-request-vs-global-request)、[认证与隔离](https://playwright.dev/docs/auth)

故障注入写明切点、触发条件、依赖模式和恢复方式，不改变被测业务规则。被替代依赖的真实集成仍需单独验证；超时/取消等待后按真实状态查询和恢复契约验收，不能断言服务端动作已撤销。生产/外部真实写入遵循当前任务与宿主授权。
