# 验收执行与复验

接收用例文档、可运行候选、环境和必要身份/数据，优先复用现有 runner 或实际操作入口，明确真实链路与 Mock 范围。

用例文档提交 Git；每次测试执行单独保存本地执行表，默认 `.dev/runs/<迭代ID>/acceptance/<runID>/report.md`。先列出本次测试执行全量或增量所选编号，默认“未执行”，逐条实际操作并及时回填；中断后继续剩余项。执行表及截图、录屏、日志等附件不提交，不回写用例文档或其他可提交文档。

表格记录用例、是否通过、实际结果/备注，以及可选证明链接。状态用“通过 / 不通过 / 未执行 / 待人工验证”；无法执行写清原因。证明有就附，没有可写“无”，不因缺少截图或附件单独判未通过；没有实际执行或没有判断所需的实际观察时，不能标通过。

AI 无法完成的人工项留待人工，收到明确的实际验证反馈后填入同一次测试执行的本地表。失败及时反馈；修复后执行原场景及相关回归，在备注保留原问题和复验情况。不能用服务可访问、截图或局部成功代替用例要求的完整链路。

结束前逐编号核对本次测试执行所选用例是否都有记录，未执行、失败和待人工项如实保留。主 Agent 维护总体流程状态，执行明细及附件继续留在忽略目录。

一个迭代可以有多次测试执行，每次单独保存执行表；`<迭代ID>` 标识所属迭代，`<runID>` 标识该迭代内的某次测试执行。同一次测试执行中断后继续填写原表；重新发起测试执行时使用新的 `<runID>`，不覆盖此前的执行表。
