# 迭代入口

采用到 `docs/dev-flow/iterations/<迭代ID>/index.md`。仅填写本轮实际需要的阶段与路径；本模板不是完整阶段的强制清单，采用后删除说明。

## 目标、范围与输入

- 项目、迭代 ID、功能 ID 与任务类型：待填写。
- 用户目标、交付结果、本轮范围与非目标：待填写。
- 前序迭代、依赖、有效产品/UI/架构/测试与代码基线：链接实际来源及版本。
- 当前阶段、候选版本、维护职责：待核验；未执行不能标为通过。

## 工程执行与协作选择

- 任务开始基线、相关初始未提交内容、目标分支/任务分支与工作目录：
- 原 checkout 或 worktree 的选择及原因、运行端口/数据等共享资源负责人：
- 主 Agent/subagent 的实际安排及原因、输入版本、写入边界与集成顺序：
- 切片/修复/集成/合并前后的必需验证入口及当前证据：
- PR 或评审位置、合并方式/授权来源/实际结果、交付及 worktree 清理状态：

按实际范围裁剪，已有计划/交接记录时只关联；没有执行的委派、合并或清理标明未执行。

## 迭代结束与后续关系

采用 Skill 的文档整理与归档协议，在此合并总结；复杂时链接本目录 `summary.md`，不复制已有报告。按实际范围填写：

- 工作结束状态/日期、完成/取消/被替代原因；目标与实际完成、未实现范围：
- 输入、源码/产物/环境版本，实际验收/交付结果、证据和未执行项：
- 关键决定及采用/放弃依据、适用范围与来源：
- 长期资产更新/复用及生效范围：引用上表，注明仍有效的迭代内规格。
- 有证据的问题根因、可复用经验与边界；尚未证实的判断：
- 遗留项、影响、后续任务/tracker、主责和状态；无承接的事项：
- 整理状态（待整理/待决/已归档）、归档日期/整理者、核对的来源版本与链接检查结果：

结束与归档分开记录；长期资产同步、遗留承接和必要来源核验未完成时不标已归档。默认保留原目录，项目索引转入历史列表；仍有效规格保留现行入口。被替换完整候选按需放 `archive/<阶段>/<资产ID>/`，普通修订由 Git 追溯。后续独立增强新建迭代；更正历史增加说明，不覆盖当时结论。
