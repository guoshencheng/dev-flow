# 当前项目文档入口

采用说明：将本模板裁剪到项目现有文档入口或 `docs/dev-flow/index.md`。填写实际项目与已存在资料，源路径使用项目相对 Markdown 链接；不创建所有类别的空文件。尚无文档标明缺口，不把下表默认分类当作已有资产。采用后删除本说明。

## 项目与迭代入口

- 项目名称、仓库/工程入口：待填写实际信息。
- 当前任务/迭代 ID、入口与受影响单元：按实际填写；长期文档或独立事件维护无需创建迭代；多仓库注明资料归属。
- 当前功能/任务 ID 与已确认基线：待填写，未确认明确标为候选。

每个已定位入口链接本项目的权威资料；各阶段本轮产物以迭代索引为入口，此表维护跨迭代当前有效来源。功能/规则的现行来源可以指向已完成迭代，不复制第二份规格。未建、不适用、候选、现行、待复验和历史分别说明；已 Review 和人工确认各保留来源/版本。相关产品 RULE/AC、原型 PT、视觉页面、ARC、技术产出 OUT/链路、TC 和证据按实际 ID 关联。

索引只登记项目资产、当前阶段与交接/结果入口，不逐轮列出私有 runs。单次执行与 Review 记录保存在忽略的本机目录；中断或跨机器接手使用正式交接，不能以本机日志作为唯一恢复入口。原始证据留在 .dev，正式交接仅登记必须转交材料的取得方式、用途和版本。

## 阅读与预览

记录采用的文档工具位置、文档根目录与实际启动方法；采用共享阅读器时 `--project` 指向本项目，`--roots` 指向上表实际文档目录。各角色共用此入口，独立原型关联自身服务及场景。

长期记录保存源路径和启动方式。本机 origin/端口从 `.dev/previews/documents.json` 取得，提供给用户前用 URL 工具核验对应项目与文件；不将临时端口作为永久地址。预览变更反馈写回上表对应权威资料。

## 历史与缺口

关联必要归档及其现行替代入口，普通修订由 Git 保留。列出本次相关缺失资产、待决事项、失效证据和后续维护责任，避免将历史或未实施目标当成当前事实。

文档整理时记录范围/日期、整理者、来源版本、长期资产变化、归档迭代及总结入口、未归档原因和遗留承接。复杂的跨迭代整理可链接 `records/reviews/<记录ID>.md`，不另建平行账本。归档迭代中仍有效的规格保留在上面的现行来源表。定时检查只有在已授权创建后记录其真实调度入口、范围和允许动作；无调度则不填写。
