# 研发协作入口

采用[总纲](references/constitution.md)组织当前任务，首次使用读取总纲。以用户要求的实际结果确定完成条件，复用现有决定和工程入口；设计文档与实现计划使用中文。

## 确定路线并推进

从请求与项目事实确定目标、当前阶段、交付范围、对应验收条件和相关有效资产。局部修复直接采用针对性验证；完整用户行为提供必要设计、可运行切片和实际交付；接口、数据、权限、兼容与故障按相关风险补充检查。

只启用本次需要且实际可用的职责。派发时提供输入及版本、可写范围、成果位置、验收与交接要求；同一共享文件或接口明确一个写入者。模型与推理强度由调用方按用户最新要求和宿主配置选择；职责配置默认省略这些字段，采用宿主的派发默认或父会话设置。当前宿主与用户的委派约束优先。

先按阶段、对象和要回答的问题确定职责：设计文档/原型的流程、规则、交互与恢复走查由产品主责，布局/呈现/响应由视觉主责；测试早期参与场景覆盖与可测性，验收执行面向可运行实现及交付候选。能启动、能点击、使用 Mock 或 Playwright 都不自动把设计原型路由给测试；用户明确指定测试检查原型时，按指定范围执行并登记原型证据。

职责尚未安装或不能被当前工具选择时，由主 Agent 明确承担相应工作，记录工具与验收缺口。配置文件和角色自报结果需要核验；专门角色与独立复核只有实际执行后才能登记。

产品与交互工作读取同包[专业 Skill](../dev-product/SKILL.md)，按其指导复用项目资产、形成流程、交互状态和验收目标。原生职责名为 `dev_product`，宿主能实际选择时使用；否则明确由当前执行者读取该 Skill 承担工作。产品和视觉的专业职责分别记录，小任务允许同一执行者兼任。

视觉与界面工作读取同包[视觉 Skill](../dev-visual/SKILL.md)，定义布局、Tokens、组件/响应状态并检查实际渲染；原生职责名为 `dev_visual`，实际派发条件同上。按任务引用同一套共享组件、原型和文档工具，专业资产分别维护。

架构设计、相关代码评审与研发复盘读取同包[架构 Skill](../dev-architecture/SKILL.md)，遵守整洁架构，细化业务域、模块职责、接口与数据契约；原生职责名为 `dev_architecture`，实际派发条件同上。实质研发完成后定向复核代码业务，更新当前架构/目录模块地图和合理性判断，给出有证据的改进建议；局部任务按影响裁剪。

架构后的技术实现方案、研发实施、诊断修复、兼容变更与集成交付读取同包[研发 Skill](../dev-engineering/SKILL.md)。先列明页面/入口、功能和端到端技术产出，产品符合性及相关 UI/架构 AI Review 通过后交测试；用例 Review/人工确认后产出实施计划并 AI 复核，自主实现可运行切片。原生职责名为 `dev_engineering`，实际派发条件同上。按原始契约处理测试反馈，自测原问题与相关回归后交回待验候选，维护方案/工程/代码/诊断和启动资产。

测试用例/策略设计、可运行实现的接口/界面验证、研发测试持续对焦和交付验收读取同包[测试验收 Skill](../dev-acceptance/SKILL.md)，按实际对象选择局部行为、真实接口/数据、前后端 E2E 与交付方案。原生职责名为 `dev_acceptance`，实际派发条件同上。用例关联 RULE/AC/ARC，核心链路核验界面操作、请求响应、服务端结果与刷新/恢复；Mock 覆盖单独记录，修复后实际复验原问题与回归。

环境/启动、产物/发布、运行诊断与恢复、依赖演进或退役读取同包[运维与交付 Skill](../dev-operations/SKILL.md)。原生职责名为 `dev_operations`，实际派发条件同上。核验实际候选/环境与核心任务，存活/就绪/业务及应用回退/数据恢复分别取证，维护项目 runbook；测试仍主责验收，原型服务保留设计阶段。

## 三个优先成果

- UI 与交互：明确用户流程、相关状态、异常恢复和视觉呈现，分别用实际操作与实际渲染验证。
- 研发测试循环：尽早形成可运行切片，反馈带版本和复现证据，修复后复验原问题与相关回归，直到本次必需条件通过。
- 实际交付：根据约定提供可启动源码、安装产物或实际部署，验证核心用户任务，报告真实入口、环境与未覆盖项。

完整功能按[执行协议](references/execution-contract.md)确认产品/交互/UI 和重要架构设计，再由研发输出端到端技术方案，经产品符合性及相关 UI/架构 AI Review；测试综合原产品文档与方案设计用例，经 AI Review 后交用户确认验收预期与覆盖；研发再产出实施计划并实际 AI 复核，通过后自主编码与持续修复。技术方案/实施计划默认没有额外人工审批。已有有效确认直接复用；改变确认基线或授权时，只提出受影响部分的决定。端到端交付与架构约束都需实际证据。

已有授权范围内持续推进；需要用户决定的关键问题具体提出，同时完成其他独立工作。新增职责或通用工具的长期建设遵守本次范围。

涉及 UI 工程或组件复用时读取[技术与共享组件约定](references/ui-stack-and-components.md)：新建 Web 原型默认 Vite + React，B 端采用 Ant Design 规范和 antd，C 端 Web 优先 shadcn/ui；其他 C 端先做网上参考研究。按需复制或参考同包 React 组件源码，在项目直接维护，记录来源哈希、差异与验证。

## 项目知识与交接

先明确本次业务项目的名称与根路径，从项目索引定位产品、交互原型、设计/UI、技术及相关验收/交付文档，登记各自实际权威位置、状态与版本；缺失或不适用明确记录。开始读取相关项目资产并核验有效性；过程中更新发生变化的权威位置；交付时报告复用、更新与能力缺口。新项目没有现行规范时使用 `docs/dev-flow/` 保存长期资产，`.dev-flow/` 仅承载本地运行状态。通用候选经过适用范围和行为验证后再进入本仓库。

项目文档与原型按共同[目录和归档协议](references/design-document-contract.md)维护分类入口，关联现行规格、规则和证据。向用户讨论、确认或交付项目设计文档时按[Vite 文档预览](references/document-preview.md)复用或启动该业务项目的阅读入口，提供项目索引与本次相关文档/原型的真实地址。Skill 提供方法与工具，维护 Skill 本身不默认进入项目文档预览流程。

交接包含结论与完成范围、成果位置与版本、实际证据与未执行项、问题和依赖、资产变化与能力缺口。完成判断针对当前候选成果，区分实现、验收、可运行交付与部署。

## 按需深入

- 细化某职责的能力或项目沉淀时，读取[能力目录](references/2026-10-07-role-capabilities-and-project-assets.md)中的对应职责。
- 建设或调整原生职责 Agent 时，读取[Codex 配置说明](references/codex-agent-setup.md)。
- 安装、更新或诊断 Plugin 接入时，读取同包[初始化 Skill](../dev-flow-setup/SKILL.md)和[安装指南](../../docs/plugin.md)。
- 建设整个体系、运行内核或 Plugin 时，读取[完整路线](references/2026-10-07-development-harness-plan.md)中的相关部分。

当前版本提供共同协议、流程入口和六职责专业指导，以及共享文档预览。工具核验、专业行为、原生派发与真实项目状态见各职责说明和[配置说明](references/codex-agent-setup.md)；随后按真实任务验证完整循环与项目资产复用。
