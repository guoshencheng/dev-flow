# 研发协作入口

首次使用读取[总纲](references/constitution.md)。从用户目标和当前项目事实确定交付范围，复用有效决定；设计文档与实现计划使用中文。共同依赖、确认和完成规则以[执行协议](references/execution-contract.md)为准。

## 一条指令收尾迭代

用户说“开始收尾”“收尾当前迭代”或“总结并归档本轮”时，直接进入[迭代收尾](references/document-archive.md#一条指令收尾当前迭代)，默认包含[代码收尾](references/git-and-worktree.md#代码收尾)。例如：

```text
开始收尾
```

从当前项目和已有索引定位本轮及候选，整理相关代码、检查完整变更 Review 与当前候选的必要测试/构建，完成已授权范围内的阻断问题修复与复验；同步有效资产、迭代总结、遗留承接和项目入口，再核对完整待提交内容并按项目约定保存。无其他约定时，通过检查的本轮相关代码、测试与文档形成有意义的本地提交，保留无关修改；推送、PR、合并与发布按已有授权推进。满足条件后逻辑归档，交接提交/分支、验证与交付状态、文档入口和未完成项。同一轮正常交付结束时包含这项收尾，重复调用只处理新增变化，不生成空提交。

明确只整理文档或历史归档时裁剪代码动作，不重新走功能实施流程，也不为已授权的常规资产更新新增确认。项目/迭代或变更归属无法确定、关键事实冲突时，只询问必要信息并继续独立工作；缺少必需验收/交付证据时完成可做的沉淀并保存待验候选，保留真实未完成状态。

## 每次按阶段推进

1. **建立/恢复全局进度**：明确最终目标和业务项目，从现行入口恢复有效基线；按[进度管理](references/progress-management.md)选择真实可用 Todo 或唯一 Progress/索引。列出完整阶段和后续未开始工作，明确当前目标、动作、下一步、依赖、完成条件与未完成项；阶段完成不等于整体完成。
2. **选择路径**：按[任务路由](references/task-routing.md)逐范围判断，先看行为/交互/契约变化及未决，再看规模与可逆性。快速路径须引用具体有效基线；混合请求分别裁剪并写依据，小改动不能替新增行为裁掉前置。
3. **核对前置与实施授权**：核验受影响业务预期/重要取舍、统一研发设计 Review 和计划复核；完整正式 TC 在功能实现后维护，不是实施前置。首次正式实现前展示路径依据、具体范围、预期结果、验证和交付，取得用户明确实施同意；快速路径也不得省略。标准路径可明确合并到设计确认，已有同一范围实施授权直接复用，不重复询问；需求表达或局部答复不自动授权实施。等待时继续研究、诊断和方案准备，受影响正式实现保持待开始。详见[实施授权](references/execution-contract.md#首次实施的人工同意)。
4. **执行当前工作**：读取下表中的相关专业 Skill，完成真实操作。产品/UI 候选先取得基于当前代码的技术成本反馈；研发统一主笔架构与实现设计，独立 Review/计划/架构收尾由主设计引用。连续实现、集成与自测，完整候选后维护正式验收用例并独立 Review，再执行验收及交付核验，问题关联修复与定向复评/复验。用户提出行为、契约或交付变化时先走[变更闸门](references/execution-contract.md#实施中的需求变更闸门)。
5. **更新并继续**：更新现有索引的有效状态和成果引用；按必需 TC/检查汇总结果，再决定下一步。必需结果未执行、受阻或失效时保持未完成，不以测试数量或阶段成果报告任务完成。

持续实现、多阶段和跨会话任务保留完整的持久进度；需要机器核验候选、版本和证据依赖时，在唯一 Progress/现有索引按需采用[状态格式与核验器](references/stage-state.md)，其他入口只引用或投影。进入受影响实现、基线变化后和结束前运行核验；已有项目工具能同等检查时复用。局部一次性任务可用同等简短记录，不为工具另建台账。工具仅核验已声明记录，不证明真实执行、不判断设计质量、不拦截操作；主 Agent 仍对前置与完成判断负责。

## 按对象读取职责

| 工作对象 | 专业入口 |
| --- | --- |
| 用户任务、流程、规则、原型与可用性 | [产品](../dev-product/SKILL.md) |
| UI、Tokens、组件、响应与实际呈现 | [视觉](../dev-visual/SKILL.md) |
| 系统/模块、契约、技术基线与代码复盘 | [架构](../dev-architecture/SKILL.md) |
| 技术方案、计划、实现、诊断与自测 | [研发](../dev-engineering/SKILL.md) |
| 测试策略/用例、实现验收、反馈与复验 | [测试验收](../dev-acceptance/SKILL.md) |
| 环境/启动、产物/发布、运行与恢复 | [运维交付](../dev-operations/SKILL.md) |
| 会话进度、阻塞、完成与授权摘要通知 | [会话监控](../codex-session-monitor/SKILL.md) |

先按阶段、对象和问题确定职责。产品/视觉主责设计文档与原型走查，测试早期提供覆盖/可测性意见，正式验收面向可运行实现及交付候选；能点击、Mock 或自动化工具不改变对象。技术方案和计划默认没有额外人工审批。

标准功能、跨职责任务中的专业设计、调查、研发、Review、验收和收尾默认用实际可用且允许的 Harness subagent，主 Agent 负责范围、进度、依赖与集成。任务包给必要原始要求、权威文件/版本、写入边界和成果/检查要求，不默认继承全部聊天；作者与独立评审分离，共享文件明确写入者。无法派发时记录真实降级，大任务不委派说明原因。模型/推理强度遵循用户和宿主本次设置。自查、委派评审和独立复核如实记录；派发或等待超时不构成结束，生命周期按[执行协议](references/execution-contract.md#实施与正式验收的边界)处理。

## 工程与项目资产

开始写入前按[分支/worktree 建议](references/git-and-worktree.md)核对基线、现有修改、目标分支和工作位置；执行者选择遵守[subagent 使用建议](references/subagent-guidance.md)及当前委派权限。实现/修复按研发的[测试保护](../dev-engineering/references/test-first-and-regression.md)和[诊断方法](../dev-engineering/references/diagnosis-and-feedback.md)进行，实际实现 Review 检查[完整变更](../dev-architecture/references/retrospective-and-evolution.md)，按[意见闭环](../dev-engineering/references/review-feedback.md)处理。

项目知识保存在所属项目。项目文档（含产品、设计、架构、研发、验收与交付）及独立设计原型统一在 `docs/dev-flow/` 下维护；持续复用的原型工程放在 `docs/dev-flow/visual/prototype/`。正式应用、测试和工具源码保留实际工程位置。迭代索引关联范围、版本、Review、确认与结果，阶段产物按 `docs/dev-flow/iterations/<迭代ID>/` 维护；长期资产通过项目入口引用。建文档、委派写入和提交采用[文档协议](references/design-document-contract.md#agent-文档控制)，正式跨职责 Review 和技术收尾独立保存重要结论及问题闭环，原始运行/逐次重试过程留在忽略的本机目录。

UI 按[视觉资产协议](../dev-visual/references/project-assets.md)持续维护独立规范、各端页面/组件规格和源码，总览组合展示。迭代只引用现行资产、记录版本与增量；无变化不创建 UI 文件，少量变化合并到索引，复杂时按需拆变更记录，不因阶段产物按迭代组织而重写完整 UI。

讨论/确认/交付项目设计时按[文档预览](references/document-preview.md)复用或启动业务项目的阅读入口，提供真实文档/原型地址；维护 Skill 本身不默认进入项目预览。结束时按[迭代收尾](references/document-archive.md#一条指令收尾当前迭代)同步项目入口及相关长期资产，交接给出范围、版本、成果入口、实际证据、未执行项和能力缺口；区分实现、自测、验收、可运行交付及部署。

## 按需深入

- 全部阶段、当前目标、下一步和恢复：[进度管理](references/progress-management.md)、[Progress 模板](assets/templates/progress.md)。
- 职责边界、实际执行与可用性：[能力目录](references/role-capabilities.md)、[职责执行说明](references/codex-agent-configuration.md)。
- 资产复用、整理与归档：[持续沉淀](references/project-asset-maintenance.md)、[文档归档](references/document-archive.md)。
- 安装/更新/诊断插件：[安装指南](../../docs/plugin.md)。不要求初始化 Agent。
- 会话监控/通知：[监控 Skill](../codex-session-monitor/SKILL.md)。会话范围、收件人、身份和定期调度须明确授权。

安装检查、核验器测试、专业行为、原生派发与真实项目验证分别登记，不能互相折算。
