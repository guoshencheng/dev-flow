# Codex 职责接入与可用性

用于接入、诊断或调整职责配置；普通项目任务按入口选取专业 Skill。插件安装和职责初始化使用同包[初始化 Skill](../../dev-flow-setup/SKILL.md)。从宿主列出的真实 Skill 路径定位安装包，不固定缓存版本或旧全局链接。

| 原生职责名 | 专业指导 |
| --- | --- |
| `dev_product` | [产品与交互](../../dev-product/SKILL.md) |
| `dev_visual` | [视觉与界面](../../dev-visual/SKILL.md) |
| `dev_architecture` | [架构设计与演进](../../dev-architecture/SKILL.md) |
| `dev_engineering` | [研发方案、实现与修复](../../dev-engineering/SKILL.md) |
| `dev_acceptance` | [测试与验收](../../dev-acceptance/SKILL.md) |
| `dev_operations` | [运维与交付](../../dev-operations/SKILL.md) |

职责配置保存身份、边界和执行所需的最小要求；专业 Skill 保存方法，项目保存事实与资产，总纲保存共同协作协议。配置引用当前安装包内的专业指导，不把项目事实或建设历史复制进职责指令。

职责文件默认省略模型与推理强度。实际选择遵循用户当前约束和宿主支持的配置/派发入口，不用某次本机验证的模型作为永久默认。发现设置不兼容时报告具体能力缺口。

分别核验配置是否可解析、宿主是否发现职责、当前工具是否可以派发、实际任务是否完成和项目资产是否可复用。安装检查通过只能证明对应接入检查；只有发生真实派发与行为验证才登记相应结果。

派发提供当前目标、输入及版本、可写范围、产物位置、验收条件和交接要求。角色不可选择时，当前执行者读取专业 Skill 承担相应工作并说明缺口；不虚构角色执行或独立复核。
