# UI 技术栈与共享组件约定

版本：0.1。更新日期：2026-10-08。来源：用户明确指定的技术与设计方向。此约定供产品、视觉、研发和测试共同使用；模型与推理强度仍由任务调用方和宿主选择。

## 技术与设计基准

| 对象 | 本体系要求 |
| --- | --- |
| 新建 Web 原型、设计稿工程 | 默认 Vite + React + TypeScript，实际启动开发服务并在浏览器查看；页面按任务生成 |
| B 端 | 使用 Ant Design 的设计规范；尽可能直接使用 antd 组件，再通过组件组合、公开 API 和主题 Tokens 扩展 |
| C 端 Web | 优先基于 shadcn/ui，复用其源码组件与主题约定，按产品定位调整呈现 |
| 其他 C 端应用 | 实施前先浏览网上的同类产品、相邻任务和目标平台规范，记录参考与适用判断，再开展设计与研发；React 在平台适用时优先 |

已有项目继续复用有效工程入口和开发服务，新建独立原型采用上述默认。React 是优先选择；本轮局部工作不自动扩展为整个项目的技术栈迁移。用户本次指定或现行工程与默认冲突时说明具体差异、可行方案与采用理由，保留用户最新要求的优先级。

B 端从 antd 的 Form、Table、Modal、Drawer、Select、Button、反馈和布局组件中选择合适模式。优先直接导入，不为改名字而包装全部基础控件。扩展用于补充有复用价值的组合、状态或领域展示；先用 ConfigProvider、主题 Token、公开插槽和属性，避免依赖内部 DOM 或覆盖全局样式。[Ant Design 与 Vite](https://ant.design/docs/react/use-with-vite/)、[主题定制](https://ant.design/docs/react/customize-theme/)

C 端 Web 的 shadcn/ui 组件源码属于项目可维护资产：记录原始来源、采用版本、修改原因与实际依赖，调整时保留键盘、焦点、禁用与可访问名称等行为。组件基底、布局、主题与业务规则分别管理。[shadcn/ui 的 Vite 接入](https://ui.shadcn.com/docs/installation/vite)、[Monorepo 方式](https://ui.shadcn.com/docs/monorepo)

其他 C 端应用的研究遵循[参考研究协议](../../dev-product/references/reference-research-and-ideation.md)。外部参考与当前项目有关：写明任务、平台、入口/操作/反馈、可借鉴机制和不适用条件。已有项目参考可以复用，但核验其来源与当前有效性；无法浏览时如实提交研究缺口，不能将未经研究的候选标为参考已完成。

## React 组件如何持续沉淀

共享源码与 Skill 一起维护在本 Git 仓库的[React 工作区](../../dev-product/assets/react-workspace/README.md)。分为 `@dev-flow/ui-antd` 与 `@dev-flow/ui-web`；两个应用示例分别运行，保持设计体系和样式边界。

直接使用基础库 → 在项目中形成必要组合 → 核验适用条件、代表场景与边界 → 提取共享组件 → 在下一项目核验复用。项目特有接口、权限、业务文案和流程政策由调用方注入，不进入通用组件的隐式行为。

每个共享组件保留：名称与用途、Props/状态契约、适用与不适用条件、基础库和来源、真实采用项目或隔离案例、运行示例、验证方式、版本与变化影响。组件清单区分“隔离示例已验证”和“实际项目已复用”，不得把初始化组件库写成已经成熟。

同一底层能力已有 antd/shadcn 组件时直接复用；自建前说明具体缺口。复用需要额外业务状态时优先组合或受控属性，保留基础组件行为。破坏兼容的变更记录迁移方法，影响项目重新核验。产品维护语义和场景，视觉维护呈现与 Tokens，研发维护实现与依赖，测试维护实际检查证据；当前尚无专门职责时由执行者明确承担。

## Git 与共享方式

源码、组件清单、来源、示例和依赖锁文件进入 Git。每次采用记录组件包版本与仓库提交；`node_modules`、构建目录和打包文件不提交。项目可从锁定版本打包安装，或在自己的组件目录中复制源码并登记来源；持续开发工作区可以使用源码链接，正式采用固定版本。

当前仓库没有远程地址和已发布包；本机通过全局 Skill 链接发现源码，通过 `npm pack` 验证包共享。团队协作需要设置用户指定的 Git 远程地址，再按提交或版本获取相同源码。远程仓库建立、推送和包发布按实际目标执行，记录成功结果后才能声称已经共享到其他机器。

具体启动、打包和接入见[工作区说明](../../dev-product/assets/react-workspace/README.md)。后续需求出现时再引入 Storybook、shadcn Registry 或包仓库；当前维持可运行示例、类型与构建检查，以及跨工程安装验证。
