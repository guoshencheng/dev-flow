# 数据、运行输出与证据的提交边界

适用于项目 fixture、运行报告、证据、历史迁移和提交前检查。按用途判断，不按 `data/`、`runs/` 或文件扩展名判断；`runs/<runID>/report.md` 是持久结论入口，不是全量运行目录。

| 内容 | 默认位置与提交规则 |
| --- | --- |
| 稳定测试输入、人工确认的独立预期/golden | 实际 tests/fixtures 等工程位置；可重复、来源明确且允许保存的样例纳入 Git。golden 不从待验实现输出自动更新 |
| 样本说明 | 文档中记录输入入口、来源、适用范围、独立预期与准备方法；不持续追加执行历史，不复制实际数据集 |
| 可复用准备、校验、复跑脚本 | 实际 tests/tools/scripts 或实验工程；纳入 Git，不能仅放临时目录供长期报告引用 |
| 人工整理的运行/验收结论 | 迭代对应 runs 下的报告或已有记录；纳入 Git，关联候选版本、环境、命令、结果、限制与必要证据 |
| 精选原始证据 | 持久 evidence 或项目已有资产存储；按一次结论选择必要截图、机器摘要、manifest、诊断片段，不复制整个工作目录 |
| 每轮生成输出 | 忽略的 `.dev-flow/`、`.tmp/`、`.runtime/` 或项目约定输出目录；包括全量日志、raw 帧、导出媒体、浏览器 profile、临时数据库和隔离项目副本 |
| 本机/敏感数据 | 凭据、认证状态、真实个人轨迹/媒体、运行数据库沿用安全保管入口；不随证据提交，样例优先合成或经授权脱敏 |

生成的 JSON 报告不是稳定输入。需要作为结论依据时，由主责选择并保存不可变证据快照，绑定 run/候选版本；后续运行写忽略目录，不覆盖已留存快照。资源许可证、依赖锁文件、固定输入的 provenance 可以是源码资产，不能一概忽略 JSON 或整个 fixtures 目录。

## 运行后与提交前

1. 运行器默认将输出写忽略目录，并支持显式指定隔离输出根。输入目录与输出目录分离，配套命令使用同一个 run 根；不要默认向 docs 或 canonical fixture 写输出。
2. 报告记录输入、候选/提交、环境、实际命令、结果及未覆盖项；可追溯身份优先采用 Git 提交加相关未提交差异，不为每次改字保存全量源码清单。
3. 选择直接支持结论的必要证据持久保存。报告链接可访问路径及版本/哈希；哈希或临时绝对路径本身不能替代证据。已清理/无法取得的历史证据明确缺口，不补造通过结论。
4. 用 `git status`、`git diff --check`、未跟踪文件清单与 `git check-ignore` 检查待提交范围；关注生成报告、媒体、数据库、缓存与认证状态。`.gitignore` 不影响已经跟踪的文件，需要移出跟踪时核对原用途并保留必要证据，不直接删除未知数据。
5. 历史整理先保全必要原始材料和承接关系，再按[归档协议](document-archive.md)维护索引。普通修订/路径迁移优先用 Git，不默认复制整套目录。尚未进入 Git 的独有历史可以保存一次快照，注明原因；避免以后每次整理再复制。

大 trace/视频按项目已有 Git LFS/制品存储规则保存，报告关联可访问位置与保留约定；没有存储入口时如实记录限制，不强制安装新服务或设统一文件大小/保留天数。归档不自动授权删除证据。
