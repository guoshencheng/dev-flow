# 迭代收尾的流程门槛

用户说“开始收尾”“收尾当前迭代”或“总结并归档本轮”时，从本次项目、范围和已有进度恢复当前迭代。正常交付也包含收尾；重复调用只处理新变化。用户明确只整理文档或历史时裁剪代码动作，不重新进入功能设计/实施。具体文件整理与逻辑归档使用[文档管理](../../document-management/SKILL.md)，基线、提交、工作区与 PR 等操作使用[Git 工作流](../../git-workflow/SKILL.md)。

## 核对结束条件

主 Agent 先核对最终目标和范围、当前候选、相关未提交变更、实现 Review、必需测试/构建、正式验收、实际交付和证据有效性。产品/视觉、架构、研发、测试及运维只对受影响对象给出专业结论；架构依据最终源码与实际验收/交付独立完成技术收尾。阻断项在已有授权范围内修复并复验，必需结果缺失则记录未完成及下一步，不能靠归档关闭。

核对项目长期资产是否与已生效的规则、设计、源码、用例和运行事实一致。专业职责裁定内容是否当前有效，文档管理只负责组织、引用、状态和保存。未实施候选或未证实经验不能写成现状；无变化可注明复用。总结应交代实际成果和版本、关键决定来源、验证及未执行范围、交付状态、资产变化、遗留责任和下一入口，证据仍引用原记录。

## 保存与归档的依赖

相关代码、测试与文档在约定检查后按已有授权保存；Git Skill 负责具体差异、提交与资源操作。推送、合并、发布等继续按各自授权执行。迭代完成、取消或被替代须有实际原因和结果来源；仍在实施、待验收或结束事实冲突时保留活动/待整理状态。归档前还须确认有效资产可达、遗留有承接、必要证据可访问。归档是文档状态与入口组织，不改变仍有效规格或历史验收结论，也不能代表整体交付完成。

本轮之外的工程变更、外部发布、消息发送、定时调度和资料删除不能从“开始收尾”推定授权。最终向用户提供完成说明，区分源码保存、Review、自测、正式验收、可运行交付与部署，附本轮 Progress 入口；缺口逐项保留。若实际存在后续 Agent 接续，另按工作交接规则记录交出方、接收方、上下文、责任及待办；完成说明不能替代该交接。文件位置、索引、预览、总结写法和链接迁移参照[文档管理](../../document-management/SKILL.md)。
