# subagent 使用与流程运行建议

本指南补充[任务路由](task-routing.md)及[职责执行说明](codex-agent-configuration.md)。六个专业职责是方法分工，不要求同时启动六个 Agent。主 Agent 持续负责范围、确认基线、依赖、集成、证据与最终交付；subagent 的使用必须符合用户当前要求、适用项目指引与宿主实际委派能力，建议本身不扩大委派权限。

## 是否委派

| 当前情况 | 默认建议与原因 |
| --- | --- |
| 清楚的局部 bugfix、文档改动、单链路顺序工作 | 主 Agent 读取所需 Skills 完成，减少上下文与交接开销 |
| 关键根因未知，存在可分别调查的边界 | 获准时委派有明确问题的只读调查，主 Agent 综合证据后确定修复，不让多个执行者盲改同一根因 |
| 重要方案/用例/计划或最终实际变更需减少自查偏差 | 获准时优先一个独立评审上下文，提供原要求与基线；评审任务结束后按需复用或关闭，不需全程常驻 |
| 正常需求含多个有明确契约、能分别实现与验证的模块 | 契约稳定后按依赖和写入边界委派实施；主 Agent 保留集成责任，模块结果集成后重新验收 |
| 实现候选已稳定，可执行耗时验收 | 获准时由独立测试执行者复验确定版本，研发对焦修复；共享环境有负责人，运行期间候选变化后重验受影响项 |
| 同一文件/接口频繁变化，任务强依赖，输入不稳定或交接成本超过收益 | 顺序推进或由一个写入者完成，待依赖稳定再委派 |
| 宿主禁止委派、没有可用子 Agent 或用户要求单 Agent | 主 Agent 分别承担专业职责，记录 AI 自查及独立性缺口，不用角色名模拟独立 Review |

不是每个 Review 都要新增一个子 Agent。根据影响与独立性需要选择关键节点；明确要求独立评审时不能以主 Agent 自查替代并登记通过。模型与推理强度遵循当次用户/项目/宿主约束，不固定在可复用流程中。

## 按流程安排

**Bugfix** 通常由主 Agent 完成复现、诊断、简短计划/AI 复核与修复；跨模块、反复失败、权限/数据/兼容风险或验收需要独立证据时，再按需引入调查、架构评审或测试复验执行者。修复由一个明确写入者负责，其他执行者提供证据；不会因启用 subagent 而重走完整设计确认。

**正常需求** 保持产品/视觉确认、架构取舍、技术方案 Review、用例 Review/确认、计划复核、实现及交付的依赖顺序。产品与视觉或相关架构/可测性调查可以在稳定输入上协作；尚未确定的契约不能作为下游正式实现依据。实现阶段只并行互不冲突的切片；测试从第一份可运行候选开始介入。最终实际变更 Review 与验收可以由不同执行者承担，也可按规模顺序使用同一个评审者，记录其参与范围和独立性限制。

**系统变更/故障** 主 Agent 优先组织恢复和关键风险验证，按问题调用架构、运维及测试；同一发布目标、迁移或共享数据有一个操作负责人，不通过并发重复执行增加副作用。

## 派发、并发与交接

派发前给出对应专业 Skill 的实际路径、问题/目标、原始要求、有效输入版本、依赖、基线与候选、可读/可写范围、禁止改写的确认预期、工作目录/分支、成果位置、验收条件和停止/交接方式。独立评审提供完整原输入与实际差异；仅给作者摘要会削弱检查，不能默认相信作者结论。

主 Agent 根据实际槽位和可独立任务数控制并发，小规模任务先从一个执行者加一个评审/测试者开始，增加并发须有明确收益；这是容量建议，不是固定人数。职责名不等于进程数，等待人工确认时只推进不依赖该决定的调查与准备。

- 只读调查/Review 通常共用可读源码，不需要 worktree；检查候选变化，避免拿变化中的工作区作稳定证据。
- 同一 checkout 的并行修改必须按文件/目录和共享接口约定唯一写入者；不得同时切换共享分支或各自提交他人修改。需要独立切换、构建或提交时，按[Git/worktree 建议](git-and-worktree.md)使用各自任务分支与工作目录。
- worktree 不解决接口冲突与共享运行资源，主 Agent 仍要确定契约、集成顺序、端口/数据和共享操作负责人。
- 子 Agent 交接包含结果、版本、实际差异、命令/证据、问题、未覆盖及资产更新；主 Agent 检查关键事实和变更，集成后重新验证，不能只转述“完成”。

依赖或需求变化时，更新输入并通知受影响执行者；停止过期写入，保存需要保留的成果，定向重审/重验。子 Agent 受阻或失败时先判断输入、权限、环境和实现原因，必要时缩小范围或由主 Agent 接手；不通过继续增派来替代诊断，也不悄悄降低验收预期。

在迭代索引/Review/运行记录中保存执行者的实际职责、写入范围、使用或不使用 subagent 的原因、输入/候选版本、交接和集成结果。仅记录真实执行方式；独立上下文不自动保证独立证据，评审者参与过实现时说明相应限制。
