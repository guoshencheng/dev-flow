# 总体进度与跨会话恢复

每轮迭代单独维护一个 `Progress.md`，覆盖用户最终目标的完整生命周期：流程确认、当前起点、尚未开始的设计/实现/验收/交付、运行验证和收尾。主 Agent 统一维护全局阶段进展，负责依赖和整体完成判断；不按职责或会话拆成多个总体进度。某个职责、派发或会话的阶段结束不等于最终目标完成。

## 唯一状态权威

业务项目默认使用 `docs/dev-flow/iterations/<迭代ID>/Progress.md`；已有项目明确的迭代目录可沿用，但仍须是迭代内独立文件。迭代索引、设计、计划、Agent 工作交接及宿主 Todo 只链接或投影本页，不独立维护总体阶段结论；不能用索引中的几条进度或聊天更新代替独立 Progress。小迭代可精简阶段与正文，不省略这个入口。未启动 Dev Flow 的查询/解释或局部操作不要求额外建迭代；明确启动流程或从咨询转入设计/研发时，按[入口启动步骤](../SKILL.md#从目标推进到完成)创建或恢复流程文档并向用户确认。具体落位、链接和模板见[文档管理](../../document-management/SKILL.md)。

接续旧活动迭代时，将仍需恢复的有效总体状态迁到本轮 Progress，原入口改为引用；如原有结构化状态块，一并迁入且只保留一份。保留原始确认、评审与证据来源，未知标待核验，不补造历史通过。已结束迭代不追溯改写。

若采用[结构化状态](stage-state.md)，同一目标只在所选权威保留一个状态块，并按真实路径核验。核验器只能检查声明的候选、版本、确认及证据依赖的一致性，不证明 Review、实际操作或整体完成；主 Agent 仍须核对真实来源。不可用的宿主 Todo 不可假定已创建，聊天文字也不等于持久记录。

## 建立和持续更新

开始列出最终目标、范围、全部大阶段、有效前置与来源、未决事项和整体结束条件。先按[流程确认](execution-contract.md#流程开始前的用户确认)主动向用户提供本页链接和整体路径摘要，记录明确答复后进入后续阶段；未确认时当前状态写“待流程确认”。流程方案版本与日常进度更新时间分开，阶段推进不要求反复确认。

任务从中途接手时，只把有依据的前置标为完成；未知保留待核验。每阶段记录责任、依赖、完成条件、成果入口、状态和下一动作，当前区明确正在做什么、下一步进入条件、阻塞及需要用户决定的事项。无关阶段说明裁剪依据，不删除必需后续工作。

派发和回报、用户确认、阶段切换、候选/基线变化、阻塞解除、修复复验及结束前更新权威。派发只记录实际执行者、输入版本、写入边界、结果和后续依赖；执行者自报完成由主 Agent 核对。候选或环境变化时判断旧 Review、用例、验收和交付证据是否失效；失败、未执行、待复验和不适用分别记录。派发、等待、并发与共享资源的实际方法见[subagent 协调](../../subagent-coordination/SKILL.md)。

Agent 工作交接记录交出方、接收方、移交对象/版本、授权与写入边界、结果/未完成项、证据及下一动作；接收方核对输入和进入条件，主 Agent 核验后更新本页。交接未成立时保留待接续或受阻，不以派发或发送消息代替已接手。向用户报告成果称“完成说明”，不把它登记成 Agent 工作交接。

结束前逐项核对目标、当前源码/产物/环境、实施 Review、正式 TC 中全部必需检查、实际交付、技术收尾及遗留承接。单列[文档盘点与长期文档回写](../../iteration-closeout/SKILL.md)的完成条件，关联实际源资料、长期权威入口、正文变更或复用依据及未回写项；必需同步未完成不能用技术收尾或总结代替。必需条件不成立时整体保持进行中或受阻，给出下一步和所需输入。外部保存/发布和文档归档执行结果分别引用对应 Skill 的真实记录，不凭进度字段宣称完成；最终向用户提供本页入口及完成说明。
