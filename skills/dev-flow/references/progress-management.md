# 总体进度与跨会话恢复

进度覆盖用户最终目标的完整生命周期，从当前起点到所要求的实现、验收、交付、运行验证和收尾。主 Agent 负责选择一个状态权威、持续更新和总体完成判断。阶段完成不等于整体完成；尚未开始的后续阶段保留为待开始。

## 选择唯一权威

先检查宿主实际可用的任务管理能力与项目既有索引。单会话短任务可用原生 Todo；没有可用 Todo 时用简短 Progress。多阶段、跨会话或多人协作任务默认维护持久 `Progress.md`，项目索引引用它。若既有迭代索引已是权威且工具要求在其中维护结构化状态，就继续以索引为权威，Progress 仅作链接或生成视图。Todo、设计主文档、实施计划和交接摘要只引用或投影权威中的总体状态，不人工双写。文档各自的候选/有效版本、Review 和验收原始结果仍由各文档负责。

若使用 `dev-flow-state` 结构化块，将它与相关版本放在选定的一个权威文件中；核验器读取实际路径。核验器只能检查所声明记录的一致性，不能证明专业 Review、实际操作或整体完成。不要假设宿主有 Todo 更新工具；聊天文字也不等于已建立持久状态。

## 起点和持续更新

开始时列出全部大阶段、有效前置与来源、待核验事项、当前阶段和整体结束条件。起点在中途时只把有证据的前置标为完成，未知记为待核验。对每阶段记录负责人、完成条件、成果位置与状态。当前区单列当前目标、正在做的动作、下一步及进入条件、依赖/待决和需用户处理的事项。

派发与回报、确认、阶段切换、候选或基线变化、阻塞与解除、修复复验及结束前更新权威。派发记录实际执行者、输入版本、唯一写入范围、结果入口、状态与后续动作；子任务自报完成须由主 Agent 核对。候选变化时判断先前 Review/验收/交付证据是否失效，保留未执行、失败和待复验状态。能并行的任务按实际槽位与共享资源负责人推进；等待超时不使整体任务完成。

任务结束时逐项核对用户最终目标与必需结果，说明源/产物版本、Review、验收、交付、未执行项和遗留承接。若必需条件不成立，整体保持进行中或受阻。可从[Progress 模板](../assets/templates/progress.md)裁剪；短任务不必填满所有表格。
