# 总体进度与跨会话恢复

进度覆盖用户最终目标的完整生命周期：当前起点、尚未开始的设计/实现/验收/交付、运行验证和收尾。主 Agent 维护一个状态权威，负责阶段依赖和整体完成判断。某个职责、派发或会话的阶段结束不等于最终目标完成。

## 唯一状态权威

根据宿主真实能力和项目已有入口选择一个 Todo、持久 Progress 或现行迭代索引作为权威；多阶段、跨会话和多人协作任务须能跨会话恢复。其他设计、计划、索引或交接材料只引用或投影总体状态，不人工维护第二套阶段结论。具体文件落位、链接和模板见[文档管理](../../document-management/SKILL.md)；流程只规定阶段和状态含义。

若采用[结构化状态](stage-state.md)，同一目标只在所选权威保留一个状态块，并按真实路径核验。核验器只能检查声明的候选、版本、确认及证据依赖的一致性，不证明 Review、实际操作或整体完成；主 Agent 仍须核对真实来源。不可用的宿主 Todo 不可假定已创建，聊天文字也不等于持久记录。

## 建立和持续更新

开始列出最终目标、范围、全部大阶段、有效前置与来源、未决事项和整体结束条件。任务从中途接手时，只把有依据的前置标为完成；未知保留待核验。每阶段记录责任、依赖、完成条件、成果入口、状态和下一动作，当前区明确正在做什么、下一步进入条件、阻塞及需要用户决定的事项。无关阶段说明裁剪依据，不删除必需后续工作。

派发和回报、用户确认、阶段切换、候选/基线变化、阻塞解除、修复复验及结束前更新权威。派发只记录实际执行者、输入版本、写入边界、结果和后续依赖；执行者自报完成由主 Agent 核对。候选或环境变化时判断旧 Review、用例、验收和交付证据是否失效；失败、未执行、待复验和不适用分别记录。派发、等待、并发与共享资源的实际方法见[subagent 协调](../../subagent-coordination/SKILL.md)。

结束前逐项核对目标、当前源码/产物/环境、实施 Review、正式 TC 中全部必需检查、实际交付、技术收尾及遗留承接。必需条件不成立时整体保持进行中或受阻，给出下一步和所需输入。外部保存/发布和文档归档执行结果分别引用对应 Skill 的真实记录，不凭进度字段宣称完成。
