# 技术图示

以用户要理解的问题、实际项目范围和可核验依据为输入，产出 Mermaid 源码、必要的关系文字、依据与验证范围。本 Skill 可独立使用，也可由不同职责按需调用；不承担架构、产品等专业判断，不因画图自动启动完整研发流程。

1. 确定问题、图示范围及现状/目标；检查相关代码、配置、schema 或有效设计和已有图。证据不足的关系标未知，不凭示例、命名或布局推断项目事实。
2. 根据[图示操作方法](references/diagram-method.md)选图并使用 Mermaid；按问题拆分包含、源码依赖、运行通信与数据关系，图旁交代视角、方向、来源、结论及省略。服务端架构文档另按实际任务读取[架构专业要求](../../agents/references/architecture/technical-diagrams.md)，不要把完整服务端视图强加于普通局部画图任务。
3. 数据库关联按[ER 字段与约束](references/diagram-method.md#er-关系的字段与约束)明确引用和被引用的表/字段、目标键、基数、可空与唯一约束、数据库 FK 或逻辑关联；联合键逐字段映射，多对多标明中间表两侧关系，未知如实保留。Mermaid 的 `FK` 标记不能单独说明目标字段，图旁正文或关系表提供对应关系。
4. Markdown 中保留可编辑的 `mermaid` 代码块，或按约定引用唯一权威 `.mmd` 源；需要示范时参考[图示示例](assets/technical-diagrams.md)并替换为实际依据。直接答复中的图不自动写入项目文件。
5. 对照图、文字和证据逐项核对名称、关系、范围、状态及版本；数据库图还须核对每张表在所引用 schema 或有效设计中定义的字段及其约束，不能把某张表的字段套到全部表。检查语法与引用。图或相关渲染条件变化时在目标阅读环境定向观察受影响呈现，核对标签、边界、箭头、中文及阅读宽度；截图按需保留，语法或渲染通过不证明技术事实正确。无法渲染或核验时说明具体限制，不虚报通过。

专业架构判断、评审结论和项目事实由承担该工作的执行者基于实际证据负责；本 Skill 不替代相关职责、授权或专业 Review。
