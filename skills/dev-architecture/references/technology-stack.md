# 技术栈选型与项目基线

版本：0.2。更新日期：2026-10-08。来源：用户明确收敛的技术约定。本 Guide 只定义 React Web、Next.js 全栈、Astro 纯静态三类工程；其他类型暂不提供通用选型 Guide，执行时依据项目自身的有效规范。

## 已确定的技术约定

| 工程形态 | 本体系约定 |
| --- | --- |
| Web 客户端 / 独立交互原型 | 使用 React；新建独立工程采用 Vite + React + TypeScript |
| 全栈 Web | 使用 Next.js + React + TypeScript |
| 纯静态站 | 使用 Astro，采用静态输出；交互需求超出纯静态范围时，按实际目标识别工程形态 |

这里按主要用户任务与是否有服务端业务划分：React 用于交互型 Web，Astro 用于内容型静态站；React 工程也可输出静态文件，不能只按托管方式把它改归 Astro。

这些选择已经确定，Agent 直接采用，不每次列框架候选或追加选型确认。B 端 Web 采用 Ant Design 规范并优先 antd，C 端 Web 优先 shadcn/ui；自有共享组件源码复制/参考与 Git 来源管理沿用[共同 UI 约定](../../dev-visual/references/ui-stack-and-components.md)。

新工程和本次明确采用的目标遵守上表；既有工程的局部工作复用有效技术基线，需要迁移时再说明范围与兼容/交付影响。一个仓库有产品、网站、服务和原型等单元时分别登记，不能从目录名或某个依赖推断实际采用，也不把退役路径作为研发入口。

## 项目中的实际基线

读取有效项目规范与决定，核对实际入口、manifest、锁文件、runtime/工具版本、CI 和交付配置。规范与实现分别记录；有冲突时保留来源并核实当前有效链路。

包管理器与锁文件按安装单元确定。`npm run` 不等于 npm 安装；不同独立单元各有锁文件可以合理。同一单元的声明、文档与 CI 冲突需定向处理，调查阶段不执行升级或清理锁文件。工具运行时和项目运行版本分别记录，实际采用兼容版本并锁定依赖。

代码格式、静态规则和类型检查按[代码规范](code-standards.md)落实到项目配置与命令。遵守[整洁架构](clean-architecture.md)的业务/适配依赖方向；Next.js 还需在实际模块地图中标清 Server/Client 边界，纯静态 Astro 标清内容生成与浏览器交互边界。存储、鉴权和外部依赖由实际业务决定，本 Guide 不预设数据库、队列或服务拆分。

## 技术基线与持续建设

沿用已有权威位置；无规范时在 `docs/dev-flow/architecture/stack.md` 使用[技术基线模板](../assets/templates/technology-baseline.md)，小项目可并入架构入口。保存实际单元/状态、技术与工具链、代码规范和检查/启动/交付入口、依据版本与未核验项。已确定的框架直接引用本约定，项目重要选择关联 ADR/ARC；不抄写锁文件和 schema 的全部内容。

框架大版本、安装/CI、代码规范、模块/数据或交付变化后定向更新基线；复盘核对真实入口与有效决定，记录偏差和必要建议。遵守既有基线的实现直接推进，只按[执行协议](../../dev-flow/references/execution-contract.md)确认改变重要决定的部分。

通用 Guide 的新增类型与具体项目的事实维护分开。历史调查不扩大当前三类约定；其他类型的项目经验保存在各项目，需要建设该类型指导时再归纳。
