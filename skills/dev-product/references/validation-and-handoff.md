# 可用性验证与下游交接：P06

## 选择能回答问题的验证方式

根据本次未知问题、现有应用与工具选择方式：

| 方式 | 能支持的判断 | 需要报告的限制 |
| --- | --- | --- |
| 场景或状态走查 | 入口、步骤、分支和恢复是否完整、自洽 | 没有证明实际呈现与操作成立 |
| 线框或静态状态示例 | 信息与操作意图是否易于理解 | 没有证明异步、导航或数据行为 |
| 可操作原型 | 核心操作和反馈在原型中是否可用 | 模拟数据与真实系统差异，尚未验证的场景 |
| 实际应用操作 | 当前版本在声明环境中的真实行为 | 设备、账号、数据与范围限制 |
| 真实用户观察 | 指定用户和任务中观察到的困难 | 样本、招募、条件及结论适用范围 |

采用现有应用或原型能回答问题时先复用。需要原型时聚焦本次关键行为，在允许范围内创建；不用高保真视觉方案代替交互说明。不能访问应用或工具时完成可行走查并记录缺口。

按任务构建 HTML 原型或设计稿、选择现成服务启动、检查渲染与操作、同用户讨论的方式见[原型与设计稿指南](html-prototyping.md)。本机服务、候选设计、原型操作、真实用户观察、生产行为与部署分别记录；没有外部服务验证时不将本机地址写成远程可用入口。

## 执行与观察

明确任务、起始数据、目标环境与成果版本，用自然用户操作走到目标或失败。观察发现入口、理解信息、执行操作、确认结果和恢复的阻力；检查本次相关键盘、焦点和反馈。

报告“条件 → 实际操作 → 观察 → 对任务的影响”。将观察到的问题与改进假设分别表达；模型推演、代理检查和真实用户观察分别标注。没有接触用户时，不生成用户访谈证言、行为统计或满意度结论。

每个实际问题关联规则、状态或验收编号，明确是否阻断本次范围、交给谁处理、如何复验。复验针对变化后的当前版本；未执行项保留为待验证。

## 下游如何继续

- 视觉：页面语义结构、信息优先级、组件意图、状态与文案、目标设备及已有视觉约束。
- 架构：业务不变量、操作与结果语义、数据和权限需求、尚缺的查询、兼容或恢复契约。
- 研发：有效目标与范围、流程和状态规则、业务约束、原型入口、依赖与可观察结果。
- 测试：稳定验收编号、代表数据、成功和相关失败恢复场景、当前实际观察与验证缺口。
- 运维交付：核心任务、演示与验收所需数据和入口、相关运行假设与约定交付终点。

交接引用同一有效规格，不为每个职责复制一套业务规则。视觉或架构反馈影响用户行为时定向协商更新，记录有效决定和受影响场景。

设计结论、候选变更与实际功能验收分别记录。未完成验证不会自动否定所有有效设计，但也不能用完成设计掩盖阻断性未知问题。
