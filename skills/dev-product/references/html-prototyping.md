# HTML 原型与设计稿构建、预览指南

本指南让 AI 根据本次产品、交互或 UI 设计问题，构建相应页面，选择现成的 HTTP 工具或开发脚手架启动预览，再与用户持续讨论和修改。脚手架提供工程与运行起点；页面内容、业务流程和视觉表现由本次任务决定。随包示例可选，任务不要求采用其预约/批量任务、布局或讨论控件。

先明确本轮需要回答的问题和成果类型。静态设计稿用于讨论信息层级、布局、文案、组件呈现和响应尺寸，需要实际渲染；可操作原型用于讨论操作顺序、状态反馈、异常恢复或方案取舍，还需实现相关操作。产品职责负责交互语义，视觉职责负责呈现，小任务可由同一执行者承担。局部且已清楚的变更可以复用现有页面，不为所有任务另建原型工程。

代码原型适合检查接近真实界面的交互，但其结果仍有模拟范围；原型代码进入生产前需要重新按工程标准实现与验收。[GOV.UK 原型指导](https://www.gov.uk/service-manual/design/making-prototypes)

## 默认执行：构建任务页面并选择现成服务

1. 读取本次目标、有效规格、视觉资产与项目入口；检查已有页面、包清单、开发脚本、可用运行时和正在运行的相关服务。确定成果是静态设计稿还是可操作原型，以及需要讨论的页面与状态。
2. 按下表选择最小合适的工程与服务。已有合适服务时复用；需要新工程时选择当前环境可用的工具。框架初始化、依赖与启动参数依据项目约定及当前官方文档，不固定框架、工具版本或模型。
3. AI 实际生成或修改本次页面的 HTML/CSS/JS 或框架组件，使用项目文案、代表数据与设计资产。启动服务前确认入口文件或路由存在；把需求写成文档或仅启动空服务不构成页面交付。
4. 执行已核验的启动命令，读取服务实际输出地址。在浏览器打开目标页面，检查设计稿的渲染与目标尺寸；原型还需执行核心操作和相关恢复场景。发现问题后修正并复验。
5. 提供真实预览地址、成果位置与版本、启动和停止方式、模拟范围及已检查内容。收到反馈后继续修改同一有效成果，并更新相关决定与规格。

| 情况 | 起点 |
| --- | --- |
| 已有运行中的项目 | 优先使用现有组件、Tokens、路由和开发服务；在允许范围内增加隔离的原型路由或 Storybook 场景 |
| 独立静态页面、没有合适工程 | AI 创建任务所需的 HTML/CSS/JS，使用环境中已有的 HTTP 工具，例如 Python 标准库服务 |
| 需要框架组件、复杂导航或开发热更新 | 优先使用项目既有开发脚本；独立工程确需框架时选择合适的现成脚手架并记录初始化和启动方式 |
| 需要远程评审 | 根据已授权的目标形成预览部署，报告访问方式、版本及模拟范围；本机地址不能作为远程访问入口 |

项目已有开发脚本时，使用包清单中实际存在的命令及项目包管理器，确认目标路由能打开。静态 HTTP 服务仅发布文件；需要服务端渲染、API 或特定路由回退时，使用对应工程的开发服务。

## 独立 HTML 页面的最小启动示例

在目标项目中先创建 `design/prototypes/checkout-v1/public/`，由 AI 根据本次需求写入 `index.html` 及必要的样式、脚本和资源。目录名按任务调整。确认环境有 Python 3 后，在项目根目录运行：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory design/prototypes/checkout-v1/public
```

此示例入口为 `http://127.0.0.1:8765/`；命令保持运行时可预览，修改后刷新，Ctrl+C 停止。端口冲突时换用空闲端口并报告实际地址，保留其他任务的服务。使用其他现成 HTTP 工具同样可以，核验其发布目录、监听地址和启动参数即可。

本机讨论默认监听 `127.0.0.1`，仅发布专用页面目录。复用现有服务时遵循其运行方式。记录服务是已有进程还是本次启动，保留重启方式；结束服务后报告入口已停止，继续讨论时保持入口可用。本机地址依赖当前机器和进程，不是永久或远程链接。

## 可选：使用随包示例快速开始

需要参考完整模拟交互或快速试用工具时，可以使用随包示例；也可以直接采用上面的标准 HTTP 服务或项目开发服务。示例不是所有项目的必需模板。使用随包工具时，在目标项目根目录执行；需要 Python 3.9 或更新版本：

```sh
python3 "$HOME/.agents/skills/dev-product/scripts/prototype.py" init design/prototypes/booking-v1 --title "预约流程讨论"
python3 "$HOME/.agents/skills/dev-product/scripts/prototype.py" serve design/prototypes/booking-v1 --port 8765
```

打开脚本实际输出的地址；默认 `http://127.0.0.1:8765/`。端口已占用时选择其他端口，`--port 0` 可自动分配。修改后刷新；Ctrl+C 停止。初始化拒绝覆盖已有目录，后续直接编辑已有原型，不重新初始化。

随包示例包含 C 端预约与 B 端批量任务两个虚构任务，可切换弹窗/同页确认、空内容、权限不足、失败、未知结果、成功和预览宽度。提交包含模拟等待，未知结果通过查询模拟任务继续；按钮触发真实的浏览器状态变化。状态直接切换仅帮助讨论展示，不证明正常流程可到达该状态。采用示例构建项目原型时，按实际需求替换页面与行为；静态设计稿或简单原型可以省去场景切换和反馈界面。

地址保存任务类型、方案和状态控制，不保存本页输入与选择；刷新不会恢复模拟任务。需要复现具体对象或输入时将场景数据放入项目原型，绑定版本，不依靠当前浏览器内存。

以下文件结构仅描述随包示例，其他工程沿用自己的约定：

| 文件 | 如何使用 |
| --- | --- |
| `public/prototype.json` | 设置原型 ID、版本、候选状态、研究问题、有效来源、验收目标与模拟说明 |
| `public/index.html` | 原型外壳和讨论控制；按项目调整页面与导航 |
| `public/app.js` | 示例任务、状态转换、方案差异与反馈导出；替换成真实规格的模拟行为 |
| `public/styles.css` | 可调整的基础 Tokens 与布局；使用项目视觉资产时保持版本和来源 |
| `review.md` | 讨论条件、观察、决定与复验；位于发布目录外，合并或关联到项目权威位置 |

随包服务只发布原型的 `public/`，默认仅监听本机。示例不自动写回项目规格；其反馈暂存在浏览器内存，刷新前点击“导出反馈 JSON”，复制生成的 JSON 或使用下载链接，确认保存到项目规定的证据位置，再整理有效决定。下载成功与反馈已进入 Git 分别记录。其他页面可以直接在项目文档中记录反馈，无需实现导出功能。

## 页面构建与验证要求

1. 绑定用户任务、页面/规则/状态编号和本轮验收目标。写明待决定问题，例如“提交后是否能找到结果”或“主操作在目标尺寸下是否清晰”。
2. 用项目实际文案与有代表性的数据量构建入口、核心操作与结果；无真实数据时使用标明为模拟的内容。默认示例不是项目已确认方案。
3. 静态设计稿检查实际渲染、文案、目标尺寸与必要状态示例，明确未实现交互。可操作原型主路径中相关按钮、字段、返回、确认和取消有对应行为；未覆盖功能明确说明，不能用无反馈的假按钮掩盖缺口。
4. 原型状态与规格使用同一含义。相关模拟延迟、权限和故障可复现；结果未知、明确失败和成功分开；需要切换方案时保持任务与数据一致。
5. 使用当前可用的浏览器工具；原型实际操作主路径与关键恢复，检查相关键盘与焦点。缺工具时如实记录，HTTP 200 不证明页面渲染或交互成立。
6. 提供实际 URL、版本、运行方式、必要场景地址、已验证渲染或操作与模拟范围。反馈引起修改后复验本轮问题。

原生 HTML 控件优先；模态应使背景不可操作、维持内部键盘路径，退出后恢复合理焦点。[W3C 模态交互模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

## 与用户讨论并收敛

在设计讨论中说明问题与候选差异，邀请用户按真实任务操作；做可用性观察时给出中性的任务描述，先观察，再追问卡点，避免先教会点击路径。分别记录团队偏好、实际用户观察和 Agent 自查。[GOV.UK 主持式可用性测试](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing)

有重要取舍时比较保持相同数据和目标的候选；不要求每次产出固定数量的方案。区分视觉偏好、交互阻力、业务政策和实现约束。反馈关联原型版本、方案、状态、具体操作与影响；实际发生的观察才能登记为用户证据。

收到反馈后定向修改原型和有效规格，复验原问题。确认决定、放弃原因、仍待验证内容及下游变更按[项目资产协议](project-assets.md)沉淀。方案被认可仅表示本轮设计取舍成立，生产功能与最终视觉仍需对应职责核验。
