# 飞书进展通知规范

适用于会话监控的手动检查和已授权定期通知。默认采用以下格式；用户另有明确格式要求时遵循用户要求。格式只规定消息正文，发送范围、身份、频率和去重仍按[监控 Skill](../SKILL.md)与实例配置执行。

## 富文本呈现

默认使用飞书富文本消息 `post`。按本地配置指定身份和收件人，通过 `lark-cli im +messages-send --markdown` 发送；该选项将 Markdown 转换为飞书 `post`。具体发送约束按已安装的 `lark-im` Skill 及 `+messages-send` 参考执行。

- 消息标题使用一级 Markdown 标题，包含检查时间和实例时区。
- 状态使用二级 Markdown 标题，形成消息的一级分组。
- 会话原名加粗；每个会话的四项内容使用无序列表。
- 有明确用户待办时，加粗具体动作及关键选择；“暂无”保持普通文本。
- 每个标题、会话名称、列表和下一条目之间留空行，使用纵向布局。
- 实际进展正文直接传入 `--markdown`，不把整条消息包在代码块里，也不以 `--text` 发送带格式的正文。下文代码块仅用于展示模板源码。

采用已验证的标题、加粗、列表和普通链接，不依赖完整 GFM、精确字号或网页 HTML。CLI 会规范化标题层级和行距；需要彩色容器、折叠或按钮时另按消息卡片能力处理，不在默认通知中自动切换。

## 按状态分组的模板

```markdown
# 研发进展｜检查时间（时区）

## 状态

**会话原名**

- 当前：正在推进的具体工作或当前结论
- 本次进展：相对上次成功通知新增的结果
- 下一步：会话中已明确的下一项动作
- 需你处理：**具体动作及其影响**；没有则写“暂无”
```

状态是消息的一级分组，同一状态只出现一个分组标题，其下连续列出该状态的会话条目；单会话也使用“状态分组 → 会话条目”的结构。会话标题使用工具返回的原名，保持可定位。条目中的四项按固定顺序保留，每项通常一句；每个条目正文尽量控制在 200 个中文字符左右，会话名称和必要链接另计。涉及重要阻塞或决定时优先说清楚，不为篇幅省略必要信息。

- **当前**：先说当前阶段及具体对象，例如“联调订单保存与列表刷新”。阻塞时说卡在哪个环节；完成时说完成了什么范围。
- **本次进展**：写本次新增的可核验结果，通常 1–2 项，例如“已修复重复提交，接口自测通过”。读取文件、搜索、调用工具等过程不单独算结果。
- **下一步**：写近期摘要中明确的动作或正在执行的后续工作；没有依据写“尚未说明”，目标明确完成且无后续写“本任务已结束”。不替被监控会话编排计划。
- **需你处理**：写谁需要做什么、涉及哪个对象或选择，以及它影响哪一步；没有用户待办写“暂无”，无法判断写“待确认”。阻塞由 Agent 自行处理时也写“暂无”。

“本次”指相对上次成功通知的增量，不是相对每次定时检查。发送失败后的待发内容保留，成功才更新通知标记；同一结果不反复出现在“本次进展”。定时检查只有发现新进展、状态变化、阻塞或待办时才发送，不能为了填模板制造更新。

## 状态与证据

- **等待你处理**：用户有明确待办或决定；“需你处理”写成可直接响应的动作并加粗。
- **阻塞**：某项依赖或失败阻止继续；写原因、受影响环节及已明确的解除动作，不把所有阻塞都转成用户待办。
- **执行中**：有证据表明任务正在推进；写正在做的对象和新增结果。
- **本轮结束**：当前 turn 已结束，但目标尚未明确达成，也没有明确用户待办；如实写剩余范围和已知下一步。
- **已完成**：近期内容明确说明用户目标和约定范围已达成；写完成范围与实际验证层级。
- **暂时不可读取**：无法取得当前状态；明确当前未知，可注明最后确认的工作及时间，不能当作本次新进展。

状态和内容都来自实际观察。实现、自测、正式验收、部署分别表达：接口自测通过不能写成端到端验收通过，提交或本轮结束不能写成已完成。没有明确数量基线时不写百分比，不凭测试数推算整体进度；没有会话中明确的时间依据时不推测完成时间。

同一会话只归入一个当前状态分组。多种状态同时存在时，优先归入需要用户处理或阻止继续的状态，在“当前”说明具体范围；部分工作仍可继续时也注明。状态变化后归入新状态，在“本次进展”说明变化，不在旧组重复列出。仅出现新的阻塞、待办或读取异常时，“本次进展”可写该变化，例如“发现测试环境不可用”或“未取得新状态”。读取异常仍按监控 Skill 抑制重复错误。

## 汇总与分组顺序

一次运行有多个需要通知的会话时，合并为按状态分组的消息：开头写“研发进展｜检查时间”，注明实例采用的时区；只列本次发生变化的会话。

默认分组顺序固定为：**等待你处理 → 阻塞 → 执行中 → 本轮结束 → 已完成 → 暂时不可读取**。没有条目的分组省略。每组只写一次状态标题，组内每条先写加粗的原会话标题，再保留上述四项；同组条目之间、不同分组之间均空一行。按状态归组后再排列条目，不把每个会话做成带独立状态标题的一级分组。不逐条罗列无变化的会话，也不在开头重复正文历史。

链接放在对应会话末尾，只有工具给出可用链接时才添加；原始日志和详细历史留在会话或成果中。不要把本机绝对路径当作飞书收件人可打开的成果链接。

## 示例

以下会话与进展均为虚构格式示例。

### 执行中

```markdown
## 执行中

**订单管理联调**

- 当前：验证保存订单后的列表刷新。
- 本次进展：已修复重复提交，接口自测通过。
- 下一步：执行真实前后端保存与刷新用例。
- 需你处理：暂无。
```

### 等待用户决定

```markdown
## 等待你处理

**订单删除规则**

- 当前：删除功能停在已支付订单的处理规则；其他联调继续。
- 本次进展：发现已支付订单的删除预期尚未确定。
- 下一步：规则确认后补齐对应实现和用例。
- 需你处理：**请选择“禁止删除”或“允许删除并保留记录”，以确定实现与验收预期。**
```

### 明确完成

```markdown
## 已完成

**订单管理联调**

- 当前：已完成约定的订单保存与列表刷新功能。
- 本次进展：真实前后端保存、刷新及失败重试用例均通过。
- 下一步：本任务已结束。
- 需你处理：暂无。
```

### 多会话汇总

```markdown
# 研发进展｜10-12 16:20（Asia/Shanghai）

## 等待你处理

**订单删除规则**

- 当前：已支付订单的删除规则待确认。
- 本次进展：发现现有用例缺少该场景预期。
- 下一步：确认后补齐实现和用例。
- 需你处理：**请选择“禁止删除”或“允许删除并保留记录”。**

## 阻塞

**订单发布**

- 当前：测试环境部署失败，尚未进入线上发布。
- 本次进展：定位到测试环境缺少启动配置。
- 下一步：补齐配置后重试测试环境部署。
- 需你处理：暂无。

## 执行中

**订单管理联调**

- 当前：验证失败重试的界面提示。
- 本次进展：保存与列表刷新用例通过。
- 下一步：复验失败重试用例。
- 需你处理：暂无。

**订单列表优化**

- 当前：检查长列表滚动表现。
- 本次进展：已消除筛选后重复渲染。
- 下一步：复验长列表筛选与滚动。
- 需你处理：暂无。
```
