# 设计系统、组件与页面

读取产品规则与信息优先级、现行视觉系统、代码主题、已验证组件和目标内容。新方案在本次范围内改善，已有项目局部设计不自动扩展为整体换肤。

## 可实现的视觉规则

| 对象 | 写到规格与代码映射中的内容 |
| --- | --- |
| 布局 | 导航、主要内容、辅助信息和行动区域；对齐、宽度、阅读顺序及相关滚动行为 |
| 排版 | 标题/正文/辅助文本层级、字重、行高、长度与截断策略；关键信息如何完整可读 |
| Tokens | 语义颜色、间距、尺寸、圆角、边界和层级；权威代码位置与必要主题差异 |
| 组件 | 官方组件/项目组件/共享组合的选择、公开属性、变体、真实源码和使用边界 |
| 状态 | 相关加载、空、错误、禁用、只读、权限、成功和结果未知的具体呈现 |
| 窗口与内容 | 实际目标窗口、窄屏/长文字/大量数据变化下的规则与必要案例 |
| 反馈与动效 | 实际触发、持续时间、完成与中断，必要 reduced-motion 替代；不影响任务完成 |

Tokens 必须能定位到 ConfigProvider、CSS 变量或实际主题模块。B 端从 Ant Design 的官方 Token、公开属性和组合扩展；不要复制一份脱离实际代码的数值表，也不要为了风格自建已有基础控件。C 端使用项目 shadcn/Tailwind 基底，复制参考源码后由项目维护。

## 结合交互语义

产品定义入口何时可见、何时可执行，视觉确定显示、禁用/只读说明、位置和相关状态的呈现。状态颜色、标签、说明和可操作反馈结合，关键含义不能只依赖颜色。禁用与错误原因保持可理解；基础控件的键盘、焦点和可访问名称保留。

例如批量操作：数量和范围由产品定义，视觉使范围与主操作清晰；零选择、处理中、部分失败、结果未知用对应呈现。未知结果不能只换成通用红色“失败”。纯布局取舍无需重写业务规则。

## 原型与工程复用

复用同一项目原型或隔离路由，用实际组件、代表内容和状态展示。Markdown 适合规则，MDX 适合规则旁的 React 示例；完整业务原型继续保留独立源码入口。调用共同工具生成真实预览链接，配置或源码变动后核验当前页面。

候选设计与正式基线分别维护。只有存在明确重复任务、边界与代表验证时提取共享组合；项目特殊权限、数据接口、配额和文案由项目注入。视觉提出通用规则与呈现改进，研发核验实现与依赖，测试检查行为。
