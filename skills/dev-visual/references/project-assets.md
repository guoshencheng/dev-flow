# 视觉资产复用与持续维护

按共同[文档与归档协议](../../dev-flow/references/design-document-contract.md)定位本次业务项目的设计/UI 资产，在项目主索引登记视觉入口，并关联产品与技术资料；优先复用 `docs/dev-flow/` 内已有权威目录。现行 UI 页面、组件说明与设计规范默认在 `docs/dev-flow/visual/` 独立持续维护，独立设计稿源码维护在 `docs/dev-flow/visual/prototype/`，正式应用源码留在实际工程；迭代只引用资产与版本并记录变化，复杂时按需拆出 `docs/dev-flow/iterations/<迭代ID>/visual/changes.md`，不每轮复制完整规格或源码。通过产品功能 ID、RULE/AC、原型 PT 和必要证据关联，讨论/确认提供该项目设计资料与总览/独立页面的实际入口，不以通用 Skill 说明替代。

专业内容按[视觉规格协议](specification-contract.md)维护；UI 基准、Ant Design 联用和共享组件方法由视觉主责维护，产品/研发/测试按需引用，不各自复制一份。

## 权威资产与关联

- `index.md` 指向现行设计系统、相关页面/组件规格、原型、参考和必要检查结论，登记总览与各端独立入口。
- `system.md` 或项目设计系统目录独立维护视觉原则、真实 Token/主题位置、字体/间距/颜色、官方和项目组件目录、变体及适用边界；复杂规范按主题拆分，页面与总览引用它，不复制第二套脱节数值。
- `pages/<页面ID>.md` 维护现行页面结构、端差异、状态、目标窗口、组件/代码映射与产品规则；差异较大时按端拆分，简单差异在同一规格分节。只维护本次需要的现行页面，不每轮生成整套文档。
- `components/<组件ID>.md` 按需维护有复用价值的组合、变体与状态契约；已有源码/组件文档足够时直接引用，不为每个基础控件增加文档。
- 设计稿工程沿用稳定源码位置，索引登记启动命令、各端页面/模块/组件与场景映射、总览和尺寸容器位置、候选和已确认源码版本；后续任务修改同一有效工程，模块组织见[设计系统与页面](system-and-pages.md#模块化-react-设计稿)。
- 迭代索引或按需建立的 `visual/changes.md` 只记录有效基线、受影响资产链接、沿用/新增/修改/替代范围、确认版本、检查结论与未覆盖项；已存在的 `visual/design.md` 可继续作为该轮变更记录，不要求改名或再新建一份。
- 参考与重要决定有來源、适用边界和替换关系；简单记录可以放在同一页面规格中。
- 原始截图、操作和复验按共同协议写本机 `.dev`，结论在现行规格或本轮结果中关联真实版本、各端内部视口尺寸、内容、状态和执行方式；必须转交的证据按项目实际要求保存。

按需使用[视觉规格模板](../assets/templates/design-spec.md)。原始设计文件、媒体、PDF/HTML 导出保留来源和实际许可；导出预览注明原件版本，不能自动成为新权威规格。

## 新任务如何复用

读取当前系统和受影响页面，核对产品规则、实际主题/组件与目标条件。未变且有效的规则直接沿用，差异建立明确变体；废弃组件、失效参考和过期截图不能仅凭名称复用。局部修改保留稳定页面/规则编号及未受影响资产。

迭代开始先做资产映射：功能/页面 ID → 现行规格 → 各端源码 → 共享组件/主题 → 总览入口。找到有效资产后原位修改并用 Git 保存历史；仅缺少独立页面、组件或规范时新增对应资产。UI 没有变化时只在迭代索引引用基线，不创建本轮 `visual/` 目录；变化较少时在索引写增量即可，变化较多再建立 `visual/changes.md`。

现行规格引用有效产品与设计版本，迭代记录受影响页面/模块、复用组件、改动与确认范围，未变的完整规格直接引用。候选修改保留已确认基线提交/版本与变更范围，历史迭代的确认/验收结论绑定原版本；新需求或新会话不重新生成整套 UI。已有完整规格在历史迭代且仍被指定为现行时先通过索引明确其权威状态，整理到稳定目录时修正引用并保留来源，不再次逐轮复制。

Tokens、组件、数据、目标平台或产品语义变化时标明影响范围；失效检查待复验，不能只刷新日期。项目自有源码和共享组合按共同复制协议维护，保护项目定制，经过项目验证的通用改进才作为共享候选回收。

日常历史由 Git 管理，已替换完整方案按共同 archive 规则存放，索引始终指向现行基线。交接列出复用/更新资产、未决问题、设计债务和下一次核验；新上下文通过文件能恢复有效方向。

V01—V08 持续记录方法、实际证据、当前有效性与缺口。配置与指导存在、工具隔离检查、实际设计行为和真实项目复用分别登记。单次候选或截图不提升为普遍偏好或成熟设计系统。
