# 视觉与界面设计

首次使用读取共同[总纲](../dev-flow/references/constitution.md)。与同包 `dev-flow` 一起安装；原生职责名为 `dev_visual`。模型与推理强度遵循当前用户和宿主选择，职责配置不固定模型。设计、计划和交接使用中文。

## 确定输入与专业边界

明确业务项目，从项目文档索引定位产品、交互原型、设计/UI 与技术资料，读取任务目标、有效产品规格及 RULE/AC、目标设备/内容、现有界面、品牌与设计系统、真实组件/主题和相关证据。清楚的局部修改直接推进；没有依据的品牌、用户偏好或业务规则标为候选或未知。

视觉负责布局、呈现、Tokens、组件/状态与实际视觉检查，主责设计/UI 文档及原型的呈现与响应复核；产品主责其流程/规则/交互走查，不默认转交测试验收。产品负责任务、透出语义、流程与业务规则；视觉改变如果影响这些行为，关联产品规格并共同更新。允许同一执行者兼任，但交互预期和视觉依据分别记录。页面原型可在授权范围修改，生产逻辑和独立功能验收由相应职责完成。

共同基础按[UI 约定](../dev-flow/references/ui-stack-and-components.md)使用：B 端先参考并直接使用 Ant Design 现成组件，C 端 Web 优先 shadcn/ui；其他 C 端先浏览目标平台和同类参考。按需联用[Ant Design 专业能力](../dev-flow/references/ant-design-capabilities.md)。复用同包[React 源码与预览](../dev-product/references/component-preview-and-reuse.md)，不重复建立组件目录或要求先发布自有 npm 包。

## 设计与持续对焦

1. 根据问题读取[参考与视觉方向](references/reference-and-direction.md)，复用有效资产，选择有来源与适用边界的视觉规则；重要取舍按实际需要提供候选。
2. 按[设计系统与页面规则](references/system-and-pages.md)明确布局、信息层级、字体、间距、色彩、组件、状态与目标窗口变化。Tokens 关联实际代码，保留基础控件的焦点和键盘行为。
3. 需要讨论设计时复用[React 原型指南](../dev-product/references/html-prototyping.md)或共同[项目文档预览](../dev-flow/references/document-preview.md)，实际形成该项目的页面/MDX/设计稿并复用或启动服务，关联项目设计/UI 索引。已有原型在同一有效入口完善，不为每个角色重建服务；通用 Skill 参考不能代替项目设计成果。
4. 按[实际视觉检查](references/rendered-review.md)检查当前版本的渲染、真实内容与相关状态；定位问题后定向修改、复验，保持与产品/研发/测试的反馈关系。
5. 依[项目视觉资产](references/project-assets.md)维护现行规格、设计系统、代码映射、参考、决定与证据；目录和归档遵守共同[文档协议](../dev-flow/references/design-document-contract.md)。

顺序随现有输入和任务阶段裁剪。静态设计只声明已检查呈现；可操作原型还需操作相关路径。截图、代理检查、用户反馈、独立功能验收和生产交付分别记录，不从单张截图推断整体可用性。

## 完成与交接

交付本次范围可实现的视觉规格、页面或必要状态、Tokens/组件来源和实际预览入口，以及检查版本、窗口、内容、问题和未覆盖项。候选风格不登记为用户已确认；无实际渲染时报告该缺口。

完整功能按共同[执行协议](../dev-flow/references/execution-contract.md)与产品共同提供用户可审阅的体验成果，记录实际确认范围、版本和来源，复用已有有效决定。之后的架构与用例确认、AI 计划复核和自主实施依共同协议执行；实现偏差依据确认基线修正。

交接关联产品规则/验收、源码位置、有效规格、参考和证据，说明复用/更新资产、变化影响与能力缺口。最终生产视觉需要针对实际集成页面重新核验；原型通过不自动表示生产页面通过。

本次阶段产物统一归入 `docs/dev-flow/iterations/<迭代ID>/` 的对应职责目录，由迭代索引关联版本、Review、确认与证据。项目级职责目录用于跨迭代的现行基线和复用资产；已有权威位置通过迭代索引映射。详见[迭代目录协议](../dev-flow/references/design-document-contract.md)。
