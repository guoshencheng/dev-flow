# 测试运行与验收报告

单次运行采用时默认保存为忽略的 `.dev/runs/<迭代ID>/acceptance/<runID>/report.md`，属于本机私有记录，不默认提交或逐轮进入项目索引。需要交接或形成阶段/最终验收结果时，按本模板裁剪提炼到 `docs/dev-flow/iterations/<迭代ID>/acceptance/result.md` 或已有交接入口，只保留接手所需结论、版本、复跑方法与必要材料。

只填写实际执行结果，未完成项明确保留。报告绑定本轮候选和环境。

## 当前结论与范围

通过/不通过/未完成及依据，实际执行者/调用方式，本次用户任务、必需条件、约定交付、未覆盖与依赖；独立复核是否实际执行。

## 输入、候选与环境

run ID、有效用例/确认与 RULE/AC/ARC、完整候选提交及相关未提交差异、实际 URL/产物版本、工具/浏览器/系统/尺寸、数据/身份类别、真实依赖与 Mock 范围。凭据不写入报告。

## 整体候选与复验范围

本次完整候选就绪依据、实现 Review关联及各技术检查汇总：
具体问题的即时反馈、关联修复候选、原问题/相邻契约/受影响回归：
内容与环境未变化的有效结果复用依据、最终整体集成与交付核验：
记录复用 runner 输出，截图/哈希按证明需要补充，不另设证据合规 Review。

## 实际执行与证据

| TC ID / 检查 | 命令或步骤 / 退出码 | 结果及重试/跳过情况 | 证据位置 / 问题 ID |
| --- | --- | --- | --- |

passed/failed/blocked/not-run/skipped 分别表达；重试通过保留 flaky 与首次证据。说明是否覆盖全部必需场景、相关 ARC、真实链路和实际交付。

## 缺陷、修复与复验

关联原问题、修复版本/原因、原场景复验与回归结果、阻断问题状态；豁免仅引用明确来源。后续版本不覆写本轮证据。

## 资产、恢复与后续

复用/更新的策略、用例、自动化、数据和回归；数据/本次进程清理结果，未完成检查、不稳定项及下一任务入口、能力缺口。
