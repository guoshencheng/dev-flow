# 前后端完整链路与交付验收

从用户指定的实际项目入口验证约定任务。独立前后端分别记录源码版本、实际 URL、运行/配置与数据库/外部依赖；Next 在同一应用中仍区分浏览器、服务端和数据职责。通过健康/版本/实际工程记录核验目标，不能因某端口可访问就假定它是当前候选。

## 完整链路的检查顺序

1. 准备与本场景匹配的独立身份、数据/状态和环境，记录有效用例/契约与候选。
2. 从真实页面入口进入，通过用户可见控件完成操作；核心行为在 UI 执行，API 可以准备前置数据，但不能先调用 API 完成目标后只检查页面。
3. 适用时在动作前开始等待对应请求/响应，按 URL/方法/对象限定，核对本次输入与响应业务结果；等待真实状态而非任意相邻请求。
4. 通过实际查询入口/API 或必要的数据观察确认服务端业务结果，验证与 UI 一致。刷新/重进/新会话核验约定持久性；需要跨进程持久化时另做真实存储/重启检查，刷新不自动证明数据库持久化。
5. 执行相关拒绝、业务/网络错误、部分失败、结果未知与恢复场景，检查反馈、数据保留和服务端副作用。
6. 当前版本复验相关缺陷/回归，保留实际命令、运行结果和证据，并完成对应数据与本次进程清理。

共享身份的读回可以使用 `page.request`；不同 API origin 或 token 模式配置实际认证与目标。浏览器自动化前端请求还需走真实 Cookie/CORS/代理/服务地址；API 客户端直接请求通过不能代替浏览器跨域链路。[UI 与 API 联合验证](https://playwright.dev/docs/api-testing)

## 启动、交付与稳定性

优先复用项目有效自动化配置。Playwright `webServer` 可管理一个或多个本地进程，采用实际启动命令/cwd/就绪地址；服务复用前核验项目与候选，CI 使用受控环境。外部部署 URL 不启动本地替代服务来冒充该部署验收。[服务管理](https://playwright.dev/docs/test-webserver)

| 工程/交付 | 按实际要求执行 |
| --- | --- |
| React 独立 Web | 研发阶段可用实际 Vite dev；交付构建站时从构建产物与实际服务检查资源、路由和核心行为，后端另核验 |
| Next 全栈 | 研发循环验证切片，交付时验证实际 build/start 或约定目标部署，覆盖服务器与浏览器链；dev 通过不替代构建交付 |
| Astro 纯静态 | 构建并从实际产物验证内容、路由/资源、链接与有需求的浏览器交互；无接口时 API 项注明不适用 |
| 可启动源码 | 从干净副本/声明环境按项目安装、配置/数据准备、启动和停止方式执行核心任务，外部必要依赖有真实可用证据 |
| 部署/产物 | 在指定版本与环境操作约定成果；记录目标入口与实际结果，平台/浏览器差异按已定支持范围检查 |

Next 官方建议 E2E 面向构建后的生产代码；采用项目有效命令和版本，不照抄示例端口。[Next Playwright 指导](https://nextjs.org/docs/app/guides/testing/playwright)

每次测试隔离浏览器上下文和可写数据，按实际支持范围选择窗口/浏览器。通过可见性/状态和必要轮询等待完成，不用无界重试；需要时间相关场景时区分模拟时钟与真实定时/异步服务。trace、失败截图、响应/日志用于诊断，敏感认证信息按项目证据规则处理。

## Mock 与端到端结论

最终完整链路对被测业务接口和必要数据服务走真实目标。前端 route mock、stub BFF、内存替代数据库或第三方 sandbox 各自登记；允许的第三方替身可用于本系统验证，但不声称该第三方实际集成通过。真实依赖不可用时保留局部结果及完整链路未完成项。

纯 API 系统的 E2E 从真实调用入口完成业务链、必要数据/事件与恢复；没有界面则跳过 UI 层。部署验收和本机测试结果分别登记，不增加本次未要求的生产发布。
