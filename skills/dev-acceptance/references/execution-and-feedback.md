# 执行、证据、研发反馈与复验

先读取有效策略/用例、当前候选与项目运行说明，复用现有 runner/环境。按实际依赖顺序准备身份、数据和服务，选择本次必需检查；可独立部分按共享数据/环境隔离条件并行。同一测试或文档明确写入者。

## 每轮运行可恢复

记录 run ID、项目、用例与产品/UI/ARC 基线、各候选提交及相关脏文件指纹、实际环境/URL/依赖模式、数据/身份类别、工具与浏览器、命令/退出码、逐场景结果和证据路径。长期记录保存可重复入口，实际凭据/认证状态留在项目忽略位置。

结果采用 `passed`、`failed`、`blocked`、`not-run`、`skipped`；偶发失败重试通过额外标记 `flaky` 并关联首次失败。框架退出码为 0 仍需检查计划中必需场景是否实际执行，跳过/不存在的测试不是覆盖通过。[Playwright 重试结果](https://playwright.dev/docs/test-retries)

一个结论绑定候选与环境，接口/UI/数据/配置/基线变化后按影响使相关旧结果待复验。原报告与缺陷证据保留原版本，更新摘要或“当前”入口指向最新运行，不把旧结果刷新日期当成本轮通过。

## 失败如何持续对焦

| 发现 | 操作与记录 |
| --- | --- |
| 实现违反预期 | 保留实际步骤、预期/实际、版本和证据，形成缺陷，给研发最小复现及对应 RULE/AC/ARC |
| 测试脚本/数据有误 | 对照权威预期定位选择器、fixture、断言实现或准备问题；修正执行方式并重跑，保留原失败原因 |
| 服务/身份/依赖不可用 | 诊断实际目标与环境，执行已授权排障；仍缺必要资源则标 blocked/未完成，继续独立检查 |
| 契约冲突或未确认 | 列原来源与受影响用例，向产品/架构提出具体决定；不自行迁就实现改写已确认预期 |
| 不稳定/重试通过 | 保留复现条件和首次证据，定位时序、共享状态、环境或实现竞态；必需验收未稳定时不能靠增加重试关闭 |

缺陷保留 ID、关联用例/契约、环境与候选、前置/步骤、影响/优先级、证据、修复版本与原因、实际复验和状态。使用项目已有 tracker/文件入口，无须重复建立账本。重复失败回到可复现条件、根因和契约/环境核查，不机械扩大 timeout、容差、重试或跳过用例。

状态关系：发现/open → 研发提交修复/awaiting-retest → 测试执行原问题与相关回归 → 通过且证据有效/closed；失败则 reopen，缺环境保留待复验。修复说明或研发自测不直接关闭问题；测试可维护脚本，生产修复遵循任务写入范围与角色责任。

## 最终结论

范围内必需用例实际通过、阻断问题复验关闭、对应 ARC 和约定交付成立，才给出通过。失败给出不通过，必需检查 blocked/not-run/skipped 或证据不足则未完成；已知偏差/豁免需具体已有授权来源，不能由测试自行豁免。

报告对应实际执行者与覆盖，分别说明代理检查、人工/用户反馈、独立复核、真实项目与部署。重要最终验收采用新评审上下文；宿主/授权不允许时说明实际由主 Agent 执行及缺少独立复核，不虚构专门角色执行。交接还包括资产复用、更新、失效和待验证能力。
