# 前端、界面与交互验证

输入是项目产品/交互规则与当前 UI 规格、实际组件和目标设备。先复用项目测试工具，业务交互遵循相同 RULE/AC；B 端优先 Ant Design/antd、C 端 Web 优先 shadcn/ui 的既定选择不新增测试专用自建控件。

## 局部行为与真实浏览器

本方法默认用于可运行实现的界面验证。产品/视觉负责设计文档与原型的方案走查，包括实际操作和恢复状态；测试可读取这些资料设计用例，用户明确指定测试检查原型时按指定范围执行。浏览器/Playwright 是可复用工具，不改变检查的阶段、主责与证据性质。

React 局部规则/组件可用 Vitest + Testing Library，沿用兼容版本与既有配置。优先按角色、可访问名称和标签选择控件，用真实用户事件方式断言结果。DOM 模拟适合多数局部行为，布局、浏览器原生行为和设备交互在真实浏览器核验；需真实组件浏览器能力时采用当前 Vitest Browser Mode 或项目既有方案。[Testing Library 查询](https://testing-library.com/docs/queries/about/)、[Vitest 组件测试](https://vitest.dev/guide/browser/component-testing)

页面测试默认 Playwright，按可见角色/名称/标签定位，列表/弹层有歧义时用实际容器限定。确无语义定位时使用稳定 test ID，避免生成类名、坐标或脆弱 nth 路径。使用可重试的可见性/文本/状态断言等待真实反馈，不用固定 sleep 或扩大超时掩盖失败。[Playwright 方法](https://playwright.dev/docs/best-practices)、[断言](https://playwright.dev/docs/test-assertions)

## 按用户任务选择场景

| 对象 | 按适用规则核验 |
| --- | --- |
| 导航与入口 | 正常路径、深链接/刷新/返回，以及实际权限下入口的显示、禁用和解释 |
| 表单/提交 | 默认值、输入校验、边界、加载/重复提交、成功与业务/网络错误、保留输入和焦点恢复 |
| 列表/详情 | 空/加载/失败、筛选排序分页、对象状态/数量，适用的大数据或虚拟列表 |
| B 端批量操作 | 选中范围/跨页语义、确认摘要、部分失败、角色与对象权限；打开实际 antd 弹层核验 |
| C 端核心流程 | 目标窗口/触摸、渐进流程、中断恢复/数据保留、可见反馈和真实结果；按已有业务选择 |
| 键盘/可访问性 | 适用的标签、Tab/焦点、弹层进入/退出、键盘提交/关闭；自动规则检查不代替实际操作 |
| 视觉与响应 | 按约定支持范围检查实际渲染、真实长文案/数据/错误状态；有视觉回归要求或需证明问题时补充基线/截图，不默认遍历多尺寸取证 |

UI 透出与服务端授权分别验证：隐藏/禁用按钮仅证明前端行为。日期、时区、文件下载、上传、浏览器存储等有业务影响时核验实际浏览器结果，不只检查回调被调用。

## Mock、视觉基线与覆盖

为难触发的网络失败/延迟可使用明确的 route/依赖替身，固定真实契约的代表响应并标为 `ui-isolated`；被测业务 API 在最终完整 E2E 中走真实服务。Mock 与真实链路分组/命名/结果分开，说明第三方真实集成缺口。

视觉回归与视觉职责对齐版本、数据、尺寸、浏览器/系统及动态内容。图像差异先判断实现偏差、环境还是已确认设计变化；基线更新有实际依据，不能为了变绿批量接受新截图。没有有效基线时作实际渲染走查，不能伪报视觉回归通过。
