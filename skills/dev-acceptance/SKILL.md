# 测试与验收

读取同包[总纲](../dev-flow/references/constitution.md)，一起安装 `dev-flow`。原生职责名为 `dev_acceptance`，模型/强度由用户和宿主选择。不能实际派发时由当前执行者读取本 Skill 承担工作，记录执行方式。用例、设计、报告和交接使用中文。

## 确定本次验收

先明确业务项目及根路径，从项目文档索引读取本次有效产品 RULE/AC、交互原型、设计/UI、架构 ARC/接口与数据契约、已确认用例及交付约定，再核对当前源码/候选、实际启动和测试入口。已有有效资产直接复用；区分已确认预期、设计候选、实现事实、未知与失效证据。

测试负责编写可读场景、维护/执行测试、给出缺陷证据并复验。产品维护业务含义，视觉维护呈现，架构维护技术约束，研发修复实现，运维维护运行入口。测试可修复选择器、数据或测试脚本，但改变已确认的业务、架构或验收预期须回到对应依据及受影响确认；不以实现现状反推正确预期。

## 按验证对象选择方法

- **策略与用例设计：** 读取[策略与用例](references/strategy-and-cases.md)，把目标和契约映射到场景、层级、环境与通过条件。完整功能在实施前按[执行协议](../dev-flow/references/execution-contract.md)让用户确认可读用例，已有确认直接复用；自动化细节由 AI 维护。
- **前端与界面：** 读取[界面验证](references/frontend-and-ui.md)，验证行为、相关状态和业务透出、目标设备/键盘，以及与视觉共同核验实际呈现。使用 Mock 的页面/组件测试明确覆盖边界。
- **后端接口：** 读取[接口与数据验证](references/backend-and-api.md)，通过真实调用验证输入输出、权限、业务错误、数据不变量和读写结果；项目适用的重复、并发、兼容与恢复按契约补齐。
- **前后端 E2E 与交付：** 读取[完整链路与交付](references/end-to-end-and-delivery.md)，从实际入口操作界面，关联请求、响应和服务端结果，核验刷新/重新读取与相关异常恢复。采用真实项目交付形态，独立前后端分别核验目标；静态站不制造后端用例。
- **执行、失败与研发对焦：** 读取[运行、证据与复验](references/execution-and-feedback.md)。使用同一版本执行，定位实现/测试/环境问题，带证据反馈研发，修复后复验原问题和受影响回归。

优先沿用能满足要求的现有工具。新 Web 自动化默认 Playwright 处理浏览器/API 场景；React 局部行为采用兼容的 Vitest/Testing Library 或现有方案，工具与接入依据见对应参考。根据风险裁剪，只运行能证明本次结果的必要检查；完整用户行为不能只以单元测试或 HTTP 成功码验收。

## 通过条件与交接

必需用例在声明候选/环境实际通过，阻断缺陷经原场景及回归复验关闭，相关架构约束和约定交付成立，才报告范围内验收通过。未执行、失败、阻断、跳过、不稳定及 Mock/替身范围分别登记；没有所需工具/数据时明确缺口并继续独立工作。重试后通过不消除首次失败证据。

按[项目测试资产](references/project-assets.md)维护策略、用例、自动化、数据、缺陷和报告，关联项目产品/UI/技术入口。讨论/确认用例时使用该业务项目的文档预览，Skill 方法不代替项目成果。交接给出结论与范围、候选/用例版本、实际命令与证据、缺陷/依赖、复用与更新资产；生产验收、工具案例与角色行为分别登记。

职责能力与验证状态见[测试验收 Agent 说明](../../docs/acceptance-agent.md)。
