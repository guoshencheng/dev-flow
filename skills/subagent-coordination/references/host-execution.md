# 宿主提示词定位与执行

同包 `agents/prompts/` 是六职责专业内容的唯一维护源，`common.md` 提供公共约束；宿主入口由 `scripts/sync_host_agents.py` 组合生成。生成物不手工编辑专业规则，也不要求先读旧职责 Skill。

## 实际发现

从已启用插件的能力列表和调用方提供的实际根路径定位资源；以被读取文件目录解析相对路径。安装缓存、开发仓库和用户目录不能凭记忆猜测。读取插件内 `capabilities.json` 可核对真实声明的角色/Skill 路由，文件存在仍不证明原生加载成功。

Codex 的 `agents/dev_*.toml` 仍是参考入口，不自动注册个人 Agent。可用 Harness 子 Agent 时传入本次专业提示词、公共约束与最小任务包；未提供原生角色能力时如实记录这一方式。Kimi 原生入口在 `adapters/kimi/agents/`，安装与重载按[安装指南](../../../docs/plugin.md)执行并单独验证。

当前宿主不能原生派发某角色时，可以给通用执行者加载同一职责提示词；没有任何委派能力时由主 Agent 读取后执行，不能将自己的不同角色名记为独立 Review。所需提示词/资源无法定位时报告具体缺项，不退回已移除的职责 Skill。

## 专业执行与公共操作

专业提示词回答负责什么和如何判断；操作 Skill 回答具体任务怎样执行。独立 Git、文档或运行请求不强制加载整个研发流程。模型、强度和并发遵循本次用户/宿主，不写入可复用角色身份。安装/升级不自动修改全局用户指引或注册个人角色。
