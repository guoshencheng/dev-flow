# 宿主提示词定位与执行

同包 `agents/prompts/` 是六职责提示词的唯一维护源，`common.md` 提供公共约束；生成器将公共约束和完整职责正文内嵌到宿主配置。维护源不等于每次运行必读清单，生成物不手工编辑专业规则。`agents/references/` 的长篇方法及 `agents/assets/` 的模板不展开内嵌，按具体任务读取，不能因正文已加载而忽略相关专业依据。

## 实际发现

从已启用插件的能力列表和调用方提供的实际根路径定位资源；以被读取文件目录解析相对路径。安装缓存、开发仓库和用户目录不能凭记忆猜测。读取插件内 `capabilities.json` 可核对真实声明的角色/Skill 路由，文件存在仍不证明原生加载成功。

先核对实际执行者是否已加载所需角色和公共约束。已加载时直接传任务包，不再要求主 Agent 或接收方重复读取同一份 `agents/prompts/*.md`。未加载时，才从本包明确加载公共约束及所需职责正文，并记录通用执行者补充提示词的实际方式；仅部分缺失时只补缺失内容。

当前插件中 Codex 的 `agents/dev_*.toml` 是内嵌正文的参考配置，不自动注册个人 Agent；不能仅凭这些文件存在就认定 Harness 子 Agent 已加载角色。Kimi 原生入口在 `adapters/kimi/agents/`，实际发现和重载按[安装指南](../../../docs/plugin.md)单独核对，已加载后同样无需重读提示词维护源。

当前宿主不能原生派发某角色时，可以给通用执行者加载同一职责提示词；没有任何委派能力时由主 Agent 读取后执行，不能将自己的不同角色名记为独立 Review。所需提示词/资源无法定位时报告具体缺项，不退回已移除的职责 Skill。

## 专业执行与公共操作

专业提示词回答负责什么和如何判断；操作 Skill 回答具体任务怎样执行。独立 Git、文档或运行请求不强制加载整个研发流程。模型、强度和并发遵循本次用户/宿主，不写入可复用角色身份。安装/升级不自动修改全局用户指引或注册个人角色。
