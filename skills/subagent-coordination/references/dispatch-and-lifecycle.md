# 派发、并发和结果收集

接收调用方已经确定的职责和目标；[流程](../../dev-flow/SKILL.md)安排阶段及必需独立性，本指南安排实际执行者。六职责不要求六个常驻 Agent，也不因工具存在自动扩大授权。

## 判断实际执行方式

先核验宿主支持的 Agent 工具、当前并发、用户/项目要求和可用模型。局部顺序工作、强共享接口或交接成本过高时可直接执行；实际必须独立而无法提供时，保留待独立检查，不将主 Agent 自查改记通过。

优先使用实际已加载所需职责与公共约束的 Agent，直接提供下述任务包，不重复读取或传入相同的源提示词。未加载时按[宿主加载与降级规则](host-execution.md)，从同包 `agents/prompts/` 的[产品](../../../agents/prompts/product.md)、[视觉](../../../agents/prompts/visual.md)、[架构](../../../agents/prompts/architecture.md)、[研发](../../../agents/prompts/engineering.md)、[测试](../../../agents/prompts/acceptance.md)、[运维](../../../agents/prompts/operations.md)及[公共约束](../../../agents/prompts/common.md)补充所需内容。这些链接是维护源与未加载时的降级入口，不是每次派发的必读清单。长篇参考、模板和操作技能按任务需要读取，不固定模型或推理强度。

## 最小充分任务包

包括：原始目标及必要用户约束、项目绝对根路径/工作目录、当前任务与所需职责、有效文件路径/版本、候选及相关初始差异、确认/动作授权来源、可写范围/唯一写入者、结果位置、检查与交接要求、依赖及停止条件。不要只提供上一位执行者的结论而遗漏原始要求，也不默认继承整段聊天。

只读评审写明禁止改源码，提供作者身份、完整输入与候选范围；独立评审者不得参与被审对象主笔。派发成功或角色名称不同不证明独立性，需核验真实执行上下文。作者与评审分离是执行事实，不是文件中的 mode 标签。

## 并发和资源

独立问题可并行调查；实现需契约稳定且写入范围互不冲突。共享文件、接口、数据库、端口、浏览器会话和服务明确负责人，worktree 隔离不等于这些资源隔离。依赖性任务按顺序，输入未定时只推进不依赖部分。

不要让多个执行者盲改同一根因；调查者交证据，由明确写入者修复。收到需求/契约变化时通知受影响执行者，冻结旧候选检查或隔离环境；不得让新旧输入混成同一通过结论。

## 等待与生命周期

使用当前宿主等待/消息能力；派发后主 Agent 继续独立准备、核对或集成。一次超时不是任务失败、完成或交还用户的依据。先查询真实状态，必要时发送窄范围补充；不要重复创建同目标执行者制造冲突。

需要中断时说明原因并保存状态，只有真实停下且资源可恢复才交接。用户明确暂停/停止时遵循；执行者结束并不自动结束主任务。主会话整体结束标准属于流程。

## 结果核对

收集实际完成范围、输入/候选、文件差异、命令和证据、未测项、问题/依赖、资源及下一步。核对返回文件/证据与授权写入范围；自报成功作为待核验信息。由专业职责裁定内容、主 Agent 综合整体结果；Git 合并使用[Git Skill](../../git-workflow/SKILL.md)。

交接区分静态阅读、自测、独立 Review、验收和部署，不将工具/角色配置存在替代真实操作。不能派发时记录原因、主 Agent 读取的职责源和独立性缺口；专业能力仍需按其实际证据判断。

## Agent 工作交接

职责/阶段衔接、中断或换执行者时，明确交出方、接收方、移交对象与下一项责任。提供上述最小任务包及结果：有效输入/候选版本、确认与授权来源、文件和资源写入边界、已完成/未完成、证据及未验证项、阻塞与下一动作。单次派发也要把输入交清，但派发成功不代表接收方已核验输入或完成工作。

接收方先核对材料可取得、版本一致、授权和进入条件成立；缺口反馈主 Agent，保留待接续/受阻，不能自行扩大授权。主 Agent 核验接续事实与返回结果后，统一更新本轮独立 Progress，关联原始成果和证据；不由各 Agent 各建全局进度。

“完成说明”是向用户汇报实际成果、验证及遗留；它不能替代执行者之间移交上下文和责任的 Agent 工作交接。宿主的会话迁移工具只处理实际支持的会话/工作区操作，不能凭工具成功声称专业交接已成立。
