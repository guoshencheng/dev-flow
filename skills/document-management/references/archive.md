# 总结保存与逻辑归档

本指南执行文档整理，不裁定专业正确性或整个迭代是否完成。[独立收尾 Skill](../../iteration-closeout/SKILL.md)组织本轮资料盘点及实际回写，[流程门槛](../../dev-flow/references/closeout.md)负责阶段及结束判断，[Git Skill](../../git-workflow/SKILL.md)保存相关代码。单独整理历史时只处理用户要求范围，不自动修工程、发版、建调度或删除历史。

## 归档前核对输入

从项目/专业索引定位迭代和权威来源，取得专业责任人确认的当前内容与真实结束状态。工作已完成、取消或被替代均可有对应整理结果，但活动、待验、结束不明的迭代不能由整理动作改为完成。

核对实际交付/验证版本与缺口、代码保存位置/未提交原因、当前资产入口、遗留承接和必要来源链接。取消无需补出不存在的验收；缺少必需交付时保留真实未完成。发现冲突交专业责任人，不自行修改规则。

## 执行步骤

1. 盘点所选资料、版本、来源、重复项、断链与遗留；有有效原记录时直接引用，不为整理重跑所有历史检查。
2. 根据专业有效性结论区分 current、待核验、被替代候选和过程资料；将有效增量实际写回既有长期正文。资料本身适合直接作为权威源时可关联长期入口，但不能以新增链接替代必要的基线合并。没有变化保留核对范围和复用依据，缺少入口按本轮有效范围补齐。专业内容的正确性由对应职责检查，未决冲突保留待核验。
3. 在既有索引结束章节写总结，复杂时拆同目录 summary.md，引用原设计/Review/验收/交付记录而非复制整套报告。
4. 已有明确结束状态且整理条件成立时，记录日期、来源版本、总结及遗留承接，更新项目导航；不成立则标待整理/待决与具体缺口。
5. 检查相对链接、资源、预览和现行入口，返回实际整理范围。重复执行只处理新增变化，不新建平行账本。

工作状态、整理状态与文档有效性分别记录：逻辑归档的迭代可能仍含 current 规格，不能批量改为 archived。普通修订由 Git 追溯，被替代完整候选按需放所属目录 archive/ 并保留替代关系。

## 总结写什么

总结至少回答实际留下什么、下一轮从哪里继续：原目标与实际完成/取消/未完成，输入/候选/产物及环境版本，真实检查和未执行项，关键决定/来源，长期资产更新或复用，代码/资源实际保存状态，遗留的责任/入口/依赖，以及工作结束原因与整理状态。

专业结论由各职责提供，文档组织者保存并关联；不能从“已归档”推出业务通过，不虚构收益、确认、执行时间或通用经验。普通重试与原始日志留项目本地目录，持久报告保留重要结果与必要证据。

## 历史迁移与保留

默认保持 iterations/<ID>/ 原路径，导航分活动、待整理和历史。确需物理迁移时先核对入站与外部链接，移动后修正相对资源和预览；无法修复的外部入口留兼容说明。不能同时维护两份可编辑 current 文档。

归档不自动授权删除历史、大文件或证据。按项目保留/清理规则处理临时缓存，必要内容先保存；未知归属保留交接。
