# 迭代入口

采用到 `docs/dev-flow/iterations/<迭代ID>/index.md`。仅填写本轮实际需要的阶段与路径；本模板不是完整阶段的强制清单，采用后删除说明。

本轮多阶段工作默认在 `Progress.md` 维护唯一总体进度，本索引只链接：总体进度（采用后填写本轮唯一 `Progress.md` 的实际相对链接）。若已明确选择本索引为权威，则把状态块放在本文件且 Progress 只引用，不双写。维护本轮目标、有效产物和交接/结果；正式独立 Review 的对象版本、发现、处理和结论持久保存在 `engineering/review.md` 或项目已有权威 Review 位置，主设计引用其结论。逐次运行日志、临时取证和 Review 原始过程写忽略的本机目录，不每次执行追加持久文件；接手信息写 handoff/result。

选定的进度权威须从开始覆盖最终目标的全部阶段：设计与技术反馈、研发设计及交叉 Review、实施计划及授权、连续实现与自测、完整候选的正式用例独立 Review、验收与交付核验、架构技术收尾、整体保存与结束。每项列负责人、完成条件、当前状态；未开始写待开始，未知写待核验。阶段切换、派发回报、基线/候选变化和结束前更新当前目标、下一步与未完成项。

## 目标、范围与输入

- 项目、迭代 ID、功能 ID 与任务类型：待填写。
- 用户目标、交付结果、本轮范围与非目标：待填写。
- 前序迭代、依赖、有效产品/UI/架构/测试与代码基线：链接实际来源及版本。
- 完整阶段、当前阶段、未开展项、候选版本和维护职责：见选定的进度权威；未执行不能标为通过。

## 工程执行与协作选择

- 任务开始基线、相关初始未提交内容、目标分支/任务分支与工作目录：
- 原 checkout 或 worktree 的选择及原因、运行端口/数据等共享资源负责人：
- 标准任务领域原生 subagent 的实际安排及原因；作者与独立评审分离、输入版本、写入边界与集成顺序：
- 切片/修复/集成/合并前后的必需验证入口及当前证据：
- PR 或评审位置、合并方式/授权来源/实际结果、交付及 worktree 清理状态：

按实际范围裁剪，已有计划/交接记录时只关联；没有执行的委派、合并或清理标明未执行。

### 确认、Review 与未决摘要

已有规格/用例/计划中记录时只引用，不另建报告。合并确认保留各对象范围和版本；用户的局部答复不得扩为其他规则或开工同意。既有预期内的正式用例细化不新增人工确认。示例字段：对象和输入版本、待确认范围、答复实际范围、必要原话与来源、待决；实施摘要的路径依据、具体范围、预期结果、验证/交付及获准 scope；Review 的实际方式、具体检查、发现、结论和时间。结构化授权用 confirmation 的 `authorizes` 关联 scope，其他前置按实际路径补齐。

设计稿源码、页面/组件规格和设计规范在各自稳定位置持续维护，此处引用实际路径、启动方式和本轮页面/场景，不复制进迭代目录。UI 无变化时仅引用基线，不创建 visual 文件；少量变化在下面记录，复杂时再关联 `visual/changes.md`；已存在的 `visual/design.md` 可继续作为增量记录，不要求改名或另写一份。未变的有效完整规格和组件直接引用。

## 交付结果与未完成项

记录成果入口、源码/产物/环境版本、完成范围、必需用例与证据、未执行/受阻内容及遗留项。阶段结束状态、设计文档状态和验收结论分别记录，单个 status 字段不能代替全部事实。

代码收尾沿用上方工程执行记录，补齐最终提交或未保存差异、完整变更 Review/定向复验、必要构建/启动结果、推送/PR/合并/发布实际状态及工作区/服务/worktree 保留原因。只记录本轮相关内容；相关成果保存不要求清空他人改动，无变化不生成空提交。
