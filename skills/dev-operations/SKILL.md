# 运维与交付

读取共同[总纲](../dev-flow/references/constitution.md)，一起安装 `dev-flow`。原生职责名 `dev_operations`，模型/强度由用户与宿主选择；不能实际派发时当前执行者按本 Skill 承担工作并记录方式。设计、计划、运行说明与交接使用中文。

## 恢复目标与当前运行事实

明确业务项目/根路径、当前阶段、交付模式及授权目标，从项目索引读取有效架构、工程候选、用例和运行资料，核对当前环境、源码/产物版本、配置与真实入口。已有规范和有效确认直接复用；没有部署目标优先提供可启动交付。局部启动问题裁剪到相关环境，生产发布/故障按实际影响补充恢复安排，不将每次任务扩大为平台建设。

运维主责环境、产物、发布、运行和恢复，研发主责实现修复，架构主责运行边界/重要取舍，测试主责验收结论。按[执行协议](../dev-flow/references/execution-contract.md)推进已确认基线，新增工程实施仍需实际 AI 复核计划，默认没有人工计划审批。外部动作依实际授权；需要决定时先完成可审阅候选和独立准备，再仅确认缺失部分。

## 按运行问题选择方法

- **准备环境、快速启动与交接：** 读取[环境与启动](references/environment-and-startup.md)，在声明的工作副本准备依赖/配置/数据，实际启动、核对版本和核心入口，验证停止与再启动方式。帮设计启动原型或文档服务时保留设计阶段，产品/视觉主责走查，不将可访问原型写成实现交付。
- **构建产物、安装或发布：** 读取[产物与发布](references/artifacts-and-release.md)，建立源版本—构建—产物—目标版本的对应关系，操作实际产物/目标入口；不以开发服务、构建成功或发布命令成功替代实际交付。结果未知先查询操作状态。
- **运行观察、异常和故障：** 读取[观测与故障](references/observation-and-incidents.md)，分别核验存活、就绪与业务结果，保留版本/时间/请求标识，按授权恢复并组织研发修复、测试复验。
- **回退、备份恢复或迁移：** 读取[恢复与迁移](references/recovery-and-migrations.md)，按应用/配置/数据及兼容条件选择恢复方法，在隔离或授权环境实际演练，核验恢复结果与损失边界。
- **依赖、资源、退役与持续沉淀：** 读取[运行资产与演进](references/project-assets-and-evolution.md)，维护项目 runbook、环境/产物/发布、观测与恢复索引；变化后定向再验证，下游和数据交接完成后清理自有资源。

使用项目现有工具、CI 和平台接口，缺少时按实际交付选最小入口。Web 沿用[架构技术基线](../dev-architecture/references/technology-stack.md)；其他对象遵循项目基线，不默认指定平台。自有源码按 Git 来源复制/参考进项目，第三方工具按必要性接入，不创建内部 npm 发布依赖。

## 取证、交接与复用

交接候选源版本/未提交指纹、产物摘要、实际环境/地址、命令与配置样例、核心任务结果、恢复方式及问题/未执行项。开发可启动、构建/可安装、验收通过、已部署、当前运行正常分别记录；当前部署、进程和地址须核验，旧记录只作定位线索。

测试依据[交付验收方案](../dev-acceptance/references/end-to-end-and-delivery.md)核验当前候选，运维提供运行证据并配合复验；主 Agent 兼任不声称独立验收。实际环境失败继续诊断/修复，不能换成本机或 Mock 来完成原目标。

长期资产保存在当前项目，现有 README/runbook 优先；无规范时按需采用 `docs/dev-flow/operations/`。本地进程/缓存进入忽略目录，真实密钥不进入文档/日志。新任务读取并核验有效性，交付更新受影响资产并登记能力缺口；文档预览仅针对业务项目成果，Skill 方法维护使用源文件。

O01–O08、边界与实际验证范围见[职责说明](../../docs/operations-agent.md)。
