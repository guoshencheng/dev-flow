# 环境、配置与可重复启动

用于 O01；工程已有交接输入见[研发交付方法](../../dev-engineering/references/project-assets-and-delivery.md)。运行记录支持其他执行者照做，实际环境声明与测试证据一致。

## 先定位实际入口

核对项目根目录、当前源码/未提交变更、manifest/锁文件、runtime 要求与工程脚本；多应用分别定位服务、工作目录、依赖和访问关系。项目 README、现有 CI/runbook 是入口，不从框架名称猜命令。恢复现有配置/数据要求，区分必须服务和可选能力；缺少条件写出受影响任务，继续可完成工作。

环境说明包含实际 OS/架构、runtime/包管理器版本、依赖准备命令、必需环境变量及来源、数据初始化、服务顺序、启动/停止与核心任务。配置样例说明必填/默认、构建时或运行时作用、公开或仅服务端、变更后重建/重启要求。真实密钥由项目已有配置系统提供，样例使用占位；日志只保留必要脱敏事实。

新工作副本按锁文件的既定安装方式准备依赖，不依赖未声明的全局包、聊天中保存的配置或上一轮缓存。数据初始化依现有脚本/契约，已有数据的可重复执行与副作用由项目核对。必要的本地替身明确标为替身及覆盖范围，不能冒充真实外部服务。

## 实际启动与停止

使用工程现行入口，记录命令、cwd、配置来源、日志入口和实际地址。端口动态分配或变更时读取实际运行输出；端口已被占用先查服务身份，不接管未知进程，也不因 HTTP 成功复用错误版本。核对目标进程、候选身份、必要依赖和核心任务后登记可启动。

本任务启动的服务记录可核验 PID/会话或平台资源标识与停止方式；停止前核对归属，停止后检查进程结束及自管入口关闭。后台化/进程托管按交付需要采用项目方案，不把工具临时会话当作长期服务承诺。停止与再启动不应丢失契约要求的数据，必要时实际验证跨进程读回。

只需打开原型或项目文档时，记录 `design-prototype` 或 `project-document-preview` 阶段与服务范围，交给产品/视觉讨论；这不要求生产发布、实现 E2E 或独立验收。实际实现交付按[产物方法](artifacts-and-release.md)验证约定模式。

## “干净启动”的证据边界

在另一工作副本依说明完成准备和核心任务，检查缺失依赖/配置、启动失败的定位与恢复方式。新目录但沿用本机 runtime、依赖缓存、浏览器或宿主服务时明确登记；不能称作新机器、所有平台或生产环境验证。README 和真实命令不符时修正运行资料，业务实现故障提交研发并保持原用例预期。

按需复制[运行入口模板](../assets/templates/operations-index.md)，已有 runbook 则更新原位置。入口还需关联验收用例和结果，避免只有健康探针没有实际使用方法。
