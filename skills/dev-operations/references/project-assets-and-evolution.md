# 项目运行资产、环境演进与退役

用于 O07/O08，并持续维护 O01–O06 的项目能力。运行知识属于业务项目，现有 README/runbook、基础设施代码与 CI 是权威位置；通过索引关联，不复制第二套。

## 资产与归档

无现行规范时按需采用以下布局，实际脚本/基础设施代码留在原位置：

| 资产 | 默认位置与内容 |
| --- | --- |
| 运行入口 | `docs/dev-flow/operations/index.md`：模式、环境/服务、依赖、配置、启动/停止、核心任务、观测/恢复入口 |
| 环境/服务 runbook | `operations/runbooks/<对象>.md`：维护对象、资源/域名/存储/下游、当前约束、命令及验证；复杂时才拆分 |
| 交付/发布记录 | `operations/deliveries/<任务ID>.md`：源/产物/操作/环境版本、结果、验收及未覆盖、恢复；不可用旧结果覆盖现状 |
| 故障/恢复记录 | `operations/incidents/<事件ID>.md` 或 `operations/recovery/<演练ID>.md`：实际影响/步骤/证据、数据边界、原因与待办 |
| 演进与退役 | 复用项目 backlog/决策记录，关联实际资源变化、消费者和验证，不另建空账本 |

项目主索引关联产品/UI、架构、工程、验收和运行。模板为[运行入口](../assets/templates/operations-index.md)、[交付记录](../assets/templates/delivery-record.md)、[故障/恢复记录](../assets/templates/incident-and-recovery.md)；按需复制并填写事实，缺失项标待核验，不预填成功。项目文档遵守[共同归档协议](../../dev-flow/references/design-document-contract.md)，稳定入口指向现行资产，旧发布/事故记录按事件保留并关联替代版本。

环境与部署现状标出核验时间/来源/版本，记录只作历史证据，不是永远有效的状态。新任务恢复这些资产后查询相关实际环境；源/锁文件、配置、服务/路由、存储或外部依赖变化时定向使相关证据待复验，更新当前入口并保留旧证据。下一任务是否实际复用与“文件已写入”分别登记。

真实密钥使用项目现有管理入口，文档保存变量含义/来源；日志脱敏。`.dev-flow/` 等忽略目录仅保存本地 PID/会话、端口、缓存与临时日志，脱敏且支持长期结论的必要证据进入项目规定位置；不把临时目录当作交付包。

## 运行依赖与资源演进

明确服务/runtime、数据库/队列/外部依赖、存储持久性、资源归属/约束、现有成本或容量数据及消费者。升级、配置/资源调整按实际问题和影响实施；重要取舍交架构和有效确认，内部操作按授权自主推进。先准备兼容/恢复与验证，完成变化后重查目标版本、健康和相关业务/性能结果；更新锁文件、runbook、架构运行地图和回归。

不因存在某依赖就做全量升级，不凭一次小样本宣称容量充分；没有实际指标时登记未知和具体下一步验证。通用经验需能说明问题、适用边界、来源与实测，再形成 Skill/工具候选。

## 退役与交接

先核对对象、资源所有权、当前消费者/下游、定时任务/触发入口、域名/路由、数据保留/导出与恢复需要，明确替代入口及有效授权。完成转移后验证下游可用、必要数据可读和旧入口停止，再按范围删除或停用自有资源；共享资源有其他消费者时不能一并删除。

注销相应调度/发布入口和凭据依项目实际安排，登记残留资源、计费状态和责任者。运行索引标明退役/替代而非伪造当前可用地址，交接后续维护者可用的版本、方法与限制。归档和资源清理分别取证，不能把删除文档当作退役完成。
