# 产物版本与实际发布

用于 O02/O03。按约定交付模式取证，技术基线不指定托管厂商或强制容器化。平台操作采用项目已有入口及当期官方说明。

## 候选与产物身份

构建输入关联源提交、相关未提交文件指纹、锁文件、构建命令/工具版本、配置模式及工作目录；产物记录实际位置、摘要、平台/架构、入口与依赖。发布候选冻结后，验证结果对应同一产物；后续内容变化重新构建并更新受影响证据。制品中的提交号可能遗漏未提交源码，不能单独作为来源证明。

安装或分发交付在另一目录/约定设备操作实际包，验证必要资源齐全、路径不依赖源码副本、配置/数据目录和启动/卸载或停止方式。平台签名、更新机制等只在交付确实要求时处理。内部组件/工具源码的复用仍按 Git 复制/参考，分发交付产物不意味着建立内部 npm 发布链。

## 已确定 Web 对象的交付区别

| 对象 | 产物与运行核验 |
| --- | --- |
| React + Vite | 读取实际 build 输出目录和 base，使用对应静态服务/目标托管操作构建产物；核对资源、深链刷新、实际 API/跨域与核心任务。开发服务单独登记，`vite preview` 用于本地构建预览，不能作为生产服务承诺。[Vite 官方说明](https://vite.dev/guide/static-deploy.html) |
| Next.js 全栈 | 使用项目实际构建/生产启动或部署适配入口，核对服务端依赖、存储、环境变量时机与请求链路；浏览器公开变量在构建中固化，环境变化可能需要重建，多实例缓存/版本一致性按实际架构核验。[Next.js 自托管说明](https://nextjs.org/docs/app/guides/self-hosting) |
| Astro 纯静态 | 操作实际构建输出，核验 base、页面/资源/内容链接与约定交互；不引入虚构后端。默认输出可为 `dist`，实际以项目配置为准。[Astro 部署说明](https://docs.astro.build/en/guides/deploy/) |

已有其他工程沿用有效基线，本表不扩展其通用选型 Guide。本机静态/生产模式核验与目标托管核验分别登记。

## 发布与核验

明确用户要求的预览/生产目标、项目/环境身份、候选、配置、数据兼容、发布入口与现有权限。准备可审阅产物、目标变化、验证方式和适用[恢复安排](recovery-and-migrations.md)，保留上一有效版本。已有授权按范围执行；缺少目标或外部动作授权时只确认必要决定，继续构建与独立检查，不增加例行审批。

同一目标的共享写入有明确负责人；使用现有 CI 时核对触发条件，分支推送可能实际发布，不能把推送一概当作无副作用记录动作。先确认当前目标状态，按项目既定顺序处理发布、配置、迁移、流量切换；不在通用 Skill 发明统一云平台步骤。

记录操作 ID、时间、源/产物摘要、目标环境和结果。超时/断连/结果未知先通过操作 ID、环境版本或平台事件查询实际状态；确认未执行才按适用重试规则重试，查询不了保留未知并报告具体缺口。数据/付费/重复副作用不能用盲目重试消除不确定性。

发布后核对目标实际版本/产物标识、入口、就绪、资源/路由/配置及核心用户链路；DNS、TLS、代理、鉴权和外部依赖按实际路径核验。控制面成功与实际目标使用成功分别记录，缓存/多副本存在时核查当前用户所到版本。发送给测试当前环境/候选与范围，由测试按原用例执行[交付验收](../../dev-acceptance/references/end-to-end-and-delivery.md)。

采用[交付记录模板](../assets/templates/delivery-record.md)或项目已有发布记录，关联实测报告、问题和恢复结果；上线后观察的信号、窗口和终止条件按项目需要确定，不自动创建定时任务。
