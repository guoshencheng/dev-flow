# Git 基线、候选、保存与集成

此方法支持独立 Git 任务，也支持流程安排的代码保存/集成。读取项目分支策略、保护规则及本次动作授权；业务完成判断由当前任务或流程负责，不因一次 Git 操作增加完整产品设计/验收门槛。

## 开始：核对真实基线与工作位置

使用 `git status --short`、`git branch --show-current`、`git rev-parse HEAD`、`git worktree list` 定位当前状态，核对暂存/未暂存/未跟踪文件与目标分支。任务开始时已有相关未提交内容需保存差异或指纹，才能区分初始修改、本次修改和他人工作。

复用已属于本任务的分支、PR 或 worktree。独立任务按项目约定建立任务分支；单任务顺序工作可沿用 checkout，需要保留其他任务修改、并行候选/服务或旧新回归时选择 worktree。不要把远端默认分支自动当成正确起点；需要新远端状态时 fetch 后核对差异。

新 worktree 不自动携带当前未提交内容；需带入时采用明确提交/补丁或宿主支持方式，记录来源。不默认 stash、reset 或覆盖原工作区。宿主有受管工具时优先使用并按其生命周期清理。分支前缀按当前用户/项目/宿主约定，Codex 无其他约定可用 `codex/<任务>`。

worktree 只隔离文件；数据库、端口、缓存、外部环境与副作用另行核对。真实密钥沿用项目安全入口，不放进提交或复制到版本化成果。

## 获取完整评审候选

记录任务开始基线与最终候选，用 `git diff <基线> <候选>` 取得全部提交的合计差异；另核对 `git diff`、`git diff --cached` 与 `git ls-files --others --exclude-standard`。多提交任务只看最后一次提交会遗漏内容。候选含相关未提交差异时保存路径/指纹，明确检查期间写入者。

diff 是定位工具；原始要求、设计、检查与缺口随评审包交专业职责。[架构评审方法](../../../agents/references/architecture/review-and-closeout.md)负责实现质量，[意见处理](../../../agents/references/engineering/review-feedback.md)负责作者回应，Git 不裁定需求符合性。基线未知时补定位，不能声称完整覆盖。

## 保存相关成果

检查实际差异、暂存内容、必要新文件和忽略规则，逐文件或明确片段选择本任务成果。已有暂存区可能含其他工作，不能直接整体提交；同文件混合修改无法归属时保留并交接，不用清空工作区制造干净状态。

按任务/项目约定形成本地提交；需要保存未完成进度时明确 WIP/待验身份，不因此报告可合并。收尾流程已安排本地保存时不逐文件重复确认。已有提交完整覆盖成果时引用即可，不生成空提交。

提交后核对真实文件/树与被验证候选，检查 hook 是否改文件或留下新差异；发生影响时定向复验并保存，不跳过检查或修改预期使提交成功。交接未保存内容及原因。

## 集成与冲突

1. 核对目标分支当前提交与项目合并策略，以及本次集成动作授权和所需检查状态。必需检查来自当前任务，Git 不自行增加另一套审批。
2. 个人未共享分支可按约定 rebase；共享分支优先不改写他人历史的 merge。确认真实基线后按依赖集成，冲突处理依据原要求与实际契约，保留双方有效行为。
3. 检查解决后的完整 diff，执行受影响行为、契约和必要构建/集成检查。单分支通过不等于组合通过。
4. 按策略使用 squash、merge 或 fast-forward；推送、PR、合并及自动发布副作用按已有具体授权执行。不要默认强推。PR 描述提供问题、结果和相关验证，不复制全过程日志。
5. 核对目标实际包含预期提交/树及 CI，交接产物/部署关系。合并成功不等于部署或业务交付完成。

## 代码收尾与资源交接

本节执行流程交来的 Git 保存与资源操作；“开始收尾”的整体编排见[流程收尾](../../dev-flow/references/closeout.md)。检查冲突标记、临时探针、锁文件/生成物一致性及本任务相关修改，不借收尾重构无关模块。

worktree/分支仅在独有成果已保存或集成、未交接修改明确、必要忽略资料/证据已保留、所属服务不再需要时清理。受管 worktree 使用宿主归档入口；不要删除未知归属目录或仍需用户预览的环境。未推送成果与未跟踪内容也需核对，不能仅看工作区干净。

在已有交接中返回：开始基线、目标/任务分支、工作目录、最终候选/提交、完整差异范围、检查结果、推送/PR/合并实际状态、残余修改与保留服务。不另建重复 Git 台账。
