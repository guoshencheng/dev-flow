# 组件源码持续复用

## React 组件如何持续沉淀

共享源码与 Skill 一起维护在本 Git 仓库的[React 工作区](../assets/react-workspace/README.md)，分别保存 B 端 antd 组合与 C 端 Web shadcn/ui 源码。两套应用示例分别运行，保持设计体系和样式边界；内部工作区名称只用于仓库组织和预览。

共享目录分别标注自有组合、上游源码和直接使用的第三方依赖。当前 SelectionSummary 是 antd 组件组合，ActionCard 是 shadcn/ui 组件组合，Button/Card 来自官方 shadcn/ui 源码并保留许可。antd 基础控件继续通过公开依赖直接使用；“复制源码”指自有组合或许可允许的参考源码，不要求把 antd 基础库复制到项目。

直接使用基础库 → 在项目中形成必要组合 → 核验适用条件、代表场景与边界 → 提取共享组件 → 在下一项目核验复用。项目特有接口、权限、业务文案和流程政策由调用方注入，不进入通用组件的隐式行为。

每个共享组件保留：名称与用途、Props/状态契约、适用与不适用条件、基础库和来源、真实采用项目或隔离案例、运行示例、验证方式、版本与变化影响。组件清单区分“隔离示例已验证”和“实际项目已复用”，不得把初始化组件库写成已经成熟。

同一底层能力已有 antd/shadcn 组件时直接复用；自建前说明具体缺口。复用需要额外业务状态时优先组合或受控属性，保留基础组件行为。破坏兼容的变更记录迁移方法，影响项目重新核验。产品维护语义和场景，视觉维护呈现与 Tokens，研发维护实现与依赖，测试维护实际检查证据；当前尚无专门职责时由执行者明确承担。

## Git 与共享方式

源码、组件清单、来源、示例和依赖锁文件进入 Git。共享组件默认直接复制到项目，或作为参考在项目现有组件体系中实现；复制后的源码由项目直接维护和快速迭代。现有基础组件、工具与主题优先复用，必要支持文件和上游许可随源码保留。

采用记录保存来源文件、提交或实际源码哈希、项目路径、项目差异与验证。当前源码有未提交修改时记录基准提交和实际文件哈希，可以立即复制，不以包发布为前置。项目依赖 antd、shadcn 所需的公开基础库，而自有组合从项目本地导入。

共享源码后续变化按需要比较、合并到项目，保留项目定制；项目验证过的通用改进再回收到共享仓库。源码复制工具核验完整文件集，保留已有不同内容的文件。`node_modules` 与构建目录不提交。

从当前安装包或源码仓库定位共享源码，记录来源提交或文件哈希；跨机器按实际 Git 同步结果核验可用性，安装成功与项目采用分别取证。

组件选择通过随包[预览目录与接入指南](component-preview-and-reuse.md)完成：提供 B/C 独立预览入口、状态示例、本地导入的使用代码、完整源码文件集和候选记录；Agent 可按组件 ID 查询或复制。已明确的组件直接使用，候选与项目实际采用分别登记。

具体启动、复制和接入见[工作区说明](../assets/react-workspace/README.md)。采用 Vite 目录、类型与构建检查，以及独立项目源码副本验证；更复杂的组件展示或源码分发按实际需要建设。
