# 功能展开示例：收藏资料

以下是虚构需求的表达示例，数值与业务选择仅用于说明写法，不是其他项目的默认规则。

## 核心对象与本次功能

读者希望保存以后要看的资料，并能再次找到。本例只提供个人收藏及查找；不含共享收藏夹、推荐算法或旧系统收藏导入。这是示例范围，不是所有收藏功能的默认边界。

| 对象 | 承载什么 | 不应混淆什么 |
| --- | --- | --- |
| 资料 | 可打开的原内容 | 取消收藏不删除资料 |
| 收藏 | 某读者保存某资料的关系及收藏时间 | 同一资料可被不同读者独立收藏 |

| 使用位置/入口 | 功能 | 完成后的结果 |
| --- | --- | --- |
| 资料详情 | 收藏与取消收藏 | 状态保存且刷新可读回 |
| 个人页的收藏列表 | 查找已收藏资料 | 可按收藏顺序找到并打开资料 |

小任务不需要这两张导航表；直接从下面的功能段落开始即可。

## 收藏与取消收藏

读者在资料详情点击“收藏”，成功后按钮显示“已收藏”，资料出现在个人收藏列表中。同一次收藏请求重复提交不增加重复条目；刷新详情仍显示已收藏。只有登录读者可以操作，未登录时点击入口提示先登录，服务端同样拒绝未登录操作。

再次点击“已收藏”即取消，成功后恢复“收藏”并从列表移除。请求失败时保留原显示并提供重试；结果未知时先重新读取收藏状态，再允许继续操作，避免向用户声称动作尚未生效。

验收例子：假设读者尚未收藏某资料，点击收藏并刷新后，详情显示已收藏，列表中只有一条该资料；取消后刷新列表，该资料消失。未登录读者不能通过直接请求新增收藏。

## 查找已收藏的资料

读者从个人页进入收藏列表，点击资料标题打开详情。本例的候选排序为按最近收藏时间从新到旧，见文末取舍；不将它标为用户已确认。没有收藏时显示空态和返回资料浏览入口。加载失败时显示重试入口，不把加载失败显示为空列表。

验收例子：若采用该排序，假设先收藏甲、后收藏乙，重新进入列表时乙排在甲前；列表读取失败时看到错误与重试，恢复后仍可看到两条资料。

## 候选细化与后续边界

假设用户只明确要求“收藏后能再次找到”，作者推荐默认按最近收藏排序。该推荐在被接受前应标为候选，不能声称用户已选择排序方式；若产品规则已确定则直接引用，不重复请求确认。本例无实际用户确认或实现结果。
