# 产品规格内容与权威来源

本职责维护用户任务、流程、原型、限制、透出与业务规则；项目目录、状态和归档采用[共同文档协议](../../document-management/references/document-contract.md)。按本次影响裁剪，已有有效规则直接引用，不额外制造人工审批。

## 规格必须能说明的细节

正文按功能和用户任务展开。多功能先用核心对象及区别、入口/功能/结果导航帮助理解，再以具体任务为标题，说明使用者、入口、操作和结果，在相关步骤解释字段、权限、计算、限制和恢复；假设验收例子就近描述。小功能可几段表达，大功能按实际任务分节，不强制旧六章、统一小标题或全局规则/验收大表。下表是完整性检查提示，不是正文目录，不要求每项都额外建文件。无关条件标明不适用；未知规则标为待决，不编造默认值。

| 内容 | 需要明确 |
| --- | --- |
| 用户任务与范围 | 用户、业务对象、入口、目标结果、相关场景及本次边界 |
| 功能原型 | PT ID、源码路径/提交、当前方案、场景入口、模拟范围；关联所表达的规则和验收 |
| 使用限制 | 实际数量、大小、频率、配额、有效期、并发或平台限制；计数口径、边界值与超限反馈 |
| 功能透出 | 谁在什么对象、状态、环境或配置下看到入口、字段、操作和结果；隐藏/禁用/只读如何选择及解释 |
| 可执行条件 | 权限、前置状态、配额或依赖；界面可见性与服务端授权分别说明 |
| 具体逻辑 | 输入和默认、校验、计算/排序/筛选、动作、状态变化、保存/生效时点、刷新读回、输出和必要接口依据；配置功能有实际选择与维护入口 |
| 相关异常与恢复 | 错误反馈、数据保留、取消、重试、部分失败、结果未知及真实恢复契约 |
| 验收与来源 | 可定位的功能段落及正常和边界/拒绝/恢复场景；已有稳定 RULE/AC ID 保留，新增按需，用户决定、接口或代码来源及有效版本 |

功能叙述使用可判断的条件和结果，例如“角色为编辑者且对象为草稿时显示发布操作；配额已耗尽时按钮禁用并解释原因”。隐藏按钮不证明后端拒绝已经实现。将数值限制、透出条件和业务算法落实到就近的可观察验收预期；必要时用追溯附录关联编号、正文位置、来源和验证入口，不另建重复业务规范。相关变更保留已有编号并列出受影响原型、实现和回归。

用户原话、作者解释与推荐分别表达；已明确的决定不重新列为待确认。未来配置、当前生效与历史撤回有不同语义时分别说明，不能通过推导扩建未要求的能力。旧系统存量/接口兼容、新系统后续历史和原数据保留分别判断；不从现有旧代码推定必须迁移，也不从“不接旧存量”推定可以删除现有数据。具体技术选择交研发设计，正文不被旧表名或当前实现锁定。
