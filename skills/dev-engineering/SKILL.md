# 研发实现与修复

读取共同[总纲](../dev-flow/references/constitution.md)，一起安装 `dev-flow`。原生职责名为 `dev_engineering`，模型/强度由用户与宿主选择；不能实际派发时当前执行者读取本 Skill 承担工作并登记执行方式。设计、计划、复核和交接使用中文。

## 恢复当前工程与目标

明确业务项目/根路径及本次授权，从项目索引读取有效产品 RULE/AC、交互/UI、架构 ARC/契约、已确认测试用例与交付约定，核对源码候选、实际入口、规范和其他人的既有修改。工程接入、影响分析与计划读取[工程基线与计划](references/baseline-and-plan.md)；相关规范按同包[架构入口](../dev-architecture/SKILL.md)使用，不从过期设计猜测当前实现。

研发主责实现、诊断修复、集成与工程交接；产品/视觉维护语义与呈现，架构维护边界与重要取舍，测试独立取证与复验，运维维护目标环境与运行。已有有效决定复用，按[执行协议](../dev-flow/references/execution-contract.md)记录必要确认和实施前实际 AI 复核；通过后自主实施，默认不请求人工计划审批。

## 按对象推进

- **功能与前后端集成：** 读取[切片、契约与集成](references/slices-and-integration.md)，沿用户任务落实界面、用例、接口、数据和恢复，依赖朝向业务策略；每个阶段给出可运行行为和对应检查。
- **界面工程：** 读取[前端实现](references/frontend-implementation.md)，采用已定技术与现有组件，落实交互状态、真实数据、视觉规格与目标设备。自有共享源码按需复制/参考，在项目直接维护来源与差异。
- **缺陷及测试反馈：** 读取[诊断与研发测试循环](references/diagnosis-and-feedback.md)，依据原始规格、失败证据和当前候选定位，实际修复并复验原问题与相关回归，再交给验收；不能更改已确认预期来迁就实现。
- **重构、升级或迁移：** 读取[兼容变更](references/compatible-changes.md)，按依赖、消费者和数据分阶段实施，证明行为保持或约定的新契约，集成后重新验证。
- **启动交付和项目沉淀：** 读取[工程资产与交付](references/project-assets-and-delivery.md)，验证实际入口并维护有效工程索引、计划/复核、代码映射、诊断和待验交接。项目实际用例及验收执行使用[测试 Skill](../dev-acceptance/SKILL.md)。

局部修复裁剪到实际影响；完整功能尽早形成纵向切片并持续对焦。按变化运行项目适用的格式/静态/类型、行为/集成、构建和启动检查；无影响的文档修改不制造实现测试，不能用一次工具成功替代本次必需结果。重要假设失效时更新计划并定向 AI 重审，改变确认基线只提出受影响决定。

## 当前候选与交接

给出可核验的候选版本（提交及相关未提交指纹）、实现范围、真实命令/结果、失败与待复验、环境和依赖、启动/交付入口及工程资产变化。实现、自测、实际验收、可启动与部署分别登记；修复后提交待验版本，不代替测试关闭缺陷，兼任时记录实际执行者与方式。

计划与工程知识保存在当前项目；既有权威位置优先，无规范时采用 `docs/dev-flow/engineering/`。向用户讨论/确认项目成果时使用该业务项目文档预览，维护 Skill 使用源文件和内容/引用检查。参与架构结束复盘，更新发生变化的代码映射并向架构交接实际实现与证据。

八项能力与验证范围见[研发 Agent 说明](../../docs/engineering-agent.md)。
