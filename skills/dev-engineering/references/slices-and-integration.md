# 可运行切片、契约与集成

用于新功能、既有功能扩展、接口与数据实现。遵守[整洁架构](../../dev-architecture/references/clean-architecture.md)和有效项目设计，拆分依据业务变化与数据所有权。

## 从行为形成切片

切片对应能操作和验证的用户/接口任务，例如“有权限的用户提交 → 后端校验与保存 → 查询可读回 → 页面反馈与恢复”。按依赖增量实现，尽早用真实主链路暴露契约和环境问题；不把“所有界面 → 所有后端 → 最后集成”作为默认拆分。

依赖尚未就绪时，可先完成明确标识的适配/契约实验或局部模拟；登记待接入对象和替换条件。模拟页面、硬编码成功和局部测试不能交接为完整可用切片。相同候选集成时核对双方版本、地址、协议、身份、错误与数据语义。

## 落实业务、协议与存储职责

| 位置 | 本次要落实什么 |
| --- | --- |
| 领域/业务策略 | 有效规则、状态转换、不变量；不依赖 React/antd、HTTP、ORM 或外部 SDK |
| 应用用例 | 授权后的业务操作顺序、内层拥有的端口、数据与副作用协调、结果和失败语义 |
| 入口/协议适配 | 解析外部输入和身份、运行时校验、调用用例、转换契约响应；类型断言不替代实际校验 |
| 存储/外部适配 | 实现持久化和外部能力，遵守事务/重复/一致性与超时等项目要求 |
| 组合与运行入口 | 装配依赖、配置、启动和生命周期；界面消费有效契约并呈现对应状态 |

物理目录与端口形式按工程规模选用；不为局部修复强制引入全部层级。已有不理想结构先在本次范围隔离业务变化，迁移建议交架构评审，不能把目标结构写成现状。

输入校验、权限与数据结果分别落实。页面按钮隐藏不代替服务端授权；确认写入成立后才返回约定成功。接口、页面缓存/列表和重新进入的真实读回结果应一致；调用成功不证明持久化、外部副作用或事务已完成。

对本次实际涉及的事务、并发、幂等、取消、超时、重试和补偿按 ARC 落实与验证；不猜测允许重试的操作，不新增没有依据的阈值或分布式设施。共享类型/schema 优先引用项目权威定义，跨域通过公开契约。

## 集成并提供待验候选

用项目实际检查入口证明受影响规则、接口/数据、界面及架构约束。静态/类型通过分别记录；真实链路从入口操作到请求/响应、服务端结果和刷新/恢复，具体策略见[测试方法](../../dev-acceptance/references/end-to-end-and-delivery.md)。前后端分离工程核验浏览器的实际代理/CORS/Cookie/身份行为，Node API 请求成功不足以证明浏览器集成。

提交给测试的切片包含当前版本、操作入口、数据/身份准备、实现和模拟边界、对应 TC、实际自测与已知问题。集成候选重新验证必要范围，分支或切片单独通过的结果不能直接继承。
