# 重构、升级与兼容迁移

用于代码结构、依赖、协议、配置或数据演进。目标、消费者和验证范围来自实际任务及[架构契约](../../dev-architecture/references/design-and-contracts.md)，其他类型依现有项目规范，不新增通用技术栈 Guide。

## 识别变化含义

| 类型 | 主要依据与检查 |
| --- | --- |
| 行为保持的重构 | 原规则/契约与有效场景，公开接口、数据和交互保持；新结构符合实际依赖方向 |
| 依赖/框架升级 | 当前采用方式、官方兼容/迁移资料、runtime 与 peer 约束、锁文件、构建和关键消费者 |
| 接口/配置变化 | 公开契约及客户端/服务消费者、默认/错误语义、兼容阶段与部署先后 |
| 数据迁移 | 数据所有权、不变量、当前/目标 schema、读写混用期和具体恢复设计 |

先识别真实消费者与当前事实；重大版本或 API 接入查对应版本官方资料，不凭旧记忆替换入口。不因局部功能顺便升级整仓依赖、格式化所有源码或迁移框架；需要的结构调整与行为改变明确对应范围。

## 按依赖分阶段落实

有共存需求时先建立兼容适配/读写路径，再转换消费者或数据，验证后移除旧能力；简单局部重构可一次完成。每阶段明确输入候选、变更、可运行结果、检查、恢复条件和下一阶段依据。

迁移脚本按实际设计处理重复执行、部分失败、存量数据和读写竞争，重要变更先在隔离样本/适用环境演练。代码回退不自动恢复数据，破坏性清理和外部迁移依现有授权与宿主约束；未知结果先查实际状态，不直接重试。

测试工具或配置变化仍需验证原目标。新的禁用规则、忽略范围、类型断言或旧场景删除须有依据和范围，不能掩盖本次错误；保持行为的变更以原场景验收，正式改变行为按已确认新预期取证。

## 维护有效基线

集成后在当前候选运行原场景、受影响消费者及适用构建/启动检查。保存源/目标版本、变更位置、兼容结果、实际迁移/恢复证据和未覆盖项。

项目更新实际 manifest/锁文件/配置、技术与代码规范、接口消费者和运行说明；架构据源码维护现状与旧能力退役状态。可选债务交待办，不因复盘增加未经确定的全仓改造；已失效方案关联替代版本。
