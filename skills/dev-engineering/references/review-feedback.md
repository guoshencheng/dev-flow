# 实现评审意见处理

用于实际实现的评审反馈，技术方案符合性 Review 不代替最终实现检查。发起评审采用[完整实现评审](../../dev-architecture/references/retrospective-and-evolution.md)，提供原要求、有效契约、任务开始基线至最终候选的完整变更、相关未提交修改、测试证据和已知缺口；多提交任务不能只提供最后一个提交。

## 核对依据再处理

| 意见 | 动作 | 结果与关闭条件 |
| --- | --- | --- |
| 正确且具体 | 核对代码/契约与触发条件，最小修复，提交修复候选，重跑受影响测试并定向复评 | 复评及必要行为复验成立；“已修改”不等于关闭 |
| 错误建议 | 用实际代码、有效契约或实验反驳，不为服从建议制造错误修改 | 评审者核验证据后记录不成立/不采用及依据；保留原意见 |
| 模糊意见 | 澄清位置、规则、条件和期望，推进其他明确事项 | 澄清后重新分类；未澄清不能假定已处理或通过 |
| 证据不足 | 保留待验证假设、责任人与最小验证方式 | 得到证据后处理；涉及必需条件的证据缺口仍阻断完成 |

依据冲突回到原要求与有效决定，必要时交产品/架构解释业务或契约。研发不能改验收预期迁就实现。只有改变重要确认取舍或动作授权时才需要用户决定，已有授权内的诊断、修复与复验持续推进。

## 复用 tracker，闭环到候选和证据

每条意见记录编号、原意见、证据/规则、影响/优先级、处理决定及依据、责任、修复候选（无修复则说明）、复评/复验结果与状态。优先项目现有 tracker，按需采用[缺陷与复验模板](../../dev-acceptance/assets/templates/defect.md)，不再建一份评审状态账本。

行为缺陷沿用 open → awaiting-retest → closed/reopen，由验收实际复验原问题及相关回归后关闭。非行为意见记录实际澄清或证据复核、关闭者与结果；错误意见经核验后以“不成立/不采用”关闭，证据不足的意见保留待验证。阻断项不能仅凭修复说明或自报成功关闭。

源码或相关配置变化后，受影响测试重新执行；定向复评修复候选、原意见及相邻契约，必要时扩大覆盖。新发现保留编号/关联，不静默替换旧结论。交接区分需求符合性和实现质量结论，明确未关闭项、当前候选与未覆盖范围。

架构承担相关代码质量评审，产品核对业务语义，研发修复，验收复验行为；视觉/运维按实际影响参与。允许且实际能够委派时用独立上下文提供完整原始输入；受限时明确主 Agent 自查和独立性缺口，不用职责名模拟独立 Review。
