# Agent 与 Skill 重组边界评审

日期：2026-10-21。对象：[迭代规划](../docs/plans/2026-10-21-agent-skill-reorganization.md)及[迁移安排](../docs/plans/2026-10-21-agent-skill-reorganization/migration-plan.md)。当前插件基线 0.3.0。类型：规划边界 Review，不是实现或安装验收。

## 执行方式与范围

作者：主 Agent。独立评审：实际 subagent `/root/boundary_review`，模型 gpt-6-sol，推理 medium，使用必要任务包而非完整聊天继承。只读检查规划、相关 Skills、Agent 入口和生成器；未改代码、未运行安装或行为验收。

评审结论：三层边界及缩窄后的操作候选基本合理。重点防止产品规格与验收用例、流程门槛与文档归档、评审执行与专业判断之间重复维护权威规则。首轮 Skill 数量不应成为硬性完成条件。

## 发现与处理

| ID | 评审意见 | 本轮处理与后续验证 |
| --- | --- | --- |
| B01 | 产品规格和正式用例需要不同输入输出，不能互写权威预期；正式 TC 不得因拆分提前成为实施门槛 | 明确 product-specification 输出流程、状态、RULE/AC；acceptance-case-design 据有效规则形成 TC；正式时点留流程。实施后做角色与边界案例 |
| B02 | subagent 的执行信息、专业结论和整体完成不能混为一体 | 流程规定所需职责/独立性，subagent 负责派发及执行边界核验，专业职责裁定成果；收回结果不自动通过 |
| B03 | 文档管理可以处理有效性状态，但不能判断专业基线是否正确 | 专业职责提供有效结论，文档管理组织保存；阶段失效和结束条件留流程。收尾场景待实施后验证 |
| B04 | 完整评审不能在移除宽泛架构 Skill 时丢失，也不能并入一般诊断 | 架构参考保留实现质量及技术收尾清单，产品保留业务符合性，研发保留意见处理；Git 获取完整 diff，验收负责行为复验，流程保留时点和独立性 |
| B05 | 产品可用性、视觉方向、架构规范、研发兼容、测试证据、运维恢复等可能没有新 Skill 对应，却仍是核心职责能力 | 迁移清单保留相应职责提示词与长篇参考去向，不因未独立建 Skill 删除能力 |
| B06 | defect-diagnosis 与 regression-verification 的不同调用需要案例证明 | 前者未知根因，后者已知目标及保护有效性；触发和产出已分别登记，真实案例待实现后执行 |
| B07 | release-and-recovery 可能仍偏宽，发布与恢复的授权/工具/证据不同 | 首轮保留一个入口，按发布与恢复 reference 分路由并分别声明前置，真实调用显示独立再拆；不因同 Skill 自动扩大操作授权 |
| B08 | product-specification 可先在内部区分流程/状态与规则/AC，避免提前增加入口 | 保留一个操作入口，按需分参考；价值取舍仍由产品负责；以实际任务评估是否再拆 |
| B09 | Agent 专业参考与资产必须被打包并能从生成入口定位，生成器不能产生第二维护源 | 记录 agents/prompts 为唯一职责源，references/assets 随包；生成物不得手工维护。补入路径、资源和候选清单验证要求 |
| B10 | 通用 UI/技术默认不能在多个职责复制，实例事实也不能成为身份规则 | 架构技术基线和视觉 UI 基准各保持唯一专业参考，项目具体版本/例外留项目 |

以上“处理”表示规划已明确归属与后续检查，不表示重组代码或行为验证通过。原始评审曾指出迁移清单链接瞬时不存在；清单现已补齐，主 Agent 已核对链接。

同一独立评审者对最终三份文档再次定向只读复核，结论为规划可通过：57 份来源参考无重复且覆盖完整，8 个现行入口与 138 个跟踪资产/工具的计数及目录族求和一致，16 个拟定 Skill 的数量和未实施状态一致，三份文档的相对链接均有效。发现的非阻断措辞已修正：图中 subagent 的“集成”改为“结果收集”，避免误解为代码合并或专业结论裁定。该定向复核不扩大到实现、行为或安装验收。

## 尚需实施验证的事项

- 十一个操作候选是否都有实际独立触发，尤其规格表达、诊断/回归、发布/恢复。
- 六职责提示词单独加载时，专业判断与交接是否充分；不能只验证角色名或生成文件存在。
- 新目录的引用、模板和工具路径、独立拷贝时必需资源以及隔离安装检查。
- Codex/Kimi 各自真实能力发现与派发；现有 Codex TOML 仍只是参考入口，不得将其存在登记为原生角色可用。

本次不新增授权，不创建监控或通知实例，不将只读边界评审折算为独立实现 Review、工具测试、验收或安装成功。
