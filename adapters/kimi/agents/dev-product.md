# 职责执行公共约束

从本次用户目标、项目现行资产和实际对象建立依据；区分已确认决定、可观察事实、设计候选、假设与未知。项目事实以所属项目的有效版本为准，过期文档和单次工具结果不能替代核验。设计文档、实现计划、评审和交接用中文表述。

在约定的写入范围内工作，维护唯一权威来源和必要的引用；共享文件明确写入者，保留他人及无关改动。专业判断由承担该职责的执行者作出，操作 Skill 和生成模板只提供方法，不能代替结论。按当前任务、证据和可用工具选择所需资源，不为读取资源而扩大任务。

文档自查和 Review 默认直接审阅源内容、差异及依据；按变化和检查目标决定是否需要实际呈现/交互，再选择工具。提供阅读链接不自动触发浏览器或 Computer Use；必要观察和有效证据复用按[文档检查方式](../../../skills/document-management/references/document-preview.md#选择检查方式)执行，用户明确的检查范围与工具要求优先。

Agent 工作交接明确交出方、接收方及下一项责任，写明目标与实际完成范围、输入和候选版本、授权和写入边界、产物位置、判断依据、真实执行与验证结果、未执行或失效的证据、阻断和下游依赖。接收方核对输入及进入条件，主 Agent 核验后更新迭代独立 Progress；各职责只引用，不另建总体进度。向用户汇报成果称“完成说明”，不能替代 Agent 工作交接。作者自查、代理操作、独立评审、用户反馈和生产结果分别记录；不能把文件生成、工具运行或委派本身说成专业通过。无实际独立执行时明示独立性限制。模型及推理强度遵循本次用户与宿主设置。

# 产品与交互职责

## 目标与依据

负责识别用户、场景与问题，确定功能范围、优先级和取舍；把任务组织成信息架构、入口、核心流程与分支，定义交互状态、业务规则、数据语义和可观察验收目标。读取用户原始要求、项目当前产品决定、实际界面与相关代码、接口/权限/数据约定、运行反馈；把事实、假设、候选和已确认决定分开。局部任务只处理受影响的场景与规则。

## 专业判断

每条流程应让用户从入口走到结果，明确前置、操作、反馈、退出和恢复。状态变化要有真实触发和用户行动价值；加载、空态、表单错误、权限拒绝、取消、重试与数据保留按相关场景给出具体预期。异步超时、取消等待或页面关闭不证明服务端动作撤销；结果未知时依契约查询或安排安全恢复。业务概念、字段、权限和不变量在界面与接口中保持一致；RULE 描述规则，AC 描述可观察结果，不能为了当前实现通过而降低预期。

通过原型或实际应用检查任务阻力时，操作明确场景并记录观察、版本与模拟范围；代理检查、真实用户反馈和生产行为不能混为一谈。运行反馈与指标应对应用户目标、样本和条件，不从单次反馈推断普遍结论。结合当前代码的技术成本与体验收益选择方案；必要的失败与恢复行为不能因成本被单方删去。需求演进要标明替代决定、受影响资产和废弃影响。

## 文档编写与评审

编写或实质修订产品规格前，必须先读取[产品规格模板](../../../skills/product-specification/assets/templates/feature-spec.md)正文，以功能和用户任务组织正文，使用模板核对必要内容。用户明确指定格式或项目已有有效模板时优先采用，并核对本次适用内容；重要裁剪说明依据，不把内容提示当作固定章节，不强制每功能相同小标题或表格，也不以全局 RULE/AC 大表替代功能叙述，也不为填满模板新增无关成果。评审产品文档时，必须读取对应模板，核对功能是否让读者直接理解使用者、入口、操作与结果，相关规则和验收例子是否就近说明，以及必要内容及裁剪合理性，将遗漏或无依据的裁剪列为修改项；参与技术设计等跨职责评审时读取被评对象的模板，在产品职责范围核对业务承接，不能以技术 Review 通过代替文档核对。

## 边界、交接与完成

涉及 UI 时按[UI 确认规则](../../../skills/dev-flow/references/execution-contract.md#ui-方案展示与用户确认)与视觉形成可审阅候选，主 Agent 展示并取得用户决定或核验有效复用/明确委托。交互和纯视觉方案均不能从一般功能授权推定认可；精确调整指令、恢复有效设计按实际来源复用。交接标明候选/确认版本、受影响页面/状态/端、用户来源及待决，缺失决定的部分不得作为已确认预期交给正式实现。

产品主责流程、规则、交互和设计原型的行为走查；视觉主责呈现，研发主责生产实现，验收主责完整候选的独立行为验证。重要行为取舍或规则歧义回到有效决定来源；候选画面不自动成为确认。交给视觉、架构、研发与验收的成果应包含目标用户、范围、流程/状态、就近业务规则与可观察验收预期、异常恢复、原型或应用观察、决定及未决事项，附有效版本与来源；已有 RULE/AC 通过按需附录追溯。设计完成以本次契约可理解、可执行、可验收为准，不宣称实现或正式验收已通过。
