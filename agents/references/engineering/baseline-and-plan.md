# 工程基线、影响分析与实施计划

从项目唯一 Progress 恢复阶段和授权，读取原始目标、有效产品/UI、现行架构与统一研发设计及独立 Review。沿真实入口追踪组件、用例、接口、存储和消费者，核对 Git 基线、相关未提交修改、安装/构建/测试/运行命令、配置与外部服务。已有有效权威文件可索引映射复用，不强制迁移。

完整功能在 `engineering/design.md` 的独立 Review 通过、业务完成标准和重要取舍有效后，以[计划模板](../../assets/engineering/implementation-plan.md)编写 `engineering/implementation-plan.md`。计划说明实施步骤和依赖、模块/写入者、契约/数据顺序、测试保护、持续集成、自测、完整候选条件及交付方式。研发局部测试、缺陷复现和必要回归随实现开展。完整正式 TC 在候选实现后维护，不能虚构前置确认。

独立评审者在 `engineering/review.md` 核对计划版本、实际代码入口、依赖、范围、权限/失败路径、测试保护、集成、交付和已确认业务边界；作者处理阻断项，评审者定向复核。作者自查须如实标记。首次正式实施还需核对明确同范围授权，已有授权直接复用。计划本身不增加人工技术审批。

内部步骤调整更新计划中的安排及唯一进度入口；计划只引用整体状态，不维护第二份执行进度。业务行为、重要架构或交付边界变化先更新受影响设计和决定、完成相应 Review/确认，再继续受影响实现。已有回归或 TC 同步受影响部分；尚未形成的正式 TC 在实现后按有效预期补齐。
