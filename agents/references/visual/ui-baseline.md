# UI 技术栈与共享组件约定

版本：0.7。更新日期：2026-10-11。来源：用户明确指定的技术、设计和源码复用方向。本次补齐迭代仅记 UI 增量、多端/规范独立维护、总览组合与移动端屏幕尺寸容器。视觉主责 UI 设计体系、组件和共享目录，架构维护技术基线，研发协作实现/依赖；此约定供产品、视觉、研发和测试共同使用，不因共享调用归入流程层；模型与推理强度仍由任务调用方和宿主选择。

## 技术与设计基准

| 对象 | 本体系要求 |
| --- | --- |
| 新建 Web 原型、设计稿工程 | 默认 Vite + React + TypeScript，按页面/业务模块/共享组件/场景组织，实际启动并在浏览器查看；后续任务持续修改同一有效工程 |
| 迭代与现行 UI 资产 | 规范、各端页面/组件规格与源码独立持续维护；迭代引用版本与设计增量，不重写完整 UI 文件 |
| 多端与整合展示 | 各端独立页面或视图组件，由同一总览引用并组合呈现；设计规范独立维护并有对应展示模块 |
| 移动端展示 | 外层尺寸容器提供明确屏幕宽高与内部滚动；默认只模拟屏幕尺寸，保持实际内容与布局边界 |
| B 端 | 使用 Ant Design 的设计规范；尽可能直接使用 antd 组件，再通过组件组合、公开 API 和主题 Tokens 扩展 |
| C 端 Web | 优先基于 shadcn/ui，复用其源码组件与主题约定，按产品定位调整呈现 |
| 其他 C 端应用 | 实施前先浏览网上的同类产品、相邻任务和目标平台规范，记录参考与适用判断，再开展设计与研发；React 在平台适用时优先 |

已有项目继续复用有效工程入口和开发服务，新建独立原型采用上述默认。React 是优先选择；本轮局部工作不自动扩展为整个项目的技术栈迁移。用户本次指定或现行工程与默认冲突时说明具体差异、可行方案与采用理由，保留用户最新要求的优先级。

设计稿源码、主题/组件、现行页面规格和设计规范属于项目可复用资产，分别维护，由总览组合展示；迭代文档只记录引用、增量和确认版本。详细的模块/多端边界、尺寸容器及复验采用[设计系统与页面](../../../skills/react-prototyping/references/multi-device-preview.md#原型与工程复用)，文档权威位置采用[视觉资产协议](../../../skills/document-management/references/professional-assets.md#视觉)；不把“每次形成设计成果”解释为每次新建工程、重写整页或完整 UI 规格。

B 端从 antd 的 Form、Table、Modal、Drawer、Select、Button、反馈和布局组件中选择合适模式。优先直接导入，不为改名字而包装全部基础控件。扩展用于补充有复用价值的组合、状态或领域展示；先用 ConfigProvider、主题 Token、公开插槽和属性，避免依赖内部 DOM 或覆盖全局样式。[Ant Design 与 Vite](https://ant.design/docs/react/use-with-vite/)、[主题定制](https://ant.design/docs/react/customize-theme/)

先核验项目已有有效组件、主题和实际 antd 版本，再参考 Ant Design 官方组件、设计模式和示例；现成组件能满足时直接使用。需要组合时评估项目已有实现和本仓库共享源码，只有仍有具体缺口才自建，并说明缺口。随包目录是共享组合与参考源码的补充，选型范围包含官方完整组件体系。

B 端组件选型、API、主题或实现需要专业支持时，读取[Ant Design 能力联用](../../../skills/component-reuse/references/ant-design-capabilities.md)：按需联合官方 `antd` Skill、CLI 或已连接 MCP，缺失时在当前任务授权范围内自主接入；官方文档可作为直接核验入口。产品、视觉、研发和测试共享该能力，分别承担交互、呈现、实现与验收。

C 端 Web 的 shadcn/ui 组件源码属于项目可维护资产：记录原始来源、采用版本、修改原因与实际依赖，调整时保留键盘、焦点、禁用与可访问名称等行为。组件基底、布局、主题与业务规则分别管理。[shadcn/ui 的 Vite 接入](https://ui.shadcn.com/docs/installation/vite)、[Monorepo 方式](https://ui.shadcn.com/docs/monorepo)

其他 C 端应用的研究遵循[参考研究协议](../../../skills/product-specification/references/reference-research.md)。外部参考与当前项目有关：写明任务、平台、入口/操作/反馈、可借鉴机制和不适用条件。已有项目参考可以复用，但核验其来源与当前有效性；无法浏览时如实提交研究缺口，不能将未经研究的候选标为参考已完成。

组件检索、预览与源码接入见[组件复用 Skill](../../../skills/component-reuse/SKILL.md)。该基准由视觉维护，项目实际版本与例外保存在项目。
