# 视觉规格内容与权威来源

视觉主责呈现、设计系统、Tokens、组件与实际渲染；产品主责用户任务、透出、交互语义和业务规则。项目目录、状态和归档采用[共同文档协议](../../../skills/document-management/references/document-contract.md)，按本次影响裁剪。

## 规格最低内容

设计规范、页面规格、组件契约和迭代变化分别维护，权威位置采用[视觉资产协议](../../../skills/document-management/references/professional-assets.md#视觉)。现行页面/组件规格在项目级原位更新并由 Git 追溯；迭代仅引用基线、资产与变更，不要求重写完整 UI 文件。设计规范独立保存，页面与展示总览引用实际主题、组件和规范来源，不各自复制一份。

视觉规格引用输入产品版本、相关 RULE/AC、当前设计系统和实际组件。记录布局与信息层级、字体/间距/颜色/尺寸、组件选择、必要状态呈现、目标窗口/内容变化、焦点与相关动效；Tokens 指向实际代码或 ConfigProvider 的权威来源。

候选确认前记录技术执行者基于现有模块、组件、接口及状态管理提供的入口/形式成本反馈，视觉回应每项状态的真实触发、用户操作价值和必要性，关联产品的业务判断及修订版本。可合并无用状态，保留错误、权限、等待及恢复等必要呈现；涉及确认过的行为变化时引用用户对受影响部分的决定。

涉及多端时标明各端的页面/视图源码与规格、共享范围、端特有布局、独立入口和总览组合；移动端给出尺寸容器位置及内部视口宽高，模拟范围默认只到屏幕尺寸。设计总览只整合引用，不成为另一套页面源码或规范权威位置。

关联可预览页面/MDX/原型及对应截图、浏览器/尺寸/数据/状态/源码版本，分别记录已检查和未覆盖内容。只形成方案时标为候选；检查过实际界面才能登记视觉验收。视觉改变若影响可见性、操作流程或业务规则，回到产品规格共同更新。
