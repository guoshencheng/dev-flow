# 〈功能名称〉独立 Review

关联研发设计（项目内实际链接：`engineering/design.md`）与唯一整体进度入口：〈实际链接、范围及版本〉。本文件由〈唯一整合写入者〉维护；各职责评审者对自己的发现和复核结论负责。评审对象各自绑定版本，设计通过不代表计划或代码通过。新增轮次时追加记录，保留此前对象、发现、修订及结论；索引只指向当前有效轮次。尚未执行的阶段写“未评审”，不得预填通过。每轮使用下方同一记录单元，按对象裁剪检查项，避免重复整套说明。

## 当前有效记录索引

- 产品/UI 候选的技术反馈：[二、设计期技术反馈](#二设计期技术反馈) · 〈当前轮次锚点或未评审；对象版本、结论〉。
- 统一研发设计 Review：[三、研发设计 Review](#三研发设计-review) · 〈当前轮次锚点或未评审；对象版本、结论〉。
- 实施计划复核：[四、实施计划复核](#四实施计划复核) · 〈当前轮次锚点或未评审；计划版本、结论〉。
- 完整实现 Review：[五、完整实现 Review](#五完整实现-review) · 〈当前轮次锚点或未评审；候选版本、结论〉。

〈形成实际轮次后把索引链接指向该轮次的稳定锚点，例如 `#plan-r1`；对象变化使结论失效时在索引标待复核并追加新轮次，不覆盖原记录。主设计只引用本文件有效版本、状态与简短结论；正式 TC 的独立 Review 引用验收原记录。〉

## 一、每轮记录单元

〈以下字段复制到第二至第五节需要的每一轮，删除未发生的空轮次；评审前仅在索引标未评审。稳定锚点用阶段及轮次命名，如 `feedback-r1`、`design-r2`、`plan-r1`、`implementation-r1`，后续不得重用或改名。〉

<a id="〈阶段-r轮次〉"></a>
### 〈轮次编号：对象版本与日期〉

- **对象与版本：**〈具体产品/UI 候选、研发设计、实施计划或完整实现；实现填写任务开始基线、最终候选、相关未提交内容及指纹〉。
- **输入与覆盖：**〈实际读取的原始业务要求、产品/UI、架构约束、设计、计划、已有回归/正式用例及代码版本；实际检查范围、未覆盖项〉。
- **执行者与独立性：**〈姓名/职责；是否参与对象编写；独立上下文评审或主 Agent 自查，如实记录〉。
- **评审时间：**〈日期与时间〉。
- **结论：**〈通过 / 修改后复核 / 阻断 / 待验证，并用一句话说明依据；未执行不建立此轮〉。

**发现与处理：**〈逐条写问题 ID、具体位置与事实、影响及有效依据、可执行修改要求、作者修订位置和版本或不采纳依据；没有发现时写明检查范围与成立依据。多职责意见注明提出者，复杂问题可链接现有 tracker，勿复制全文。〉

**定向复核与结论变更：**〈复核者、时间、修订候选、实际检查和结果；行为问题关联验收复验。修订/复核发生在下一轮时追加下一轮并引用本轮问题 ID，不用“已修改”关闭阻断项。〉

## 二、设计期技术反馈

〈在产品/UI 候选形成期间记录研发/架构对实际代码、组件、接口、状态和数据链路的检查。比较不同功能位置或交互形式的改动范围、复用、成本和维护影响；争议状态写真实触发、用户价值、操作差异与建议，并记录产品/UI 的处理。每次候选或检查范围变化按第一节格式追加轮次。〉

## 三、研发设计 Review

〈独立架构执行者检查统一设计的业务链路、模块职责、依赖、接口/数据、权限、兼容与恢复；产品/UI 核对原目标、行为和呈现承接。不同执行者在同一候选上的意见可由唯一写入者整合，但分别注明执行者、范围和结论；设计修订后追加定向复核轮次。按第一节格式记录。〉

## 四、实施计划复核

〈此节是[实施计划](implementation-plan.md)中“计划 AI 复核引用”的固定链接目标。独立评审者核对计划所依据的设计和业务预期、实际工程入口、步骤依赖、写入边界、测试保护、持续集成、完整候选和交付可行性；核对明确实施授权的来源与范围，不把完整正式 TC 当作前置。每个计划版本及复核轮次按第一节格式追加。〉

## 五、完整实现 Review

〈完整候选形成后，独立评审者检查任务开始基线至当前候选的全部提交及相关未提交内容；分别给需求符合性与实现质量结论。产品/UI 的真实体验核对与验收用例 Review/执行、交付核验分别引用其原记录和适用版本。修复候选追加轮次及定向复评，旧候选通过不自动延续。按第一节格式记录。〉

## 六、有效结论与引用更新

〈逐对象核对索引所指轮次是否仍适用于当前版本，列出未关闭阻断、待验证和未覆盖项。更新研发设计（项目内实际链接：`engineering/design.md`）“引用与关联文档”中的本文件链接、版本、真实状态和简短结论；计划与架构技术收尾（项目内实际链接：`architecture/closeout.md`）引用各自适用的轮次。整体阶段只在唯一 Progress 维护。〉

模板中的项目成果路径在采用后替换为本项目实际相对链接；未形成的成果保持待形成，不把随包模板登记为有效Review或交付结果。
