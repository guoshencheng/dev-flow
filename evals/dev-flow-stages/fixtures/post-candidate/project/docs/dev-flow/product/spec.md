# 单个订单备注：产品规则与完成标准 v1

此文档是评测夹具的合成产品基线，确认来源见本轮 `decisions.md`。它规定正确预期；实现只提供可测试入口。

## 范围与入口

调用者通过 `order_notes` CLI 针对一个订单编号保存或读取备注。调用者有 `editor`（可编辑）或 `viewer`（只读）角色。备注保存在调用者指定的本地 JSON 文件中；该文件代表本任务的实际持久化数据。范围不含网络服务、图形界面、用户登录或部署。

## 规则

| 编号 | 规则 |
| --- | --- |
| RULE-01 | 可编辑者可为一个非空白订单编号保存 1 至 120 个字符的备注，备注不能全为空白。成功后再次读取该订单应得到原样备注，包括有效的首尾空格。 |
| RULE-02 | 保存一个订单的备注不应改变同文件内其他订单的备注；再次保存同一订单会以新备注取代旧备注。 |
| RULE-03 | 只读者不能保存备注，命令应报告拒绝，原文件内容与字节保持不变；只读者仍可读取已有备注。 |
| RULE-04 | 空白订单编号、全空白备注或超过 120 字符的备注应被拒绝，原文件不改变。 |
| RULE-05 | 提交前写入失败时命令应报告失败，原文件内容与字节保持不变；调用者随后用同样的新备注重试，成功后可读取新备注。 |
| RULE-06 | 读取不存在备注的订单应报告未找到，不创建或改写文件。 |

## 可观察完成标准

| 编号 | 调用者可观察结果 |
| --- | --- |
| AC-01 | 在临时数据文件保存订单 `ORD-100` 的 `门口放置` 后，另一次 CLI 调用读取 `ORD-100` 输出相同内容。 |
| AC-02 | `ORD-101` 已有备注时，修改 `ORD-100` 后重新读取两个订单，分别得到新值与原值。 |
| AC-03 | `viewer` 保存同一订单遭拒绝；再次读取仍是原备注，数据文件字节未改变。 |
| AC-04 | 无效输入遭拒绝；数据文件不改变。 |
| AC-05 | 模拟提交前失败遭拒绝；重读还是旧备注，原文件字节不变；重试成功后重读得到新备注。 |
| AC-06 | 无备注的订单读取失败，数据文件未被创建或更改。 |
| AC-07 | 按项目运行说明生成可执行 zipapp，从源码目录外启动这个产物，完成保存和独立回读，证明确实使用指定的数据文件。 |

`--fail-before-commit` 是受控故障注入入口，方便判断 RULE-05；常规调用不使用。产物交付限定为本机可启动 zipapp，尚未指定线上部署。
