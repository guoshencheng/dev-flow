# 研发设计 v1

## 目标与入口

`python3 -m order_notes` 提供 `save` 和 `show`。`--store` 显式指定本地 JSON 数据文件；zipapp 的根 `__main__.py` 使用同一入口。输出与进程返回码供调用者观察。无 UI 和网络依赖。

## 功能链路

| OUT | 链路与对应规则 |
| --- | --- |
| OUT-01 | 保存：解析订单、角色和备注；先拒绝无权限或无效输入，再读取原数据，更新单个键并提交；对应 RULE-01～04。 |
| OUT-02 | 读取：读取指定文件与订单键；返回备注或明确失败；对应 RULE-01、03、06。 |
| OUT-03 | 失败恢复：在原文件同目录写临时文件，刷盘后原子替换。故障注入发生在替换前，清理临时文件，保留原文件；允许重试；对应 RULE-05。 |

数据约定：文件是 `订单编号 → 备注字符串` 的 JSON 对象。一个 CLI 进程一次处理一条命令。设计不要求并发写者协调；本轮也没有线上部署目标。源码目录外运行 zipapp 时，`--store` 使用调用者传入的路径，不依赖当前工作目录或源码树。

## 自测和交付

研发自测检验局部保存/读取、只读拒绝、受控写入失败与重试。交付通过 `zipapp` 打包标准库项目；实际产物启动、跨目录保存回读和正式验收留待完整候选后执行并记录。
