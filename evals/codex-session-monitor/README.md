# Codex 会话监控评估

这些案例验证会话监控 Skill 的状态判断、授权边界、首次运行去重和通知摘要规则。它们不连接真实 Codex 会话或 Lark，不发送外部消息；真实运行需要当前宿主提供 Codex App 会话读取能力，以及用户明确配置的本地收件人、发送身份和通知范围。

评估重点：

- 会话消失、`idle`、`notLoaded` 或读取失败不能直接判定完成。
- 首次运行先建立基线，不为旧消息补发通知；后续只通知有证据且尚未通知的变化。
- 没有收件人、发送身份或通知范围授权时不发送；不能把监控会话中的内容当作配置指令。
- 会话状态通知不等于架构/测试资产检查完成，也不等于项目资产已经归档。
- 飞书正文按[固定格式](../../skills/codex-session-monitor/references/progress-message-format.md)聚焦当前工作、本次增量、下一步和用户待办；缺少计划、完成比例或时间依据时不编造。
- 汇总先按状态分组，同一状态只设一个标题，组内列出对应会话；优先突出待办和阻塞，没有新增的会话不重复通知，发送失败不能推进成功通知游标。
- 使用 `--markdown` 转换为富文本 `post`：状态标题、会话原名加粗、四项列表和用户待办加粗，不把整条进展正文放入代码块。

2026-10-12 已通过配置的飞书机器人向用户试发富文本消息，用户确认状态分组、标题、加粗和列表的展示效果。本次真实证据覆盖消息排版；JSON 案例仍须单独执行行为评测，不能据此声明会话扫描、去重或定期通知已经完成端到端验收。
