# CSV 批量导入交互规格

版本：0.2，2026-10-07。状态：本次产品设计交付，功能尚未实现或验收。入口：[产品入口](../product.md)。本文件是本次新增行为的唯一规格，验收见 [场景](csv-import-acceptance.md)，证据与依赖见 [交接](csv-import-handoff.md)。

## 依据、目标与取舍

本轮已读取最新请求 `evals/dev-product/cases/continuation.md`、项目入口 v0.3、已有规格/验收/交接 v0.1、项目约束 `AGENTS.md` 与接口权威 `contracts/import.md` v0.4。历史业务确认来自项目内 v0.1 资产的来源记录；本轮未读取 initial.md 或上一轮对话。最新请求与接口共同确认最大行数为 200，其余已确认规则保留。原 v0.1 资产仍写 1000，已因新要求过期，以下定向同步；本轮只更新受影响规则、状态、文案与验收，不重设计页面。项目只有 `src/existing.txt` 说明占位，没有应用、可执行接口、设计系统文件或用户研究证据。

目标用户：有当前项目编辑权限的模板管理员。核心任务：从模板列表选择 CSV，理解预览中的有效和错误行，明确提交全部有效行，处理结束后在模板列表看到实际新增模板。

本次确定设计供下游执行，但页面结构、文案、焦点路径等为设计方案，不冒称用户逐项确认。已确认业务约束及接口能力不被设计建议覆盖。范围含选择、解析、预览、错误清单、提交、等待、结果未知查询、结果、导入记录恢复；不含自动导入、跨设备草稿恢复、新分类管理、生产实现或部署。

既有查看、编辑和 AC-EDIT-01 继续有效。沿用现有设计系统的约定；当前仓库无法核验组件或 Tokens，视觉职责需找到真实来源，不在此生成新的视觉系统。

## 业务规则

| 编号 | 规则、依据与分类 |
| --- | --- |
| R-01 | CSV 为 UTF-8，字段 `name`、`category` 必填、`note` 可选。用户已确认。格式解析错误与行错误分开提示。 |
| R-02 | name 去掉首尾空白后非空，在当前项目区分大小写地唯一。文件内规范化 name 重复时，所有相关行都无效，不能保留第一行作为有效行。用户已确认。预览显示规范化后的 name，便于理解实际导入值。 |
| R-03 | category 必须来自当前项目已有分类。预览校验依赖分类及已有模板名称数据；服务端导入时重新验证权限和数据约束。用户要求与接口。 |
| R-04 | 空文件、无有效行、超过 200 行禁止提交；有效行不超过限制也不能绕过文件总行数限制。上限来自最新请求与接口 v0.4；其余语义复用已确认规则。 |
| R-05 | 先解析再预览全部有效及错误行；不能勾选任意子集；用户明确提交全部有效行，错误行不提交，可下载错误清单。用户已确认。 |
| R-06 | 本地未提交时可以取消或重新选文件。提交后不能撤销后台任务，关闭只停止等待。用户已确认与接口。 |
| R-07 | 提交有效记录与 client_batch_key。同一键相同内容只创建一次，不同内容拒绝；响应有 job_id，可按键查接收结果，按 job_id 查 running/succeeded/failed 及实际成功、错误数。接口 v0.4。 |
| R-08 | 超时或连接中断不等于失败，先查询同一批次再决定下一步。查询不明或仍不可达时继续标记结果未知，禁用新的批次提交，不给出“未导入”的承诺。接口与设计方案。 |
| R-09 | 预览有效不等于最终成功。结果使用服务端实际数量，允许呈现非零错误数；接口未声明原子事务，不推定 failed 时全部未写入，也不对已有成功记录重试。接口约束与设计方案。 |
| R-10 | 无权限用户不能提交；若预览期间权限失效，保留本地预览，说明权限拒绝并禁用提交；不以隐藏按钮代替服务端校验。已确认目标权限与接口；反馈为设计方案。 |

CSV 解析设计候选：第一条 CSV 记录为表头，后续数据记录计入 200 上限，不把引号内换行算作多行；允许 UTF-8 BOM；忽略完全空白的尾部记录，其他空白数据记录列出必填错误；缺少必填表头或重复表头为整文件错误；未知列提示且不提交该列；category 按项目分类原值匹配，不擅自转大小写或自动建分类；note 留空按空值处理，不新增长度限制。这些细节尚无权威约定，架构需确认前后端一致的解析规则；影响 AC-IMPORT-03、04、05、06。若不同，定向更新本规格与场景，不能以实现默认值静默替代。

错误清单设计：预览只要有行错误就能下载 UTF-8 CSV，列为数据记录序号、原始 name/category/note、错误代码、中文原因；一个记录保留所有错误，序号从表头后的第 1 条记录起。提示“修正后重新选择文件”；重选会清空旧预览、统计和未提交批次身份。下载是本地预览错误的清单，不声称包含服务端任务逐行失败详情。研发需处理 CSV 引号、换行及表格软件公式注入风险，保持原值可追溯。

## 页面语义与导航

桌面 Web，入口为模板列表。设计方案：编辑用户可见“批量导入”主操作，并有“导入记录”次级入口；无权限显示禁用及“需要当前项目编辑权限”。使用有标题的导入对话框或等价独立页面，视觉可选择呈现容器，但关闭、返回及数据保留语义相同。

1. 选择：标题“批量导入模板”；简短说明 UTF-8、字段、200 条上限、分类必须已存在；文件控件有标签。主要操作“选择 CSV”；退出“取消”。
2. 解析：文件名、读取状态“正在解析并校验”；获取当前项目分类和名称的数据失败时显示“无法校验，请重试”，不得当作零分类或零模板。数据没到齐前不能提交。
3. 预览：先显示文件名和总计 / 有效 / 错误数量，再列行数据与中文错误原因。默认展示所有行，可按“全部 / 有效 / 错误”筛选；筛选不改变提交范围。大量行采用分页或虚拟列表，但每条行错误可定位。主按钮“导入全部 N 条有效模板”，次级“下载错误清单”“重新选择”“取消”；无有效行时主按钮禁用并有原因。有错误时提示“M 条错误记录不会导入”。用户点击主按钮即明确确认，提交内容只含预览有效行；不增加一层内容相同的确认弹窗。
4. 等待：显示批次状态“已提交，正在导入”，有 job_id 时展示可复制批次标识；主区域不能继续编辑提交内容。按钮“关闭并稍后查看”；说明“关闭只停止等待，后台任务继续”。无撤销按钮。
5. 结果：标题随实际 job 状态显示“导入完成”或“导入任务失败”；显示实际成功数、错误数及服务端可用原因。succeeded 且错误数大于零时明确“部分记录未导入”。成功数大于零可点击“查看新增模板”；返回模板列表刷新当前项目数据；若接口没有新增 ID 或批次筛选能力，显示完整最新列表，不伪造过滤定位功能。提供“查看导入记录”。重新导入只能开始经重新校验的新文件，不自动重发旧有效集合。
6. 导入记录：展示项目、任务标识、状态、实际成功/错误数和刷新操作；从记录重开已提交任务状态。接口 v0.4承诺该恢复入口，但尚未给出记录列表查询、字段、权限和排序细节，列为下游依赖。关闭前未提交的文件不作为记录，不承诺刷新后草稿恢复。

## 流程与状态契约

| 状态 | 进入 / 操作与转换 | 反馈、数据保留与退出 |
| --- | --- | --- |
| S0 未选文件 | 从模板列表进入；选择文件 → S1；取消 → 模板列表 | 焦点进入标题后文件控件；无后台动作。 |
| S1 解析校验中 | 读取文件和当前项目数据；成功 → S2；文件或数据失败 → S3；重选 → 新 S1 | 禁用提交；可取消本地读取与请求等待；过期解析结果不得覆盖新文件。取消清空本地文件与预览。 |
| S2 预览 | 有效数 > 0 且总数 ≤ 200 且具备权限才允许提交 → S4；重选 → S1；取消 → 列表 | 保留本地文件、原行、规范化记录及错误；筛选 / 下载不改变数据。关闭或 Esc 等同取消，丢弃草稿。 |
| S3 本地不可提交 | 文件格式、总行数 > 200、零有效、数据加载或权限错误；数据请求可重试 → S1；重选 → S1 | 超过上限提示“CSV 最多支持 200 行，请减少记录后重新选择”，禁用提交；其余错误明确原因；文件 / 预览能保留就保留，乱码文件无法产生可信行预览；下载仅限已解析的行错误。退出丢弃本地草稿。 |
| S4 提交中 | 固定有效内容与批次键并发送；获 job_id → S5；响应确认拒绝 → S7；超时 / 响应丢失 → S6 | 点击 / Enter 立即禁用提交，同一键与相同内容固定，不再修改。已发请求不可称作撤销；关闭仅停止前端等待。 |
| S5 已接收 / running | 按 job_id 查询；running 留在 S5；succeeded → S8；failed → S7；查询不可达 → S6 | 显示“正在导入”，保留 job_id 与键；允许手动刷新、关闭并从记录恢复；重复刷新不新建任务。 |
| S6 结果未知 | 以已有 job_id 查状态，否则以原 client_batch_key 查是否接收；收到任务 → S5 / S7 / S8；仍未知留在 S6 | 保留固定内容、键和已知任务标识；不显示确认失败，不生成新键重试。若权威查询确认尚未接收，允许原键原内容重试 → S4；“未接收”的明确判定形式由架构补齐。当前页面关闭后通过导入记录恢复的支撑也需补齐。 |
| S7 服务端确认拒绝 / failed | 呈现可用原因与实际数量；权限恢复或输入修正后重选并重新预览；任务 failed 先看实际结果再新导入 | 不把整批回滚当作事实。未接收拒绝时预览保留；已接收失败显示任务结果并保持可查询。未明确终结之前禁止新导入同批数据。若成功数未知，显示“成功数量尚未确认”，不能写 0。 |
| S8 succeeded | 展示实际成功 / 错误；返回并刷新列表；查看记录；另一次导入回 S0 | 不自动重复任务。成功记录即使用户已关闭页面也可由记录查询；返回入口焦点恢复到触发操作或列表标题。 |

键的生命周期：在第一次提交前为当前固定有效集合创建键，同一结果未知或未接收重试保持相同键和内容；重新选文件或明确终结后开始的新导入生成新键。输入被修正后必须重新校验，不把新内容放入旧键。键及 job_id 的客户端保存方式、保留时长由架构明确；不新增跨设备未提交草稿恢复。查询、记录或本地标识丢失时，只能明确提示“无法确认此批次，请查看导入记录”，不能指导盲目再次提交。

## 可访问性与反馈

所有操作可通过 Tab 到达；文件控件有明确 label。解析和数量变化通过非打断状态提示播报，失败原因可被读屏读取；错误行显示文字，不只依赖颜色。预览列标题、记录序号和错误原因关联，筛选标记选中态。提交 / 查询反馈后焦点保持在对应操作附近或移动至结果标题，不能落到已禁用消失按钮。模态容器需焦点约束并在退出时返回模板列表触发控件；Esc 在提交前取消，在提交后仅关闭等待。下载后保持筛选与焦点；重选清空旧结果并聚焦文件选择区。视觉、研发需在实际实现中核验键盘、读屏与分页定位，不把本段视作已通过。
