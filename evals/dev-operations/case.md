# 运维与交付隔离工具案例

目标：用真实文件持久化 HTTP 样本操作可分发源码包，验证启动、身份/数据、故障识别和恢复方法。执行者为主 Agent，不是独立模型或原生角色评测。

输入为[研发缺陷样本](../dev-engineering/fixtures/http-ui/server.before.mjs)和[已验证修复补丁](../dev-engineering/fixtures/http-ui/repair.patch)。在新工作副本应用补丁，增加产物版本/源码摘要健康信息；形成 good 包，另在独立候选删除写入制造 bad 包，健康接口仍返回 200。不改变业务判据：实际编辑身份保存后服务端读回相同条目，查看身份写入拒绝、空标题拒绝且无副作用。

实际场景：

1. 缺少必需配置时启动失败并给出可定位原因；完整配置解包启动后版本/源码摘要相符。
2. 在包的解包目录完成真实登录、保存/读回、权限与输入边界，正常停止后端口关闭；再启动仍可读回原数据。
3. 同一数据启动 bad 候选，健康正常，写入响应 201 但读回缺失，保存探针判为失败。停止并回退 good 包，旧数据保留且新的写入/读回恢复。
4. 停止写入后备份一致文件，隔离副本模拟数据丢失；启动后观察缺失，停止后恢复到另一数据文件再启动，核对完整快照并执行新核心任务。
5. 停止全部自管服务并核验端口关闭。保留源/补丁/脚本及包摘要、命令、请求结果和数据对比。

执行入口：在仓库运行 `python3 evals/dev-operations/run.py`，数据/包/日志位于忽略的 `.dev-flow/operations-eval-*`。结果 `checks.json` 和 `report.md` 写入指定输出目录，默认临时工作副本的 `results`；本轮持久记录用 `--output evals/dev-operations/runs/2026-10-08`。固定源文件可重建包，依赖本机 Node/Git/Python，仅验证串行本地文件样本；不声称干净机器、React/Next/Astro 构建、数据库/并发、云端发布或生产灾备。
