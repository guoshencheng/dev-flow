## 实际工具案例

样本位于[http-ui](fixtures/http-ui/docs/product.md)，有固定产品契约与真实本地 HTTP、测试 Cookie 和 JSON 文件。六个 Playwright 用例在隔离副本按同一预期运行 `broken` / `fixed` 两个受控版本；只有服务错误恢复一例使用明确的 route mock，其余 API/E2E 走样本真实服务。

实际环境：Node v26.4.0、Playwright Test 1.62.1、现有 Chrome for Testing 153.0.8010.12。样本锁定工具版本，浏览器通过显式可执行路径使用已有安装；下载默认 Headless Shell 停留无进展后已停止本次下载，未将默认打包浏览器记为已验证。所用版本是本次环境，不构成所有项目默认版本要求。

| 用例 | 缺陷版实际结果 | 修复版实际结果 |
| --- | --- | --- |
| TC-API-01 保存后真实查询读回 | 失败，接口成功但查询缺失对象 | 通过 |
| TC-API-02 查看者直接调用拒绝且无写入 | 失败，返回 201 且产生未经允许的对象 | 通过，403 且无副作用 |
| TC-API-03 无效输入拒绝且无副作用 | 通过 | 通过 |
| TC-E2E-01 界面保存、请求/响应/读回及刷新 | 失败，页面显示成功，查询与刷新无法取得保存结果 | 通过 |
| TC-UI-01 ui-isolated 服务失败保留输入、恢复重试 | 失败，错误后输入被清空 | 通过；故障阶段为 route mock，随后请求回到真实服务 |
| TC-UI-02 查看者界面按钮禁用 | 通过，仍未挡住 API 越权 | 通过；UI 透出与后端授权分别检查 |

每轮 6 项、一个 worker、不重试；缺陷版退出 1、2 通过/4 失败，修复版退出 0、6 通过，没有 skipped/flaky。两个版本的固定判据均匹配，测试管理的服务端口在结束后已关闭。此案例验证了工具检查可以发现这些缺陷及固定版本复验，不代表 AI 自动诊断/修复或跨角色沟通已验证。

实际命令、输入指纹、版本、运行位置与结果见[checks.json](runs/2026-10-08/http-ui/checks.json)；完整原始报告为[缺陷版](runs/2026-10-08/http-ui/broken-report.json)和[修复版](runs/2026-10-08/http-ui/fixed-report.json)，必要失败页面文本快照保存在同一目录，副本仅清理行尾空格；原始 JSON 报告保留。trace/截图为本地临时诊断产物，没有登记视觉回归/视觉验收通过；持久 JSON 断言错误与源码足以定位本例预期/实际。

## 重复运行

在仓库根目录运行 `python3 evals/dev-acceptance/run.py --install-browser`，脚本复制到忽略的 `.dev-flow/`、`npm ci` 并安装匹配 Chromium 后执行两个版本。已有可用浏览器时可通过 `EVAL_BROWSER_EXECUTABLE` 指定其绝对路径并省略安装选项；须实际核验该组合。脚本不写业务项目，输出保留在该次独立运行目录，复制需要长期保存的报告/证据时保留原版本。
