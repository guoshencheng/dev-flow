# 条目保存：隔离测试契约

本项目是测试方法验证样本，使用本地 HTTP、浏览器与 JSON 文件，不是生产应用脚手架，不代表 React/Next/Astro 或真实数据库已经验收。规则是人工构造的评测输入，不登记为用户对业务项目的确认。

- RULE-01：编辑者可提交非空标题，成功为 201，得到 ID 与标题；随后查询和刷新能看到保存的条目。
- RULE-02：查看者可阅读，保存按钮禁用；绕过界面直接 POST 应为 403 且无写入副作用。
- RULE-03：空标题返回 422 / INVALID_TITLE，不产生条目。
- RULE-04：保存服务失败显示“保存失败，请重试”，保留标题并恢复按钮；服务恢复后重试成功且可读回。

API：POST `/api/items` `{title}`；GET `/api/items` `{items}`。本地样本登录 POST `/test/login` `{role: editor|viewer}` 设置测试 Cookie，只用于隔离 fixture。身份与数据每个测试独立。标题前缀为测试唯一 ID，持久性通过 GET 与刷新检查，跨进程/生产数据库不在本案例范围。

固定预期运行两种服务版本，不能为缺陷版本修改用例：`broken` 有授权、保存读回及错误恢复缺陷；`fixed` 修复上述问题。故障恢复用例 route mock 明确属于前端隔离测试；真实 E2E 用例不拦截业务 API。
